# 连载记忆与多集一致性（v5.17.0 新增）

> **来源**：ManjuForge 连载记忆机制（伏笔表 / 故事圣经 / 角色关系图）吸收改造。
> **触发条件**：A3 分级 **且** 项目 ≥3 集——单集短片与 A0/A1 轻量路径不启用，**别让单镜小活被连载流程拖死**。
> **分工铁律**：`连续性台账.md` 管**镜间/段间状态**（站位/持物/时段），本文件管**集间剧情与跨集资产**（人设/伏笔/关系/连续性锁）——两层不重叠、不互替，多集项目两层都跑。

---

## 一、为什么多集需要单独一层

第 20–30 集起，上下文装不下全剧历史，人设会崩、伏笔会丢、设定会漂移、关系会乱。
单集交付物（本 skill 的提示词包）只能承载**当集信息**——跨集一致性必须有**包外的持久事实源**。
这就是三个记忆文件存在的理由：它们是**提示词包的上游**，不是交付物的一部分。

## 二、四个记忆文件（格式与更新时机）

### 2.1 伏笔表（`伏笔表.md` · 机检 N4/N4b 的输入）

表行列序固定：`| ID | 类型 | 埋设集 | 状态 | 回收集 |`（5 列旧格式，**继续有效**）

```markdown
| ID | 类型 | 埋设集 | 状态 | 回收集 |
|---|---|---|---|---|
| F-01 | 插叙 | 3 | 已回收 | 6 |
| F-02 | 悬念 | 5 | 埋设 | — |
```

**v5.20.0 起支持 7 列扩展格式**（反转分级 + 锚点数，旧表不用改——级默认 L1、不查锚点）：

```markdown
| ID | 类型 | 级别 | 埋设集 | 状态 | 回收集 | 锚点数 |
|---|---|---|---|---|---|---|
| R-04 | 马甲 | L3 | 1 | 已回收 | 3 | 4 |
| R-09 | 实名 | L3 | 2 | 推进 | — | 5 |
```

- **状态枚举**：埋设 / 推进 / 已回收 / 废弃（机检查枚举，出枚举 = ERROR）
- **三条纪律**：埋后 **≥2 集**才可回收（机检 WARN）；回收内容与埋设一致（允许升级禁止降级——语义判断，人工核）；已回收的伏笔不复活（除非剧本层明确改判）
- **反转分级（v5.20.0）**：级别 ∈ **L1 单集小反转 / L2 跨集反转 / L3 全剧级反转**（枚举外 = `E-FORESHADOW-LEVEL`）。**L2 需 ≥3 个锚点、L3 需 ≥4 个锚点**（`W-FORESHADOW-ANCHOR`）——锚点 = 埋设集里露过的痕迹（集:秒），不给足锚点，观众要么看不懂要么觉得硬。
- **大反转间距（v5.20.0）**：相邻 L2+ 反转的埋设集间隔 **≤4 集**（`W-FORESHADOW-GAP`）——中段连续 4+ 集没有大反转，观众等不及。
- **更新时机**：每集新埋伏笔立即登记；推进 / 回收的当集同步改状态
- **机检**：`python scripts/audit_project.py <包.md> --foreshadow 伏笔表.md`（N4：ID 重复 / 状态枚举 / 回收时距 / 空表元检查；N4b：级 / 锚点 / 大反转间距）

### 2.2 故事圣经（`故事圣经.md`）

全剧设定唯一事实源总纲：世界规则 / 角色弧光 / 视觉母题 / **禁止变化清单**。
初始化创建，**每 5 集刷新一次**；世界观或角色发生变更时回写摘要。
**与资产注册表的关系**：注册表管外观与数值（色值 / 身高 / lock_out），圣经管设定与叙事（规则 / 弧光 / 母题）——一个是资产层事实源，一个是叙事层事实源，都写但不重叠。

### 2.3 角色关系图（`角色关系图.md`）

关系结构化数据：**矩阵**（谁对谁当前是什么关系）+ **事件时间线**（哪一集发生了什么关系变化）。
初始化创建；每集有关系变化时更新矩阵 + 追加事件行。
**事件行类型枚举（v5.20.0 扩）**：结盟 / 反水 / 疏远 / 靠拢 / **称呼变化** / 重逢 / 决裂。
**称呼变化是关系信号的最低成本形态**（外部《单王》范本：大鹏对周野「野哥」→ E10 起「周顾问」，
一句称呼完成叛徒归位的观众通知）——语言三件套的第三件，见 `叙事层_剧本门控与台词.md` §三。
**亲缘推导**（家族 / 师徒戏）沿用 `资产层_锁定与一致性.md` 的亲缘纪律：骨相继承 40%~60%、五官关联只做年龄差、家族成员共享至少 1 个 Secondary/Accent 色值。

### 2.4 连续性锁（跨集资产锁 · v6.5.0 新增，C28）

> **来源**：zenstory-ai/drama-skills 的 continuity-lock 机制（③ MIT，2026-10-28 实勘；锁面逐字三处一致＋防作弊细则为机制改写吸收，未逐字拷贝）。

**管什么**：跨集复现的**物件外观描述**——道具 / 服饰 / 场景特征物每集每段各写一遍，措辞一漂模型就画出另一个东西（第 3 集的怀表和第 18 集的怀表对不上）。注册表管数值与版本（C 门 / F 门），台账管「状态怎么变」（G 门），锁管第三件此前没人管的事：**同一物件的外观描述跨段逐字复现**。

**锁面（lock face）**：一句**冻结的外观描述**。凡「在锁」的段，正文必须逐字出现这句锁面（只去空白比对，标点也算字——逐字就是逐字）。

**格式**（项目级 `连续性锁.md`，与伏笔表同族）：

```markdown
| 锁 ID | 对象 | 检索词 | 镜头范围 | 锁面 | 状态 |
|---|---|---|---|---|---|
| LOCK-P02 | 旧怀表 | 怀表 | 全集 | 银色旧怀表，表壳背面刻痕已磨平 | 在锁 |
| LOCK-C01-疤 | 沈照眉疤 | 眉疤 | 1,3 | 左眉尾两厘米旧疤 | 在锁 |
| LOCK-P06 | 底片 | 底片 | 全集 | — | 解锁 |
```

- **状态枚举**：在锁 / 解锁（机检查枚举）。**解锁行跳过不查**——留档不删，锁历史可追溯。
- **镜头范围**：`全集`（传入的每个包都查）或 镜号清单（`1,3`，对传入包内对应段生效）。集级范围由调用方控制：一次只传相关集的包。
- **正文边界**：只认代码围栏内、`—— 以下不进正文 ——` 之前的正文；锁面写进参数行（`# 备注`）不算写了。

**三条纪律**（防作弊细则，照搬其原注口径）：

1. **一集锁个位数**——锁是给「跨集必现且必须同款」的东西用的，满篇都是锁等于没有锁（外部原注 craft_default 同口径）。
2. **锁面一旦登记，跨集不得改写**——要改 = 先在台账写变更行（改了什么、为什么），再改锁表，并回写故事圣经；直接改锁面 = 假装物件没变过。
3. **负面区命中不算命中**——锁面塞进 `Must not` / 负面提示词不但是没写，而且是写反了（`E-LOCK-NEGATIVE-ONLY`）。

**机检**：`python scripts/audit_continuity_lock.py <包.md>... --locks 连续性锁.md`（opt-in：不给 `--locks` 是跳过不是通过）。码表七条：`E-LOCK-BADROW`（行格式/枚举/在锁行锁面空/范围不合法）、`E-LOCK-DUPID`（锁 ID 重复）、`E-LOCK-MISSING`（在锁且范围命中但锁面正文一处都没有）、`E-LOCK-NEGATIVE-ONLY`（锁面只进负面区）、`W-LOCK-MENTION-NO-FACE`（段提到检索词但没带锁面——漏写还是本段合法，人工确认）、`W-LOCK-EMPTY-RUN`（空表不是已登记，G7 同口径）、`W-LOCK-UNREADABLE`（锁表文件读不了——跳过不是通过）。

**与既有机制的分界**（别重复造，也别互相顶替）：资产设定图提示词与冻结关键帧沿用资产层既有锚（注册表数值 + C13 锁行复述 + C18 实录帧链），锁只管**跨段正文的逐字复现**这一处；外部 IMG/PLAN/REF 三态引用与本库 M0/M1/M2 素材形态同构（对拍确认，不另立）。

## 三、每集工作流（接到新集任务时的顺序）

```
读故事圣经（30 秒锚定全貌）→ 读角色档案 + 本集相关关系行 → 读最近 5 集剧情摘要
→ 按记忆约束生成本集（走 Step -1 → 6 全流程，三锁照锁）
→ 更新逐集记忆：剧情摘要 + 伏笔表 + 关系图（如有变化）+ 场景布局（如有变化）
```

**生成时的硬约束注入**（写进本集创作上下文）：

- 角色性格、说话风格、关系不得与角色档案矛盾
- 已死角色不可复活（除非圣经允许）
- 已揭露的伏笔必须有回收或明确延续；新伏笔当集登记
- 时间线不得跳跃或矛盾

**与三锁的关系**：多集项目**每集照锁**（赛道 / 模型 / 画幅 / 投放面 / 交付形态），但已锁定的值跨集沿用、不重新问——这正是 P1-1 决策流水（`decisions.jsonl` + D2 门）的用武之地：流水落盘一次，D 门逐集核对没有漂移。

## 四、与既有机制的接口

| 机制 | 分工 | 接口 |
|---|---|---|
| 连续性台账（G 门） | 镜间 / 段间状态 | 记忆文件管集间剧情；台账出段间穿帮时回查记忆文件是否漏更新 |
| 资产注册表（F 门） | 外观与数值 | 记忆文件管设定与叙事；identity_verdict 判「新变体」时同步更新关系图 |
| 连续性锁（C28 · §2.4） | 跨集物级外观描述逐字复现 | 锁面变更必须过台账变更行＋圣经回写；锁只补「跨段措辞漂移」这一类，与台账/注册表不互替 |
| 剧本门控（Step -1 五道门） | 单集结构 | Gate 4 世界观边界的「时代法则 / 人际网络」以故事圣经为准 |
| 版本拆分与互锁（C 门） | 角色多版本 | 换装 / 形态变化照旧走 `版本拆分与互锁清单.md`，与记忆文件互不替代 |
