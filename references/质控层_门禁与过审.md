# 质控层 · 门禁与过审

> 本文件合并两套体系：
> **liqi 的机械校验**（七道脚本：`check_prompt.mjs` 的**规则码全表**（§二；数量以脚本为准，`check_skill.mjs` 第二项做两向对照）+ `audit_literal` / `audit_project` / `audit_risk` / `check_style` / `check_prompt_h3` / **`audit_contract`**）＋ **语义门禁**（P0~P2 三级 + 改动后三步复验）。
> 本层由两套质检体系合并而成：P0~P2 三级门禁来自一方的分级实践，过审双向闭环（量化闸门 + 转译词典）来自另一方的合规实践，两者已在下文各节合并。
> 一句话原则：**脚本负责「查得出来」，门禁负责「拦得住」，复验负责「改完不漏」。**

## 一、质检架构（L1 / L1b / L2 / L3 + 风格层 + L4 契约层）

| 层 | 工具 | 答什么问题 | 什么时候跑 |
|---|---|---|---|
| **L1 机械层** | `check_prompt.mjs`（H3 面改跑 `check_prompt_h3.mjs`） | 单条提示词本身合不合规（时间轴、参数、台词三写、字符数、slop 词） | 每写完一条就跑 |
| **L1b 表述层** | `audit_literal.py` | 画面表述抽象不抽象（九类）+ 高敏感画面 + **J 类·动作可生成度（v5.18.0，独立轴不计入九类）** + **M 类·模型行为禁用字（v5.35.0，高危命中退 exit 2）** | 交付前跑 |
| **L2 项目层** | `audit_project.py` | 跨镜一致性（台词对齐、资产锚、角色漂移、时长、转场表） | 有剧本 / 资产库时跑 |
| **L3 过审层** | `audit_risk.py` | 哪些镜会被审核拦、风险分多高 | 投国内面前跑，被拦后复筛 |
| **风格层** | `check_style.mjs` | 风格串轨、压句漂移、假绿防线、**冻结后一致性**（S10 色域 / S11 禁用项，v5.8.2） | 挂了 style_id 就必跑（Step 2.5 起） |
| **L4 契约层** | `audit_contract.py` | **阶段产物完整性**：该做的阶段做没做、做出来的东西有没有按模板真正展开（还是简笔摘要） | 开工 `--init` 建表，交付前全项核销（v5.8.3） |

L1 / L1b / 风格层**不是可选项**；L2 / L3 按条件触发（有剧本或资产库 / 投国内面）；**L4 交付前必跑**。
**只跑 L1 就交付 = 未完成质检。** 各脚本分工另见 `references/失败诊断与返修映射.md` 第四节。

**L2 与 L4 的分工（别把两者当同一套东西）**：L2 查**内容一致性**——同一份稿件内部矛不矛盾
（C 门版本漂移 / C2 场景时段 / G 门台账对账 / N 门剧本量化），**它默认你上游做了资产层**；
L4 查**阶段产物完整性**——资产层到底做没做、风格锚到底选的谁、机检到底跑没跑，
**它不判断内容对不对，只判断东西在不在、指纹全不全**。两者串行跑，结论互不覆盖。

## 二、L1 · `check_prompt.mjs` 规则码全表（→ P0/P1/P2 映射）

运行：`node scripts/check_prompt.mjs <提示词包.md>`

规则码 = **内容码 + `E-INPUT` / `E-WRONG-SCRIPT` 两个输入级码**（文件读不了、>2MB、拿错脚本时直接以退出码 2 早退，不进下列三级表）。
**码表与数量以脚本为准**：`check_skill.mjs` 第二项逐码做「脚本实现 ↔ 文档登记」两向对照（实现有、文档无 = ERROR）。旧版这里写过「68 = 66 + 2」与「34 基础 + 29 专项」，但 34+29=63≠66 —— 手维护的分项数字已经腐烂，故改为不给数、只给权威源。本 skill 把 liqi
原来的 error / warning 两档**重映射为 P0/P1/P2 三级**：

- `E-*`（error） → **P0 阻断**，必须改完才能交付
- `W-*`（warning）且涉及结构缺失 → **P1 自动修复**
- 其余 `W-*`（审美 / 密度类） → **P2 优化建议**

| 规则码 | 触发条件 | 处理 |
|---|---|---|
| `W-BEAT-BUDGET` | 段数超/低于该时长的推荐区间 | 按推荐区间重切段 |
| `W-LENGTH-CAP` | 可复制正文超字符额度（见 C05） | 删冗余，先删形容词与重复空间描述 |
| `W-CONSTRAINT-SHAPE` | 刚性约束缺「必锁 / 可见性 / 禁现」三段式 | 补齐三段 |
| `W-ALLOCATION-MISSING` | 未声明保真预算（主/次/省） | 补写 |
| `W-COLOR-BUDGET` | 未声明色彩预算（唯一重音色 / 单一色系） | 补写，防模型自发补饱和度 |
| `W-FIRSTFRAME-SHAPE` | 声明了首帧但未补该帧构图 / 主体位置 / 镜头方向 | 补三要素 |
| `W-I2V-GARMENT` | 已声明首帧，正文仍出现未与参考图关联的服装名词 | 改「换成 X」写法（见 C18） |
| `W-SURFACE-MISMATCH` | 投放面与段头骨架语言不匹配（国内面接受【时间轴】/ 无前缀裸位 / `镜头N：`；国际面只接受 `Shot N (0-7s):`） | 按投放面换骨架 |
| `W-SKELETON-MODEL-MISMATCH`（v5.37.1 立） | **段头骨架与锁①型号不匹配**：锁①=2.0 却用了秒级时间轴（2.0 官方按事件序响应镜头编号、不响应秒级时间戳）；或锁①=2.5 却只有镜头编号没有时间范围（时长预算与节拍密度失去核算依据） | 2.0 面改 `镜头1：全景，固定机位。…`，秒只作内部预算写进行为描述；2.5 面改【时间轴】0-7s：骨架。型号写错了就改声明或加 `--model` |
| `W-SHOTNUM-SEQUENCE`（v5.37.1 立） | 镜头编号骨架的编号不是 1..N 递增（跳号 / 重号 / 从 0 起） | 重排为 镜头1 / 镜头2 / 镜头3…；模型按事件序响应编号，跳号会让「第几个事件」指代不清 |
| `W-CONTEXT-LEAK` | 正文出现跨镜指代（「上一镜的…」「如前」「继续自」「上一场」…，v5.16.0 扩充词表） | 每镜独立自足，删指代 |
| `W-BEAT-CLAIM-MISSING` | 同包内部分镜块有认领行、部分没有 | 统一：要么全用要么全不用 |
| `W-BEAT-TIME-OVERRUN` | 认领拍预估时长超镜长 15% 容差 | 重排拍或改时长 |
| `W-COMBAT-CONTACT-MISSING` | 打斗镜未写接触点 | 补「谁哪个部位击中对方哪个部位」 |
| `W-COMBAT-RAGDOLL-GUARD` | 打斗镜 Must not 无布娃娃禁令 | 补禁令 |
| `W-DIRECTOR-NAME-IN-BODY` | 正文出现导演名 / IP 符号 | 改原创表述 |
| **`W-META-IN-BODY`（v5.15.2）** | 正文出现**制作注记**（「剪辑时剪掉…」「仅作下一段…」「不重新设计…」「见接戏全景…」「施工：…」）——**它不参与投喂** | 移到施工行（`Must not` 之后）。写在正文里是**白占 800 字额度**，模型也读不懂——它只会把这些当画面描述去渲 |
| `W-AXIS-NO-GEO` | 轴线行无地理参照（缺方位词或锚物连线） | 补锚物连线 + 屏幕方向映射 |
| `W-AXIS-STATE-IN-BODY` | **逐镜正文出现 `建立/保持/跨越` 状态词**（v5.27.0） | 状态词移进连续性台账场景账；正文只留锚物连线 + 左右 |
| `W-STAGING-RELATIVE` | 站位锚在活人身上（相对距离） | 改挂固定锚物 |
| `W-PARAM-RATIO` | 参数行 `ratio` 不在锁②**六值**（16:9 / 9:16 / 21:9 / 4:3 / 3:4 / 1:1）、也不是 `adaptive`（v5.37.2：`adaptive` 是 2.5 与 2.0 系列的官方默认值，视频编辑任务**必须**用它，此前被误报） | 改六值之一或 `adaptive` |
| `W-PARAM-DUR-RANGE` | 参数行 `duration` 越界（`-1` / `auto` 除外——那是智能时长，没有秒数可判） | 改到区间内 |
| `W-PARAM-DUR-AUTO`（v5.37.2） | 参数行写 `duration: -1` / `auto`（**智能时长**，由模型在区间内自选整数秒），但正文是**秒级时间轴**——定时权打架：平台定的秒数与正文排的段必然对不上，且返回时长按 24 帧取整 | 二选一：写死秒数并与标题一致；或改用镜头编号骨架（2.0 面），把时长交给平台。**官方口径**：Seedance 2.0 系列 / 2.5（非视频编辑任务）支持 `-1`；视频编辑任务跟随待编辑视频时长，不支持另行设置 |
| `W-REF-OVER-LIMIT`（v5.37.2） | 与 `E-REF-OVER-LIMIT` 同判据，但**包内没声明锁①型号**——按最严的 12 份兜底，所以只告警不拦 | 补【模型版本】：X（确认是 2.5 就是图 30 / 合计 50 的口径），或按 12 份砍 |
| `W-PROP-HAND` | 持物未分左右手 | 写死「左手 X · 右手 Y」，空手明写 |
| `W-SHOT-MULTI-SCALE` | 一个镜号里出现 ≥3 个景别档位（v5.35.0） | 拆镜，或统一到一个主导景别档。与 `W-LENGTH-CAP` 分工：那条查「写太多」，这条查「装太杂」 |
| `W-STAGING-ALONG-TOO-CLOSE` | 同侧多人的 along 坐标差值 < 0.12（v5.37.0） | 把其中一个的 along 挪开 ≥0.12。两人贴在同一个点上，模型会把它们合成一个人（或双头身影） |
| `W-EMPTY-TIMELINE`（v5.37.1 立 · 假绿防线） | 镜块内**有疑似段头但一条时间轴段都解析不出来**——此时时间轴连续性 / 运镜原语 / 节拍密度等门禁是**静默跳过**的，包会显示全绿。**这不是通过** | 核对段头骨架与投放面是否匹配：【时间轴】0-7s：（国内面·2.5）/ Shot 1 (0-7s):（国际面）/ `镜头1：`（Seedance 2.0 面）；骨架写成本机不认的形式＝上述门禁等于没查，须逐项人工复核 |

### P2 级（W-*，优化建议 — 节奏 / 密度 / 审美类）

| 规则码 | 触发条件 | 处理 |
|---|---|---|
| `W-OVER-20S` | 越过**锁①放行线**（2.5 = 20s；2.0 / H3 / H3 Max 的上限即 15s，不存在这一档，故只在 2.5 面出现） | 建议拆，不拆要写理由（三条件放行制） |

### 三之一、汇总行四档：`error / warning / 未查 / 不适用`（v5.37.3 起；分类 v5.37.6~8）

`audit_project.py` 的汇总行此前只有两档：

```
结果：0 error / 10 warning
```

问题在于这 10 条 warning 里 **没有一条是查出来的问题**——全是「你没传 `--registry` / `--ledger` /
`--script`，本门跳过」。真正的 2 条黄字（无转场表、未指定首帧）埋在 10 条「未查」中间，扫一眼就滑过去。

**「未查」和「不合格」是两条轴，共用一条通道就等于第三条轴也没了：warning 数不再是质量信号。**
现在拆成三档：

```
结果：0 error / 2 warning / 11 未查（缺产物 10 / 门槛 1，未查 ≠ 通过） / 1 不适用（不适用 ≠ 通过）
```

| 档 | 含义 | 该做什么 |
|---|---|---|
| `error` | 查出了问题，且阻断 | 改内容 |
| `warning` | 查出了问题，待人工判 | 人工判真假 |
| `未查 · 缺输入` | 文件**在项目里**，只是没传参（或剧本里没标情节点） | 跑一次 `--auto` / `--config auto` 就有；不是改内容 |
| `未查 · 缺产物` | 文件**根本不存在**（`_search_dirs` 扫不到） | 补参数永远补不上——先做上游那道工序 |
| `未查 · 门槛` | 输入齐了，但样本量 / 粒度不够（2 个镜块凑不出 25%~40% 的占比） | 补参数**没用**，换粒度复扫 |
| `不适用`（第四档，**不进未查、不进退出码**） | 这一门对本包没有意义（包内没有「镜头裁定」表 → R 门无关） | 什么都不用做；但它**意味着这一门你永远没验过** |

配套三条口径：

1. **未查不进 `warns` 计数**，控制台用 `[SKIP]` 灰字单独一行，`.gates.jsonl` 另记 `skips` 字段，
   `codes` 里归 `SEC-SKIP` 桶。
2. **退出码不变**：0 = error / warning / 未查 **全为 0**（真·全查全过）；1 = 有 error；2 = 有 warning 或 有未查。
   「未查不算通过」靠这一条守住——把 10 门没跑读成绿灯，等于把一道没跑的门当成一把锁。
3. `gates_stats.mjs` 的「最常响」榜**排除** `SEC-SKIP` / `UNCODED`，另起一行报「另有 N 条未查」。
   否则判读会说出「最常响的是 SEC-SKIP，优先改它的措辞」——它没有措辞，它代表你少传了一个参数。
4. **未查再分类**（v5.37.6）：汇总行括号里写 `缺输入 11 / 门槛 1`，`.gates.jsonl` 记
   `skip_input` / `skip_thresh` / `skip_untagged`。理由是这两句的**下一步动作完全不同**：
   前者跑一次 `--config auto` 就少了 10 条，后者怎么补参数都不会变——混成一个数，
   用户就会把「不可满足的判据」和「自己没传参数」当成同一件事，于是两类都不处理。
   一条新写的未查消息若忘了带类别，会被记进 `未分类` 并**在汇总行里点名报出来**，
   不并进任何一类（并进「缺输入」最危险：它会让人去补一个补了也没用的参数）。
5. **`缺输入` 与 `缺产物` 的判定不靠措辞，靠自动发现**（v5.37.7）：报告层用一份**探针**
   （`auto_fill` 跑在临时对象上，不写回 `args`）判断「这份文件在不在包目录 / 父目录 /
   `assets`·`docs`·`data`·`script` 里」，依赖关系直接用 `COVERAGE_GATES` 那张表——
   不另维护第二份门→输入映射。改判只发生在 `缺输入` 上，`门槛` 与 `found` 的一律不动。
   E01S02 就是这条规则的价值证明：改前 `缺输入 11`，改后 `缺输入 1 / 缺产物 10`——
   那 10 条一条参数都补不动，因为那个目录只有 `包.md` 和 `beats.txt`。
6. **门级未查 ≠ 行内未查**：`audit_all.py` 总账里的「门级未查 N」按**门**数（`--skip` / 未声明
   `style_id`），`audit_project` 行里的「N 未查」按**判据条数**。两个数放在同一屏时，
   总账会显式说明「两者不可比」——否则用户会拿 1 和 12 对比，以为哪边算错了。
8. **`.gates.jsonl` 现在带 schema 版本 `v`**（v5.37.10）：v1（无 `v` 字段）= 只有
   `ts/tool/file/exit/errors/warns/codes`（后来补了 `skips`）；v2 = 再加**可选**的
   `skip_input` / `skip_missing` / `skip_thresh` / `skip_untagged` / `nas`
   （只有能分类的 `audit_project` 会写，node 侧脚本只写 `skips`）。
   记版本的唯一目的是让 `gates_stats` 分清两种「未分类」：
   **v1 老记录**（采集时还没这个字段，重跑一次就有）与 **v2 漏标**（新写的未查消息忘了带
   `kind`，是代码问题）。没有 `v` 时这两件事长得一模一样，提示语只能含糊地说「或者是老记录」。

9. **`kind` 是必填参数，不是默认值**（v5.37.12）：`_skip_msg(reason, kind, hint)` /
   `_skip_section(reason, kind, hint)` 都**没有默认值**。默认值就是那个「替你回答」的东西——
   写的人没说，默认值替他答「缺输入」，而有的跳过根本不是缺输入（v5.37.8 那个把全绿堵死的坑
   就是这么来的）。现在漏了就当场 `TypeError`。
   双保险：`scan_conflicts` 的 **K8** 在静态层面同时盯 `_skip_section`（门级装配）与
   `_skip_msg`（门函数内部）——条件是 `if <cond>` 且 `<cond>` 里没有 `args.*` 的调用，
   必须显式 `kind=`。实测删掉任意一处 `kind=`，K8 报 1 条、运行期报 `TypeError`。
7. **「不适用」为什么必须单独一档**（v5.37.8）：它原来混在未查里，后果是一个没写
   「镜头裁定」表的包**永远拿不到「全部通过」**——至少 1 条未查，退出码恒为 2。
   **不可达的信号没人追**：既然全绿永远拿不到，用户就不再追求全绿，连带真问题一起忽略。
   所以它不进未查、不进退出码，但必须出现在报告里（`[N/A]` 灰字 + 汇总行
   `N 不适用（不适用 ≠ 通过）` + `.gates.jsonl` 的 `nas` 字段 + `SEC-NA` 桶）——
   否则就从「假绿」换成了「静默省略」，那是更坏的一种。
   同样的理由，它的消息句式也不是 `本门未查（…）` 而是 `本门不适用（…）`：
   让「该查没查」和「不该查」在**文本层面**就长得不一样。

⚠️ **历史坑（已修）**：`_issues_from_sections` 原来用 `startswith('本门未查')` 认未查，而
`未配置版本互斥词表，本门跳过` / `未给 --registry，F2—F6 跳过` / `未给 --ledger，G 门跳过` /
`未提供 --script，N 门跳过` 四条**不含该前缀**，被算成所在门「响了」。
实测同一份 E01S02：改前 `codes` 里 `SEC:C 1 / SEC:C2 1 / SEC:F 1 / SEC:G 1 / SEC:N 1` 全被记成命中，
而那五道门这次一次都没跑；改后只剩 `SEC:E 1 / SEC:B 1 / SEC-SKIP 12`。
**统计口径错，比门本身错更难发现——因为报告看起来更有内容。**

### G 门为什么不能并进 C / C2

| 门 | 在哪个范围里找矛盾 | 例 |
|---|---|---|
| **C / C2** | **提示词内部**——同一镜里两个互斥特征同现 | 「素白中衣」与「藕荷衣裙」同现；声明深夜却写暖橙夕照 |
| **G** | **提示词 vs 外部事实源（台账）** | 台账记长风持桃木剑、提示词写「双手空」——两边各自都不矛盾，放一起才是穿帮 |

C / C2 查不到第二类，因为矛盾不在同一个文档里。台账是 Step 3 逐段登记的外部事实源，
G 门拿它去核提示词，这是补一类**跨文档**的错，不是把 C/C2 重做一遍。

**G 门的三条防误报**：① G1 只在提示词**明写空手**时报，没写走 G2 的 WARN（没写 ≠ 矛盾）；
② G3 只比对台账文件里**相邻两条**，跨段本就可能切场；③ G5 只比时段**标签**，不比光照词——
那层语义归 C2 门的 `lock_out`。

⚠️ **G 门通过 ≠ 连续性没问题**：本门只查可字符串比对的三类（持物 / 角色登记 / 时段标签）。
站位漂移、朝向反转、姿态无声回退、陈设状态回退都需要语义理解，机检查不了，
是 `连续性台账.md` 第九节自检八问的人工活。

⚠️ **F4/F5/F6 只查「落盘与合法性」，不查「判得对不对」**：它们能证明身份判定做了、取值合法、
未决的没出图，但「穿雨衣的人是不是 S07 那个角色」这类判断脚本查不出来，是 `资产层_锁定与一致性.md`
5.1—5.3 的人工活。**F 门通过 ≠ 身份判定正确**，别把绿当结论。

### C 与 C2 为什么是两套语义（v5.6.3 分开）

同一个「版本漂移」，两类资产的判据**不同**，混用会一边误报一边漏报：

| 门 | 资产 | 判据 | 例 |
|---|---|---|---|
| **C** | 角色 / 道具 | 同一镜**同时出现两个版本名** | 「素白中衣」与「藕荷衣裙」同现 → 串版 |
| **C2** | 场景 | 同一镜**声明了时段 T，又命中 T.lock_out 的词** | 「时间线锚点：深夜」却写「暖橙夕照」→ 串版 |

**为什么场景不能照搬 C 的语义**：场景提示词通常**只写当前时段的光照描述，不写时段名**，
所以「两个版本名同现」几乎永不触发（v5.6.2 实测：召回极低）。而 `lock_out` 记的正是
「别版特征」，所以「**声明 T + 命中 T 的禁写词**」才是场景的正确判据。

**C2 门的判定细节**（全部为了不误报）：

- 声明只在**字段行**里找（`场景：` / `时间线锚点：` / `光源：` / `氛围：` / `环境：`），
  正文叙述不参与——所以「他想起那日正午的事」不会被判成声明了正午；
- 没声明时段 → **跳过**（不猜）；
- 声明了 ≥2 个时段 → 报「同时声明两个时段」；
- 声明了该场景**未登记**的时段 → 报 WARN（多半是注册表漏建变体）。

**🔴 C2 门的召回取决于 `lock_out` 的完备性**：T 的 `lock_out` 必须覆盖**其余所有变体**的
标志性特征，只写一两条就会漏。所以本门对词数 **< 3** 的变体发 WARN 提示补齐；
建议每版从**色温 / 光质 / 影子形态**三个维度各取，总数 ≥3 条。
**「其余所有变体」= 全文判读出来的时段集合**（v5.20.1，`场景资产与时间线光照.md` 2.4.0），不是 registry 里碰巧登记的那几个。

**🔴 C2 门查不到的那类问题**（v5.20.1）：本门只认 registry 里**已登记**的时段——场景若在全文里出现某个时段却没登记 `variants`，
本门既不会报「未登记」，也拿不到它的 `lock_out`，**静默通过**。所以 `场景资产与时间线光照.md` 2.4.0 要求
出四阶前**先做全文时段检索并把结果回填 registry**。**本门没报错不等于没漏时段。**

**A 项是最不能省的一项**——用户铁律「台词一字不差」，返修时最容易顺手压缩长句，只有 A 项能抓出来。
（`--coverage` 可查反向覆盖：剧本里的台词有没有在提示词包里漏掉。）

## 四、L3 · `audit_risk.py` 过审风险分

运行：`python scripts/audit_risk.py <提示词包.md> [--shot 1,2,3,5b] [--detail]`

**评分模型**：`风险分 = Σ(词等级 × 出现次数)`，等级 3=极高（几乎必拦）/ 2=高（写实下必拦）/ 1=中。

**阈值**：

- 单镜 **≥20** ＝ 可能被拦 → 必须替换后再投
- 单镜 **≥50** ＝ 大概率被拦 → 该镜重新设计
- 退出码：0 无触发 / 1 有极高词 / 2 只有中高危词

**只扫可复制正文**——自动排除 `>` 说明行与 `#` 参数行。因为只有正文会真正送进模型与审核。

**该脚本的词汇表是志怪 / 民俗 / 恐怖向**（人皮、验尸、停尸房、剥皮、声带、黏膜），
**动作 / 暴力向的词汇表来自外部《平台安全合规转译指南》**（第三方资料，未随本仓库分发，见 §六）。两表题材互补，都要用。

⚠️ **它只查词，不查画面。** 拿到风险分之后必须走 §6.3 高敏感五手法给每一拍配镜头手法——
**换词不算完，画面不兜底等于没改。** 画面表述（剪影、伤情本体、儿童危险物口径）另跑
`scripts/audit_literal.py` 的 S 类。

## 六、过审双向闭环（C16：查 → 改 → 复筛）

机械校验给的是**量化闸门**，语义门禁给的是**修改手册**。两者是「查」与「改」的关系，合起来才是闭环：

```
① 查：跑 audit_risk.py，拿到单镜风险分与贡献词清单
        ↓
② 改：按题材选词表，逐词替换
        ↓
③ 复筛：再跑一次 audit_risk.py，确认风险分降下来（≥20 的镜降到 <20 才放行）
```

### 6.1 志怪 / 民俗 / 恐怖向词表（liqi 体系）

| 高危词 | 物理转译词 |
|---|---|
| 人皮 | 皮壳 / 蝉蜕 / 旧衣壳 |
| 验尸 | 验看 / 查验 |
| 停尸房 | 石室 / 静室 |
| 剥皮 / 剥 | 蜕下 / 脱下 / 褪去 |
| 血 | 赤红 / 暗红痕 |
| 尸体 | 无生命躯壳 / 空衣 |
| 器官 / 声带 / 黏膜 | 不提，改外在表现（喉部起伏 / 呼吸声） |
| 肌肉 / 骨骼 | 赤红躯体 |

### 6.2 动作 / 暴力 / 战斗向词表（四维度）

| 维度 | 高危拦截写法 | 转译方向 |
|---|---|---|
| **击打受力** | 骨裂、骨折、骨头碎裂 | 写受力后的**位移与形变**（身体后仰、手臂被带偏） |
| **面部创伤** | 鼻血、嘴角流血、面部变形 | 写**遮挡与角度**（背对镜头、发丝遮面） |
| **致命打击** | 致命、杀死、当场毙命 | 写**结果状态**（不再起身、镜头停在空位） |
| **环境破坏** | 血肉横飞、爆头、肢解 | 写**环境反应**（尘土扬起、物件散落） |

### 6.3 🔴 改的落地：高敏感五手法（换词不算完）

**这是过审闭环里最容易漏的一环。** 6.1 / 6.2 解决的是"词怎么换"，但没有解决"画面怎么办"——
词换掉了，画面还在拍同一个东西，审核照样拦，或者模型照样把它生成出来。

**纪律：每替换一个高危词，必须同时给这一拍指定一种镜头手法。** 只换词不给手法＝没改。

| 手法 | 怎么做 | 适用 |
|---|---|---|
| **画外（声音先入）** | 危险发生在画外，画面只给听者的反应；声音先到，画面后到或不给 | 伤害、事故、死亡 |
| **前景遮挡** | 用门框 / 碗沿 / 桌沿 / 器物挡住主体关键部位 | 利器、身体局部 |
| **局部特写** | 只给手、器物、衣料，不给全貌 | 伤口、形变、操作过程 |
| **逆光与暗部轮廓** | 主体压在暗部，只留边缘与轮廓，暗部有层次不死黑 | 暴力动作、垮塌、熔化 |
| **空镜承接** | 危险过后接一个环境空镜，用痕迹代替本体 | 结果、余波、现场 |

#### 两条反直觉纪律（踩过才知道）

**① 只给结果，不拍过程。**
要表现"他夜里抓过自己的脸"，**不能写抓挠动作**——写抓挠就必然要拍到皮肤接触与形变，高风险且模型做不好。
正解：只给结果。「左颊颧骨下方一道两指长的浅白印子，边缘不齐，颜色比周围皮肤浅一档，不红不肿」，
配合声音层的抓挠声。**观众看得懂，模型做得到，审核过得去。**

**② 儿童与危险物要分两层，不能写「全程不同框」。**
剧本若要求儿童接触危险物（端热汤、靠近灶火），不能写「孩子全程不与热源同框」——
这会与核心动作直接打架，投喂时两条指令互相抵消，模型随机二选一。
正解：写「**不与危险发生的瞬间同框**」，并把可见范围收窄——
`端汤过程只给碗身与双手，碗口不抬起，热气不扑面`。动作保住了，危险瞬间没拍到。

#### ⛔ 剪影不是规避手法

`audit_risk.py` 早期版本建议"配合雾 / 剪影 / 暗调降冲击"——**这条已修正**。
剪影降的是可见度，同时也**降掉了"人物在场"**（模型读不懂剪影，见
`视听层_镜头文法与光色.md` 剪影反向约束）。人物要出场就必须给光与朝向，
遮挡用前景与暗部，不用剪影。

### 6.4 不可合并的两句声明

- 本 skill 提供降低风险的方法，**不承诺任何 100% 通过**——最终以各平台实时审核政策为准。
- 人脸过滤在**模型层**，换 API 宿主无效；被拒时不要浪费时间换宿主，改**风格化画风**重试。（liqi）

## 七、改动后复验铁律（C13：liqi 完全缺失的一环）

> 改稿禁止只复验改动处。改动会与全档其他部分冲突——典型翻车：改一句台词剧透前文伏笔、改一个场景与资产锚冲突，而整档未重跑。

### 三步复验闭环（缺一不可）

1. **局部验证（改动处自检）**：改动内容本身达标（台词 / 画面 / 锚点 / 时长）
2. **联动冲突检查（七项交叉扫描）**：伏笔 → 角色（人设 / 脸模 / 服装）→ 信息量（剧透 / 节奏）→ 因果节拍 → 资产锚点 → 时长预算 → 画幅一致性
3. **全量审核**：整档重跑 L1 + L2 + P0~P2 门禁；**不允许以「已检查改动处」豁免**

### 《改动复验报告》交付要求

**修改类交付物文末必须附：改动清单 + 联动检查结论 + 全量审核结论。**
**未附报告 ＝ 视为未完成复验，禁止交付。**

这是本 skill 唯一强制附件。任何「改了三个字所以不用复验」的判断，一律驳回。

## 八、声音三段混音电平（制作纪律，写进参数行）

```
对白 0 dB  >  动作物理音效 SFX −6 dB  >  环境声景 / BGM −14 ~ −18 dB
```

- 对白永远处于最高清晰度优先级。
- 动作音效不得遮盖人声；激烈打斗或对白爆发时 BGM 自动避让（Ducking）。
- 与四层混音段（环境 / 动作 / 呼吸 / 逼近）是两回事：**四层定「有哪些声音」，电平定「谁听得清」**。

## 九、后期兜底层（生成完之后还有一道保险）

提示词与资产板能压住大部分漂移，但压不住全部。**已经生成的镜头里仍有一小部分脸会歪**——这时候不重抽，走后期兜底。

### 两道工序

| 工序 | 做法 | 适用 |
|---|---|---|
| **漂移镜头换脸修正** | InsightFace / FaceFusion 把漂掉的脸贴回参考脸 | **只处理脸清晰可见的镜头**。远景小脸、背影、侧后脑不做——贴上去反而更假 |
| **全片统一调色** | 所有片段进 DaVinci / CapCut 统一曝光与白平衡，再套一个 LUT | **全片必做** |

### 为什么调色比换脸更重要

**肤色统一对「感知一致性」的贡献大于任何单项技术。** 不同生成调用之间的色温差，会让同一个角色看起来像换了个人——脸明明是对的，观众还是觉得「不是他」。所以：

- 顺序上**先调色再看换脸**。很多「脸不对」的观感问题，调完色就消失了。
- 生成时**不要逐镜单独调色**，一律留到后期统一处理——生成期调色会引入不可逆的色偏。
- 基准调色板来自资产层注册表 `palette`，**与场景光照锚点是两回事**（光照管「光从哪来」，调色管「全片落在哪个色域」）。

### 与「回卡修」的分工

| 问题出在哪 | 用哪一招 |
|---|---|
| **卡本身错了**（设定图上的面板就有问题） | 回卡修（`失败诊断与返修映射.md`）——不重抽镜头，改卡后所有镜头继承修复 |
| **卡是对的，只是这一镜生成歪了** | 重抽这一镜；重抽仍不稳 → 后期换脸修正 |
| **卡对、单镜也对，但全片观感不统一** | 后期统一调色 |

**不要用后期兜底去掩盖卡的问题**——卡错了却一直靠换脸贴，成本会失控，而且每个镜头都要贴一次。

## 十、交付契约核销（CT1~CT8，v5.8.3）

### 10.1 治什么病

前九节解决的是「查得出来」，这一节解决的是**另一个病**：

> **`check_prompt.mjs` 报全绿 ≠ 任务完成。**

`check_prompt` 只校验**投喂块语法**——它不知道你上游有没有真做资产层、有没有选风格锚、
有没有跑过项目级审计。于是出现三种典型交付缺陷：

1. **只写了投喂稿**，漏掉资产层 / 方位卡 / 时段锚点表 / 台账。格式全绿，产物半拉。
2. **几行简笔摘要糊弄**——资产层写成「沈知微：22 岁，穿靛蓝布衫。」一行，
   没按 4 View 模板展开；风格锚写成「2D 赛璐珞，冷色调。」两句，九段锚只剩两段。
3. **挤牙膏式返工**——你抓一次我修一次，开工前不建清单，交付前不逐项核销。

契约核销把「阶段产物完整性」从**交付人的记忆**变成**可核销的清单**。

### 10.2 八项契约（硬产出 + 唯一权威源 + 必现结构指纹）

| 码 | 阶段交付物 | 唯一权威源（必须回读） | 必现结构指纹 |
|---|---|---|---|
| `CT1` | 剧本门控通过记录 | `叙事层_剧本门控与台词.md`（§一 五阶门控 + §六 分阶段量化门禁） | 五阶门控 Gate 1~5 记录 + 情节点显式标注 |
| `CT2` 🔒 | 风格锚声明 + 冻结 | `风格路由表.md`（§六 递进收窄四步 / §七 选定即冻结） | `【风格】<style_id>` 声明 + 九段锚 ≥7 段 + 冻结四项 |
| `CT3` | 角色资产板（4 View + 五官 10 项 + 服装 6 项） | `资产层_锁定与一致性.md` | 4 View 版式 + 左区头部近景 + 右区保头无脸三联 + 文字锁 16 项 + 性别锚 |
| `CT4` | 场景方位卡 + 时段锚点表 | `场景方位卡与固定锚物.md` + `场景资产与时间线光照.md` | 方位卡四要素（罗盘 / 固定锚物 / 屏幕方向映射 / 禁变）+ 项目级光照锚点表 |
| `CT5` | 道具 / 持物设定 | `持物设定图_模板.md` + `道具展示表_模板.md` | 关键道具锁定 + 入画方式（手持 / 悬挂 / 置地）+ 持物分左右手 |
| `CT6` 🔒 | 逐镜提示词 + 配额自检 | `分镜配额与机检规范.md` | 逐镜块 + 时间线分镜 / 参数行 / 光色基调 / 保真预算 / 站位 / 刚性约束 |
| `CT7` 🔒 | 投喂稿过机检 | `check_prompt.mjs` / `audit_project.py` / `check_style.mjs` | 附校验结果：脚本名 + 结果态（`0 error` / 通过） |
| `CT8` | 质检结论与改动复验报告 | 本文件（§一 质检架构 + §七 改动复验） | L1~L3 结论 / 过审风险分；**修改类交付必附《改动复验报告》** |

🔒 = **不接受豁免的硬项**（CT2 / CT6 / CT7）。这三项任何形态的交付都必须做，
写了 `【契约豁免】` 声明也无效，脚本会额外报一条提示。

运行：`python scripts/audit_contract.py <稿件.md> [--mode auto|full|board|asset] [--style <id>] [--script <剧本.txt>]`

### 10.3 四态判定：PASS / WARN / FAIL / N/A

| 态 | 含义 | 严重度 |
|---|---|---|
| `PASS` | 硬产出在场且结构指纹齐 | —— |
| `WARN` | 硬产出在场但指纹不全（或该项属建议级） | 人工复核后可交付 |
| `FAIL` | 硬产出缺失，**或在场面但关键指纹 0 命中**（＝简笔糊弄版） | 阻断交付（退出码 1） |
| `N/A` | 本项不适用（无输入）或已**显式声明跳过** | **不计入通过项** |

🔴 **N/A 不是通过，是「没查」**。这是本 skill 从 Z 门（块数 0 时 D/C/C2 三门的 OK 是空跑）、
G7（台账解析出 0 条报 FAIL 不报 OK）、N2（情节点 0 处标注报「无法核对」）一路立下来的同一条口径——
延续到契约核销，否则一张空白包也能报「全绿」。
报告里 N/A 项**单列**，核销率按 `PASS / (PASS+WARN+FAIL)` 算，分母不含 N/A。

**三种 N/A 来源**：

1. **无输入**：未给 `--script` 且包内无剧本段 → CT1 N/A；包内无道具锚与道具锁定 → CT5 N/A；
   资产包形态（无镜块）→ CT6 N/A。
2. **档位不适用**：包内**显式声明** `资产依赖分级：A1` → CT3 N/A（A1 单角色单镜，资产可选）。
   ⚠️ 必须显式声明——**没声明就是默认 A2/A3，没做资产层报 FAIL，不报 N/A**。
3. **声明式豁免**：见下节。

### 10.4 声明式豁免（照 `分镜配额与机检规范.md` §六 的体例）

段首一行显式声明即生效，机检认字符串：

```
【契约豁免】CT3：本包 A1 档，资产可选不建链
```

**可豁免**：`CT1` / `CT3` / `CT4` / `CT5` / `CT8`（依赖项目档位或交付类型）
**不可豁免**：`CT2` / `CT6` / `CT7`（🔒）

🔴 **豁免一个已 FAIL 的硬项不会让它变 PASS，只会让它变 N/A**——
豁免是「本项不适用」，不是「本项通过」。所以豁免同样要写理由，
理由会被打进报告（`显式豁免：<理由>`），留痕可复核。

**豁免不是免检**：声明只改变「查哪一项」，不改变「要不要做这件事」。
把 CT3 豁免掉去做单镜包，是合理；把 CT3 豁免掉去做 A3 连续剧集，是把风险藏进报告里。

### 10.5 模式判定（`--mode auto`）

| 模式 | 判定依据 | 影响 |
|---|---|---|
| `full` 整片交付包 | 命中「转场注记 / 连续性台账 / 全局制作纪律」任一满配标记 | 全八项按整片标准核 |
| `board` 看板 / 节选 | 无满配标记 | 与 full 同标准（契约不因节选降级，指纹全不全自己会说） |
| `asset` 资产包 | 无镜块 + 有「资产 X｜」条目 | CT6 判 N/A |

⚠️ **只认满配标记才升 `full`，不因出现轻量标记就降级**——
上游踩过一次：见 `P2.5` 即判 board-lite，静默跳过六项满配契约，
恰好放走「漏 P1/P3/P5」这类最典型的漏项。**宁可多查，不可静默漏查**。

### 10.6 开工建表 / 交付核销

```
# 开工前（贴进工作笔记，每完成一项打勾）
python scripts/audit_contract.py --init --style <style_id>

# 交付前（未通过严禁宣布「任务完成」）
python scripts/audit_contract.py 包.md --style <style_id> --script 剧本.txt
```

**与 `audit_project.py` 的串行关系**：先跑 L1~L3 拿结果 → 把结果写进包内「附 校验结果」区块
（这一步同时完成 CT7）→ 再跑 L4 核销阶段产物。**L4 全项通过后才可以交付。**

### 10.7 失败模式表

| 现象 | 根因 | 处置 |
|---|---|---|
| 格式全绿但用户说「少了东西」 | 只跑了 L1，没跑 L4 | 跑 `audit_contract.py`，按 FAIL 项回补对应 reference |
| CT3 报「简笔摘要」 | 资产层写成几行角色描述 | 回读 `资产层_锁定与一致性.md` 第二节，按 4 View 模板展开 |
| CT3/CT4 报 FAIL 但其实本片不用资产 | 没显式声明 A1 档 | 包内写「资产依赖分级：A1」——**没声明就是默认 A2/A3** |
| CT7 报 FAIL | 把「格式查过了」当成「机检跑过了」 | 交付前必跑 L1/L1b/风格层，把结果写进包内 |
| CT8 报 FAIL | 修改类交付没附《改动复验报告》 | 补三步复验闭环（局部 + 七项联动 + 全量审核），见 §七 |
| 报告里一堆 N/A 却读成「全过」 | 把 N/A 当 PASS 了 | N/A 单列且不计入核销率——**「没查」不是「没问题」** |
| 用 `【契约豁免】` 想跳 CT2/CT6/CT7 | 硬项不接受豁免 | 脚本会额外报提示；这三项老老实实做 |
| **包内注记写了「本包无 ×××」结果被当成证据** | **自我污染**：核销器读的是全文，注记里的「无场景方位卡」「无剧本层」会被匹配成「有方位卡」「有剧本层」 | **别把核销结论原文抄进包内**——注记里只给计数与理由，不要复述契约项名与指纹词；逐项判词跑脚本现看。（实测踩过：往黄金样例注记里写了一句「CT4 无场景方位卡」，CT4 立刻从 FAIL 变 WARN、CT1 从 N/A 变 FAIL） |


## 十一、口径溯源纪律（v6.1.0 · C22）

口径三态（① 官方 / ② 平台特性 / ③ 社区实测）分级解决了「这话是谁说的」，C22 补上后半句：**③ 类必须能回访**（本行为口径图例，K9 豁免同理）。

- **新写入的 ③ 社区实测数值/断言**：同句必须带可回访来源——外部 URL，或库内「文件#节」指针（如「裁决记录《外部Skill吸收裁决总表》W4 行 / C03 节」），或「本库自立＋立项日期」。
- **历史入库、原始出处未存档的 ③**：不许补造来源——写「原始出处未存档，待复访补证」，复访到原源后回填并去掉该标记。
- **豁免**：裁决记录（《外部Skill吸收裁决总表》）、变更叙事（《待办路线图》）、词条定义（glossary）三类文件整文件豁免；「口径三态（v5.x …」版本标注式图例行豁免。
- **机检**：`scan_conflicts.py` K9 行级 WARN（维护时跑，不参与交付门禁）——行含「③ 社区实测」却无 来源/出处/未存档/待复访/口径图例 标记即报。
- **为什么行级、为什么不进交付门禁**：加门三问——交付包里不该出现口径讨论（那是 references 层的事），K9 只服务库内维护；行级标记零语义猜测，与 K1~K8 同哲学。语义级「来源是否真的支撑该数值」只有人工复访能判，机器不装懂。
