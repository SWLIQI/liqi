# 场景资产与时间线光照

场景是分镜的背景板。角色资产解决"人长什么样"，场景资产解决"人在哪儿、什么时候、什么光下"。

## 一、场景资产与角色资产的四个根本差异

照搬角色模板会出错。差异在：

| 维度 | 角色/道具资产 | 场景资产 |
|---|---|---|
| 主体 | 有主体（角色/道具） | **无角色**（背景板），出现人物即失败 |
| 文字策略 | **要中文引线注释** | **默认无文字**（画面纯净） |
| 视角组织 | **4 View 板**（左区头部近景身份锚 + 右区保头无脸三联） | **四阶出图链**：单视图基准图（文生图）→ 俯视空间结构图（图生图）→ 多视角图（图生图）→ 不同时段的多视角图（图生图） |
| 版本维度 | 服装阶段 / 状态 | **时间线**（同一场景的晨/午/昏/夜） |

**文字策略的取舍**：场景图是给分镜当背景用的，画面上带文字会污染画面。所以场景资产默认走"纯图无字"——注释全部落盘 `.md` 承载（沿用 SKILL.md Step 3 降级预案的第 3 档逻辑）。需要给美术评审看的场景设计稿，才切到「标注模式」加中文引线。

### 一之一、写场景前先定两件事（v5.36.0 新增 · 来源 shuohao novel-art scene-pass）

**① 定位句写设计意图，不写户型说明。**

- 设计意图：「小到人与人躲不开视线的审讯室」——它说清了这个空间为哪场戏存在。
- 户型说明：「约十平米，六排坐板」——只是测量数据，画面和戏都用不上。

判据：这句话删掉之后，有没有一场戏会变难拍？不会 → 它是测量数据，移到注释层。

**② 朝代/年代先定再写，且不许写「古代」「古装」「某朝」「架空」。**

这类词在画面上没有任何对应物——模型读到「古代府邸」只能自己挑一个，于是庭院出成宋、书房出成明、道具出成清，摆在一起不像同一部戏。定死之后，斗拱样式、家具腿型、窗棂纹样、灯具形制、地面铺装全部按它写。

原著是架空设定时，写它**像**哪个朝代——「明代风格」——而不是写它是架空的。

### 一之二、场景资产图不带画风，投喂词必带（v5.36.0 新增 · 防误用界限）

这两件事对象不同，**不要互相套**：

| 对象 | 要不要画风 | 为什么 |
|---|---|---|
| **场景资产图**（environment sheet，当参考图） | **不带** | 画风是出图那一刻才定的，整批共用一段风格指令由调用方附加。写进每条只会跟当时选的风格打架，而且换风格要逐条改 |
| **逐镜投喂词**（Step 3 的正文） | **必带** | 逐镜单独投喂，模型看不到卷首的风格锚段落；不内联 = 模型一个字的画风都没收到（S7-PRESS-NOT-IN-SHOT，P0） |

**S7 门只管投喂词，不要求场景资产图。** 反过来说，也不要把场景资产图的「不带画风」当成理由，去削弱逐镜投喂词的内联。

场景资产图要整段带上的是**表面处理**（用旧还是维护，见资产结构层模板.md 第 5 层补），它讲的是这个空间被谁在用、用了多久，换任何画风都成立。


## 二、场景资产出图链：单视图 → 俯视图 → 多视角图 → 不同时段的多视角图

> **v4.7.10 重构**。旧版只有一阶「2×2 四视角场景环境设定表」，缺两个前置产物，带来三个问题：
> ① 没有任何一张图承担「空间坐标说明书」的职责，逐镜写站位时无据可依；
> ② 四视角直接在文生图里一次生成，没有可参考的基准图，跨视角一致性全靠文字描述；
> ③ 遇到复杂场景没有升级手段。
>
> **v5.6.3 补第四阶**。三阶时代缺一条：同一场景的**其他时段版本**要在哪里出。当时只在第三节用一段文字交代
> 「一阶不出、二阶不出、三阶出」，变体成了挂靠在三阶下的一个分支。现在把它提升为**独立的第四阶**——
> 因为它的入口条件（**基准版三阶已锁 + 全文时段检索已做**）、产物（不同时段的多视角图）与纪律（只改三段）都与三阶不同。
>
> 全链四阶，**前一阶没锁定不进下一阶**。核心纪律一句话：
> **一致性靠参考图传递，不靠同图并列。**

| 阶 | 产物 | 出图方式 | 一张 / 多张 | 职责 |
|---|---|---|---|---|
| **一阶** | 单视图基准图 | **文生图** | 1 张 | 全链的身份与画风基准 |
| **二阶** | 俯视空间结构图 | 图生图（喂一阶） | 1 张 | 空间坐标说明书 |
| **三阶** | 多视角图（2×2 四视角） | 图生图（喂一阶 + 二阶） | 1 张 | 基准时段的多角度参考 |
| **四阶** | 不同时段的多视角图 | 图生图（喂一阶 + 二阶） | **每个时段变体各 1 张** | 同一场景其余时段的多角度参考 |

**四阶只出变体，不出基准版**——基准时段的多视角图是三阶的产物。四阶的入口不是三阶的图，而是**基准版已锁定**这个事实。

### 2.0 为什么不能把角度塞进一张图：格数就是注意力的除法

| 做法 | 每格分到 | 实测 |
|---|---|---|
| 单张单角度 | 100% | 稳 |
| 2×2 四格 | 25% | 可用（**本链的格数上限**） |
| 3×3 九格 | 11% | 崩（实测：至少 4 格机位与指令不符，物体跨格换位） |
| 五区块并列（约 15 格） | 7% | 更崩 |

把 N 个角度塞进一张图，每格只分到 1/N 的生成预算——**格数越多越崩，这是结构性的，换措辞救不回来**。

更根本的一条：同图并列的几格之间**没有任何强制一致的机制**，模型只是照着感觉画几格像的；
而逐张出图时每张都真的基于同一张基准图生成，一致性由图生图链路强制保证。

**本链纪律：格数上限 2×2。要更多角度就逐张出，不在同一张图里加格。**

### 2.1 **一阶 · 单视图基准图（文生图）**

**职责**：全链的身份与画风基准。**1 张，文生图。**

```
生成图片：{场景名}的场景参考图（基准图），人眼高度的平视广角建立镜头，站在{机位}、朝{方向}看，一眼能看清整个空间的结构与主要陈设。这是该场景的基准参考图，后续的俯视空间结构图与多视角参考图都基于它保持一致。

场景：{空间定位}。{空间结构与尺度}。{核心陈设}。{次要陈设}。{材质与磨损状态}。

光源：{光源在哪}。{光是什么性质与强度}。{照到什么地方}。{产生什么结果，含阴影特征}。

地面与天花板：{材质与磨损}。{结构，如肋架拱顶/木梁}。

画风：{项目风格锚压句首句逐字内联} + {本场景特有的材质与可见性要求}。

构图为{沿中轴线/环形/斜向}的强纵深：前景（{前景物}）→ 中景（{中景物}）→ 远景（{远景物}）三层分明。

画面中空无一人，只有静止的景物。避免过度锐化、色偏、噪点、碎块和畸变。
禁止内容：出现任何角色或人物、人物剪影、人影；画面上出现任何可读文字；{项目风格负面词}。
```

### 2.2 **二阶 · 俯视空间结构图（图生图，喂一阶）**

**职责**：**空间坐标说明书，不是氛围图**。**1 张，图生图（喂一阶）。**

> 🔴 下面模板里出现的「空间内容」「陈设清单」「标注规则」这些行内标签，
> **是要把后面的内容一起复制进 prompt 的**，标签本身承担提示作用，
> 所以保留成正常句——但**不要给它们额外加括号说明**（如「（严格）」「（共 N 件）」这类纯纪律），
> 纪律写在 `2.8 字段写法要点` 表里。

这是全链最有价值的一张——它提供的是**文字给不了的空间信息**：
N 件物体的相对位置，用文字写要几百字还写不准（「第三根柱旁」这类序号定位，模型根本不知道哪根是第三根），
而俯视图一眼说清。之后每一镜的站位都能拿它当依据，逐镜对账也有了坐标。

```
基于参考图1（该场景的单视图基准图），生成该场景的俯视空间结构图。这是一张空间坐标说明书，不是一个氛围画面——它的唯一职责是让人和后续镜头都能准确读出每件物体在哪里。保留参考图中的空间布局、建筑结构、陈设、出入口和动线关系，只把摄像机改为正上方垂直向下的鸟瞰视角。

空间内容：{长宽与长宽比}。以下每件物体的数量即为定值，画面中不得增减。{柱列位置与数量，含柱径}。{西端/东端/两侧的门窗位置}。

陈设清单，共 {N} 件，位置一律以墙体和门窗为基准给出：
一、{物件} {数量}，{相对于墙/门/窗的位置关系}。
二、……

地面与动线：{走道宽度与走向}。{磨损状态与散落物}。

出光与阴影：{主光来向，在地面形成的可读光斑形状}。{影子的长度与平行关系}。

标注规则：只在画面四条边的正中各标一个字——{前/后/左/右 的分配}，共四个字，不得重复、不得增加其他任何文字或符号。

画风：{项目风格锚}。

避免过度锐化、色偏、噪点、碎块和畸变；不要线框蓝图或工程图风格；不要出现任何人物；不要改变原有建筑结构与陈设数量。
```

### 2.3 **三阶 · 多视角图 2×2 四视角（图生图，喂一阶＋二阶）**

**职责**：**基准时段**的多角度参考。**1 张 4 格，图生图（同时喂一阶 + 二阶）。**

（此前文档称这一阶为「四视图」／「多视图」，与之是同一件事——2×2 就是四格。**v5.20.1 起统一叫「多视角图」**，避免与四阶的「不同时段的多视角图」混名；四阶是"多个时段各一张"，三阶是"多个角度合成一张"。）

四视角沿用 liqi 的**叙事性四镜**（平视 / 仰视 60° / 陈设特写 / 俯视广角）；
非写实风格（皮影 / 剪纸 / 水墨 / 版画）按 SKILL.md 的六处适配改成侧影 / 正面 / 关节分解等。

```
生成图片：{项目风格锚压句首句逐字内联}专业场景环境设定表，16:9 画幅，{空间类型}，画面填满不出现大面积空白，带极淡蓝图辅助网格。

以参考图1（单视图基准图）为画风与材质依据，以参考图2（俯视空间结构图）为空间结构依据，保持同一空间结构不变，只改变摄像机的位置和角度。

场景：{空间定位}。{空间结构与尺度}。{核心陈设}。{次要陈设}。{材质与磨损状态}。
光源：{光源类型与位置}。{光的性质与强度}。{光作用于何处、产生什么结果}。{阴影特征}。
氛围：{情绪基调}。{空气感与粒子}。{色温倾向}。
时间线锚点：{时段}，{该时段唯一光照特征}，{人工光是否点亮}。

画面排布 2×2 网格共 4 个视角面板，第一行从左到右：① 正面平视（直接面向场景的平视视角）；② 仰视（相机从水平面向上倾斜 60 度）。第二行从左到右：③ 特写（聚焦环境关键陈设的紧凑视角，填满大部分画面）；④ 俯视广角（从高处俯瞰，视野开阔）。

硬性不变量（四格中必须完全一致，任何一格都不得改变）：{逐条列死——每类物体的数量、位置基准、朝向}。禁止新增参考图上没有的陈设。

核心强制约束：四个面板展示完全相同的环境与陈设布局，摄像机位置、高度、方向明显不同，透视变化强烈且明确；四个面板的光照方向、色温、强度完全一致；面板之间添加干净纤细的 1pt 白色网格线分隔（内部边缘线，不要双重加粗，不要外框）。

禁止内容：出现任何角色或人物、画面上出现任何可读文字、面板分隔线双重加粗、黑色粗边框、不同面板出现不同陈设或不同光照方向、{时间线互锁词}、{安全约束}、{风格约束}。
```

### 2.4 **四阶 · 不同时段的多视角图（图生图，喂一阶＋二阶）**

**职责**：同一场景**其余时段**的多角度参考。**每个时段变体各 1 张，图生图（同时喂一阶 + 二阶）。**

**触发条件**：**按全文判读**（见 2.4.0）后，该场景的**时段集合 ≥2 个**。单一版本（全片只在一个时段出现）的场景**没有四阶**。
🔴 **不许只看注册表 `variants` 字段就下结论**——`variants` 是**登记结果**，不是**事实来源**。

**入口条件**：**基准版三阶已锁定 + 全文时段检索已做**。四阶不吃三阶的图——基准时段的多视角图是**三阶的产物**，不是四阶的输入。四阶的输入是**一阶 + 二阶这两张基准产物**，理由是空间结构由它们保证（见 2.4.2）。

#### 2.4.0 🔴 时段检索口径：按全文判读，不按字段判读

**一句话**：一个场景到底要出几个时段版本，**由全文说了算，不由 `variants` 字段说了算**。

**为什么不能只看字段**：`variants` 是**登记结果**，不是**事实来源**。登记时漏一个时段，四阶就少出一张图；等到分镜用到那个时段才发现场景只有基准版，只能现场补图——而现场补的图**没走「喂一阶 + 二阶」的链路**，画风与空间结构直接脱钩。这是「同一场景画成两个地方」最常见的成因，且**事后再补补不回来**（基准图已经锁定，补图只能当新基准，代价等于重做该场景）。

**判读源（四类，全读，缺一类都不算读完）**：

| # | 判读源 | 捞什么 |
|---|---|---|
| 1 | **剧本 / 大纲正文** | 场次行的「时间」列（拂晓 / 晨 / 正午 / 午后 / 黄昏 / 入夜 / 深夜），以及正文里的时间指示词（"天还没亮""掌灯时分""日头偏西""三更天"） |
| 2 | **分集结构表 / 分镜表** | 该场景 slug 出现过的**每一行的时段**——逐行过，不许抽样、不许只看首尾 |
| 3 | **台词与旁白** | 时间指涉（"昨夜那场火""三天后的黄昏""天亮之前"）——**这类最容易被漏**，因为它不在场次行里 |
| 4 | **注册表 `variants`** | **只作待核对清单，不作结论**；它的作用是被全文打脸 |

**判读动作（五步）**：

1. **列名**：列出该场景的 **slug + 全部别名 / 俗称**（"县衙停尸房"／"停尸房"／"义庄"可能是同一个 slug）。
   🔴 **只搜一个名字必漏**——剧本里叫"义庄"、分镜表里叫"停尸房"，是最常见的一种漏检。
2. **扫**：按「slug + 全部别名」在上表四类判读源里各搜一遍，列出**时段集合**。
3. **记证**：每个时段至少记 **1 条证据行**（文件名 + 行号 + 原文片段）。**没有证据行的时段不进集合。**
4. **对账**：时段集合与注册表 `variants` 逐条对齐，按下表三条判定处理。
5. **落盘**：检索结果写进场景 `.md` 的「**时段检索**」小节（证据行表 + 基准时段的选择理由），**四阶出图前必查**。

**三条判定（对账用）**：

| 情况 | 判定 | 处置 |
|---|---|---|
| 全文有证据、registry 没登记 | **漏登记** | **补登记 `variants` 并出四阶**（不许因为"字段里没有"就跳过出图） |
| registry 有、全文找不到证据 | **悬空时段** | 标 `pending`，**不出图**（留占位，不删条目）；确认剧本改了再删 |
| **同一场景同一场次的时段互相矛盾**（一处"黄昏"一处"入夜"） | **冲突** | **回问确认**，不许自行取一个——取错了整条四阶的光照全错，且连锁污染 `lock_out` |

**基准时段也按全文选**：`baseline_time` 不是"登记表里第一个"，是**全文里出现次数最多、且承担关键戏**的那个时段。
选错基准的代价是：其余时段全部要跟一个冷门时段的基准对齐，越修越远，且四阶的「逐字复用基准版」会把这个错误复制到每个变体。

**这条纪律同时管住另外三处**（不只在本阶生效）：

- **互锁词覆盖**：`lock_out` 要覆盖**全文时段集合里的全部时段**，不是只覆盖 registry 里那几个（见第三节「时段版本的互锁词」第 1 条「每版 ≥3 条、覆盖全部时段数」——这里的"全部时段数"指的是**全文判读出来的时段数**）。
- **C2 门**：`audit_project.py` 的 C2 门按「声明时段 × 该时段 `lock_out`」判定，它**只看得到 registry 里写了的**。所以全文检索的结果**必须先回填 registry**，否则 C2 门查不到——**门没报错不等于没问题**。
- **纵向一致性矩阵**：第四节纵向矩阵验的是「同场景 × 跨时间」，验的集合就是这里的**全文时段集合**，不是"已经出了图的那些"。

> **为什么这条不做成机检**：全文判读要跨四类文件做语义理解（别名归一、时间词转时段、矛盾识别），脚本断言会大面积假红，反而制造假绿门。
> 所以落到**硬纪律 + 落盘证据表**（证据行就是给人复查用的），不新增 ERROR 码。

#### 2.4.1 一阶与二阶都不重出

| 阶 | 基准时段 | 其余时段变体 | 为什么 |
|---|---|---|---|
| 一阶 单视图基准图 | 出 | **不出** | 变体的画风由基准一阶传递，重出会引入第二套画风基准 |
| 二阶 俯视空间结构图 | 出 | **不出** | 空间结构跨时段不变，重出会让「同一场景」变成两个地方 |
| 三阶 多视角图 | 出（基准时段的） | — | — |
| 四阶 不同时段的多视角图 | — | **出** | 这是变体唯一要出的图 |

**一句话**：变体**只补不同时段的多视角图这一张**，前面三阶全部复用基准版。

#### 2.4.2 **四阶同时喂一阶与二阶（与三阶同理）**

四阶的模板与三阶**逐字相同**，只有三段改内容。喂参考图时仍然**两张都要喂**：

- 只喂一阶 → 画风对，但空间结构会漂（模型不知道墙、门、窗、柱的相对位置）；
- 只喂二阶 → 结构对，但画风会跟丢（俯视图给不了材质与画风）。

这与 2.5 第 2 条是同一条纪律在四阶的重申。

#### 2.4.3 🔴 **四阶只有三段可以改**

```
① 光源：{按该时段 light_port + lighting_anchors 重写}
② 氛围：{情绪基调 · 空气感与粒子 · 色温倾向}
③ 时间线锚点：{时段}，{该时段唯一光照特征}，{人工光是否点亮}
```

**其余一律逐字复用基准版三阶的模板内容**——场景段、陈设清单、地面与天花板、画风、构图、硬性不变量、核心强制约束、面板排布。改任何一段都会引入与基准版的空间漂移。

**特别提醒「硬性不变量」那一段**：它的内容是「每类物体的数量、位置基准、朝向」，**必须与基准版逐字一致**，一个物件都不能增减。`baseline_time` 的用法就是「基准版锁死空间结构、陈设布局、色板；其余时段变体只改光照字段」。

#### 2.4.4 **四阶禁止内容必须补互锁词（按全文时段集合补，不按 registry 补）**

四阶的 `{时间线互锁词}` 位**不能留空**，也不能照抄基准版的。**要禁的是「全文判读出来的其余全部时段」（见 2.4.0）**，不是 registry 里碰巧登记的那几个。每个变体要写**别版特征**，且从**色温 + 光质 + 影子形态**三个维度同时下刀：

```
四阶 · 停尸房黄昏版：
禁止内容：……、正午顶光、冷白天光、短锐阴影、{安全约束}、{风格约束}。
```

只禁一个维度挡不住串版——夜版只禁了「日光」，模型仍可能给它一个均匀照明的顶光。

#### 2.4.5 **四阶的落盘命名**

四阶产物按 `<slug>-<时段>.md` / `.png` 命名，与三阶的基准版并列存放：

```
scenes/xianya-morgue-noon.md      ← 基准版（三阶）
scenes/xianya-morgue-dusk.md      ← 黄昏变体（四阶）
scenes/xianya-morgue-night.md     ← 深夜变体（四阶）
```

变体**不占新条目编号**（见 `版本拆分与互锁清单.md` 第二节），注册表里仍挂在原场景条目的 `variants` 下。

#### 2.4.6 **四阶的锁定判据（验全文时段集合，不验已出图的那几张）**

出完四阶后，按第四节**纵向一致性矩阵**验（同场景 × 跨时间，查「有没有区分开」）。**验的集合是 2.4.0 全文判读出来的时段集合**——少出一张就没验全。三项不合格就要回四阶重出：

- 色温差异：晨昏夜长得一样 → 对照 `lighting_anchors` 拉大色温差
- 光斑位置：光斑钉在同一处不动 → 写明光斑随太阳角度落在哪
- 阴影长度：影子长度没变 → 按锚点表写明拉伸程度

**先查「有没有漏时段」（2.4.0 的证据行表逐条对），再查这三项；四项全过，这个场景才算资产完整。**

### 2.5 生成纪律（硬，八条）

1. **前一阶没锁定不进下一阶。** 锁定判据——一阶看画风与光位是否稳定；二阶看墙、门、窗、柱、陈设的相对位置是否可读且无矛盾；三阶看四格的空间结构是否与二阶一致；**四阶看各变体是否既保留了基准版的空间结构、又与该场景其余时段可区分**。
2. **三阶与四阶都必须同时喂一阶和二阶产物。** 只喂一张必漂：喂一阶得到画风但空间随意，喂二阶得到结构但画风会跟丢。
3. **格数上限 2×2。** 禁止九宫格与多区块并列。需要更多角度时走第 4 条。
4. **要更多角度就逐张出。** 每次只出一个机位，每条仍同时喂「一阶 + 二阶」，**只改机位那一句，其余一字不动**。不要接着上一张续画——续画会继承上一张的漂移。
5. **不变量清单必写。** 三阶、四阶与后续逐张出图都要附一份「物件 + 数量 + 位置基准」清单，逐条列死，并明令禁止新增陈设。实测里最常见的漂移就是模型自己加东西。
6. **方向标注只许四边中点各一个字。** 模型自己加标注会重复与自相矛盾（实测出现过「后」×2、「左」×2 同时出现）。
7. **四阶只改三段、只禁别版。** 四阶的提示词只有光源 / 氛围 / 时间线锚点三段可改，其余逐字复用基准版；禁止内容必须补该变体的互锁词（**按全文时段集合补**，见 2.4.0）。改了第四段（比如为了让画面更贴这个时段而调整陈设），空间结构就与基准版脱钩了。
8. **进四阶前先做全文时段检索（2.4.0），不许只看 `variants` 字段开工。** 时段集合从「剧本 / 大纲正文、分集结构表与分镜表、台词与旁白、注册表 `variants`」四类判读源里判读，按 **slug + 全部别名**检索，每时段带证据行落盘。漏一个时段 = 少出一张图 = 分镜用到时才现场补图，而补出来的图没走「喂一阶 + 二阶」链路，**不可逆**。

### 2.6 失败模式与定位

| 症状 | 出问题的阶 | 处方 |
|---|---|---|
| 四格之间物体换位置、数量变化 | 三阶（参考图未生效或未喂） | 确认二阶与一阶都传进去了；风格保真度调高；重跑 |
| 俯视图与单视图空间对不上 | 二阶（图生图链路断了） | 别在俯视图上硬改，回到一阶重出再走一次 |
| 多格机位与指令相反 | 三阶（方位表述不清） | 用绝对方位（朝东/朝西），不用「朝东回看」这类相对表述 |
| 讲道台/道具位置每格都不同 | 定位方式错 | 把「第 N 根柱旁」换成「紧贴某墙，位于某门与某物之间的中点」 |
| 画面里多出参考图没有的东西 | 未写不变量清单 | 补第 5 条的清单与禁令 |
| 标注重复或矛盾 | 未约束标注 | 补第 6 条 |
| **变体的空间结构与基准版对不上**（同一场景画成两个地方） | 四阶（陈设段被改动 / 只喂了一阶或只喂了二阶） | 检查四阶模板是否只改了三条允许改的段；确认一阶与二阶都喂进去了；按 2.4.2 重跑 |
| **变体之间串版**（黄昏版里出现正午顶光） | 四阶（互锁词缺失或只禁一个维度） | 按 2.4.4 从色温 / 光质 / 影子形态三维度补互锁词 |
| **分镜用到某个时段，场景却只有基准版**（漏出图） | **四阶前置——没做全文时段检索，只看 `variants` 字段就开工** | 按 2.4.0 补检索 → 补登记 `variants` → 补出该时段四阶；**不许现场硬补**——硬补的图没走「喂一阶 + 二阶」链路，画风与结构双重脱钩 |
| **同一场景在剧本里换了个叫法就漏检**（"义庄" vs "停尸房"） | 检索只用了单一名字 | 按 2.4.0 第 1 步列全 **slug + 全部别名**再扫；漏检的时段补进集合 |
| **基准时段选了个冷门时段**（其余各版都围着它对齐，越修越远） | `baseline_time` 取了"登记表里第一个" | 按 2.4.0「基准时段也按全文选」重选：出现次数最多 + 承担关键戏的那个 |

### 2.7 标注模式（给美术评审用，带中文引线）

在一阶或三阶基础上，把「禁止内容」里的"画面上出现任何可读文字"换成"文字仅限中文引线注释，禁止英文与乱码"，并在核心强制约束后追加：

```
细节面板：{陈设特写}、{材质特写}、{光影特写}，引线标注中文。
```


### 2.8 字段写法要点（一阶—四阶通用）

> 下列字段在一阶、二阶、三阶、四阶四份模板里含义一致，写法要求相同。

| 字段 | 写法要点 |
|---|---|
| 场景 | 按「定位 → 结构尺度 → 核心陈设 → 次要陈设 → 材质磨损」五段写。陈设要**列全**，分镜里要用到的每件道具都得在场景里能找到 |
| 光源 | 必须写出**光源在哪、光是什么性质、照到什么上、产生什么结果**四件事。只写"昏暗"不够，生图模型不知道光从哪来 |
| 时间线锚点 | **本 skill 的核心字段**。写时段 + 该时段唯一特征 + 人工光状态。见下节光照锚点表，数值只从注册表取 |
| 四视角网格 | ①平视 ②仰视60° ③特写 ④俯视广角。顺序固定，便于跨场景比对 |
| 1pt 网格线 | 明确写"内部边缘线，不要双重加粗，不要外框"——AI 生图常把分隔线画成粗黑框或双线 |
| 色板 | **无——场景不画色卡**（色板上的色名与色值属于可读文字，与"场景默认无文字"冲突）。色值只落盘注册表 `palette` 与 `.md`，人工校色时查文档；图上的色彩一致性由光照锚点（色温/光位）与基准调色板逐字复用保证 |
| 禁止内容 | **"出现任何角色或人物"是场景资产的第一硬约束**，必须写 |

### 2.9 镜次阈值与备用机位版（v5.38.2 新增 · 频次驱动的第二版多视角）

> **一句话**：一个场景在分镜里被拍了超过 3 次，就该另有一版「换了个机位看」的多视角图——
> 高频镜头总用主版本四视角，构图会互相撞车。口径三态：**③ 社区实测**（来源：本库自立工程经验，2026-10-21 v5.38.2 立，无外部出处）
> （阈值为 2026-10-21 新立的工程经验值，非官方口径；样本不足，可按项目调整并在记录表写明）。

**一、镜次统计（全文镜次检索 · 出三阶前后各查一次）**

- **怎么数**：同一场景按 **slug + 全部别名** 检索分镜的「场景：」行，按**镜块去重计数**——
  一个镜块算一镜，同一镜内多次提及不算多镜。判读方式与 §2.4.0 全文时段检索同源：
  **按全文判读，不许只看字段**；分镜表没写完时按剧本场次预估，分镜定稿后复算一次。
- **判读源**：分镜表「场景：」行（主源）、剧本场次标注、注册表 `scenes` 桶（只作待核对清单）。
- **落盘**：检索结果写进场景 `.md` 的「**镜次检索**」小节（证据行表 + 高频判定），
  与「时段检索」小节并列，出图前必查。

**二、触发阈值与产出**

| 镜次 | 动作 |
|---|---|
| ≤3 | 不触发，主版本三阶够用 |
| **>3** | **触发**：在三阶主版本之外，**图生图另出一版「备用机位版」多视角图** |

- **图生图输入**：**以主版本三阶四视角成图为底图**（一致性由底图保证），一阶基准图作辅助参考
  同挂。与 §2.3「喂一阶 + 二阶」的纪律不冲突——那是从基准图组**生成**多视角的链路；备用机位版
  是**对已锁定成图做视角改绘**。二阶俯视图不再喂入（其信息已固化在三阶成图里，重复喂入会稀释
  底图权重）；若实测发现仅用三阶成图会丢结构细节，回退为「喂三阶成图 + 一阶」并在记录表写明。
- **格数**：仍 2×2 四面板，**格数上限纪律不变**（§2.0）。
- **机位要求**：四个面板全部采用与主版本**不同的机位角度或朝向**，至少在**两轴**上错开。
  主版本四面板是「正面平视 / 仰视 / 特写 / 俯视广角」（§2.3），备用版可用的机位轴：
  ① 平视转对角线（斜 45° 看同一空间）；② 朝向反转（从场景深处看向入口）；
  ③ 高低角互换（平视改贴地低角度，俯视改高位长焦）；④ 特写换主体（陈设 A 换陈设 B）。
  **禁止只把主版本镜像翻转**——镜像不产生新机位信息，等于没出。
- **一致性纪律**：画风、色域、材质、陈设清单、硬性不变量逐字复用主版本生成指令，
  **只有机位角度与朝向两段可改**（对齐四阶「只有三段可改」的纪律思路；备用版不涉及
  光照时段，故无 `lock_out` 互锁）。

**三、标注与登记**

- **版本标注**：产物命名 `<slug>_altview.png`；条目内 `label` 必写「备用机位版」；
  **适用镜次编号必写**（`applies_to`：镜 3、镜 7、镜 9…）——分镜制作时按它对应引用，
  哪个镜该用备用版一眼可查。
- **登记**：`scenes.<slug>.alt_views`（v5.38.2 新增桶，与 `variants` / `damage_states` 并列）：
  每条写 `label` / `applies_to` / `base`（图生图基准产物名）/ `angle_delta`（机位差异一句话）/
  `outputs`。**不填 `identity_verdict`**（视角容器不是新身份，同 `damage_states` 口径）；
  **不设 `lock_out`**（备用版与主版本是叠加关系不是互斥关系，主版本照常服务其余镜次）。
  字段细节见 `资产注册表_asset-registry.md`。
- **分镜引用**：适用镜次的【参考素材职责】指向备用版图；未触发的镜次照旧指向主版本。
  素材接线单照常登记。

**四、输出物（每次执行场景出图链必出）**

《场景镜次统计与备用机位版记录》表，落盘进场景 `.md` 的「镜次检索」小节：

| 场景 slug | 出现镜号 | 镜次 | 是否高频（>3） | 备用机位版状态 | 适用镜次 |
|---|---|---|---|---|---|
| 偏院 | 镜1、3、7、9 | 4 | 是 | 已出图（altview） | 镜3、7、9 |
| 正厅 | 镜2、5 | 2 | 否 | 不适用 | — |

**五、与既有机制的关系**

- 与**四阶（时段变体）**正交：四阶管「几点」，备用机位版管「从哪看」。可叠加——同时段变体
  若也高频，按同规则对该变体追加，`label` 写明所属时段。
- 与**方位卡**正交：方位卡管不变的空间基准，备用机位版不改空间基准、只改观察机位。
- 与**三类漂移**正交：镜次频次不改变场景状态，不进漂移表。
- **不做机检**（加门三问：阈值刚立、无实战命中数据；先跑项目攒《镜次检索》记录，
  命中模式清晰后再议是否进 audit_project 的纯汇总段）。

## 三、时间线光照系统（核心）

**外部经验一条（③ 社区实测 · 来源：Rylaispirit/cinematic-video-prompt-skill §8.4，MIT，2026-10-29 对拍吸收）**：写**具体钟点**比写时段词更能锁住光位——「下午 3:40–4:10」这类数字钟点给模型的光照锚比「下午」更硬。本库未逐条回归，项目光照锚点表仍以「时段＋唯一特征＋人工光状态」为主字段，钟点只作可选强化写法，与 Ark 的「时长：X 秒」回声同属「可写不必须」。

### 为什么必须有

没有光照锚点时，每次生成场景都在随机采样色温和光位。结果是：同一场戏的甲场景是暖黄夕照、乙场景是冷白正午，剪在一起直接穿帮；同一场景的清晨和正午又长得一模一样，时间流逝感消失。

两条铁律：
- **同一场景 × 不同时间 → 光影必须可区分**
- **不同场景 × 同一时间 → 光影必须一致**

### 项目级光照锚点表（一次定义，全场景共用）

写进 `asset-registry.json` 的 `lighting_anchors`。**这是全项目唯一光源事实源**，任何场景的任一时段都必须从这里取值，禁止现场编。

| 时段 | 色温 (K) | 光质 | 入射角 | 影子 | 人工光 | 关键特征 |
|---|---|---|---|---|---|---|
| **拂晓** dawn | 6500–8000 | 极弱、全漫射 | 无明确方向 | 几乎无、极柔 | 烛火将熄 | 冷蓝灰主导，尘埃悬浮，冷暖交界 |
| **晨** morning | 5000–5600 | 中、斜射 | 15–30° | 长、较清晰 | 灭 | 晨雾，光束斜长，冷白偏暖 |
| **正午** noon | 5500–6500 | 最强、硬 | 60–90°（近垂直） | 最短、边缘锐利 | 灭 | 高对比，垂直光柱，暗部浓重 |
| **午后** afternoon | 4500–5000 | 强、略软 | 30–45° | 中长 | 灭 | 光斑偏移，暖意初现 |
| **黄昏** dusk | 2000–3500 | 中、水平穿透 | 5–15°（极低） | 极长、拉伸变形 | 将燃 | 强暖橙，长投影横贯画面 |
| **入夜** evening | 2000–2700 | 弱、点光源 | 不适用（多点） | 短、围绕光源 | **点亮** | 烛火光晕，衰减快，光域小 |
| **深夜** night | 7000–10000 | 极弱、单光源 | 单一（月/残烛） | 浓黑、对比极强 | 残烛/无 | 大面积暗部，仅轮廓微光 |

注意：**黄昏和入夜都是暖色，但性质完全不同**——黄昏是低角度日光（有明确方向、投长影），入夜是点光源（无方向性、光域小、衰减快）。这是最容易搞混的一对，互锁词必须能区分。

### 天气-光照耦合表（时段之外的第二个光照维度）

**时段决定色温与入射角，天气决定光被怎么改造。** 只锚定时段不锚定天气，同一时段的两个场景照样会打架。

| 天气 | 高光 | 阴影 | 色温偏移 | 粒子 / 空气 | 曝光 | 提示词写法 |
|---|---|---|---|---|---|---|
| 晴 | 明亮、边界清晰 | 硬、边缘锐利 | 无偏移 | 无 | 高 | 硬边阴影，高光锐利 |
| 薄云 / 散射 | 柔化，有方向无锐边 | 软，方向仍可辨 | 微冷 +300K | 无 | 中高 | 柔化定向光，阴影有方向但边缘松散 |
| 阴 | 几乎无高光 | 极软，近乎消失 | 冷 +800–1500K | 无 | 中 | 无可见阴影，均匀顶光，色温偏冷 |
| 雨 | **高光被散射成片** | **阴影软化，对比下降** | **冷蓝偏移** | 雨丝、湿地面镜面反射 | 中低 | 散射高光，软化阴影，冷蓝偏移，湿地面镜面反射 |
| 雾 / 霾 | 光域扩大，光柱可见 | 阴影几乎消失 | 冷灰偏移 | **体积雾、丁达尔光柱** | 低对比 | 体积雾中可见光柱，低对比，远景衰减 |
| 雪 | 高光增强（雪面二次反光） | 阴影偏蓝（天空反射） | 冷 +1000K，高光仍暖 | 雪粒、白雾呼吸感 | 高（易过曝） | 雪面二次反光，阴影偏蓝，高光保留细节 |
| 风沙 / 扬尘 | 高光浑浊 | 阴影被尘土冲淡 | 暖黄偏移 | **浓密悬浮颗粒，光柱明显** | 中低 | 浓密悬浮尘土，浑浊光柱，暖黄偏移，远景低可见度 |

⚠️ **最常见的翻车**：提示词写了"雨天"，画面却是晴天的锐利硬阴影。天气对光的**物理后果**必须显式写出，只给天气名词没用。

### 大气元素锚点（跨场景一致）

大气元素最容易忽有忽无——一个场景有尘埃、另一个没有，剪在一起立刻穿帮。登记为项目级锚点：

```
atmosphere: { particles: "悬浮尘埃", fog: "无", rain: "无", rule: "尘埃是逆光产物：只有存在逆光或光柱的场景才可见，漫射场景不出现" }
```

**规则必须写成条件句，不是绝对值。** "所有场景都有尘埃"是错的——漫射光下看不见尘埃；"逆光场景才有"才对。

### 物体恒存锚点（场景痕迹跨场次保留）

场景的"伤疤"要跨场次保留：墙上的裂缝、门板的破损、地面的污渍、道具的缺口。这些是场景的指纹。

```
permanent_marks: ["东墙第三块砖有斜裂纹", "停尸台西北角有缺口", "排水口附近有深色污渍"]
```

出图时写进提示词的"场景"行，并在禁止内容加"改变既有痕迹"约束。不登记的话，同一面墙第一场有裂缝、第三场消失，观众说不出哪里怪但会觉得假。

### 色彩节奏设计（什么时候该"破"一致性）

**一致性不是目的，一致性是为了让刻意的破有意义。**

> 观众把有意的色彩转变读作叙事，把随机的转变读作失误。

规划方法：
1. 全片定一个基准调色板，逐字复用于所有场景。
2. **只在情绪转折点留一处刻意对比**（如：全片冷青灰，唯独真相揭晓那场转暖）。
3. 要破就**破得彻底且持续整场**——半吊子的偏移最难看。

```
color_rhythm: { baseline: "低饱和青灰调", turning_point: "第7场真相揭晓，转暖橙", rule: "除第7场外全部锁定基准调" }
```

**🔴 色彩节奏与光照锚点是两回事，不要互相取消**（v5.6.2 明确）：

| | 本节的 `lighting_anchors` | 本节的 `color_rhythm` + 注册表 `palette` |
|---|---|---|
| 管什么 | **光从哪来**——光源色温、入射角、影子 | **全片落在哪个色域**——最终画面的调色倾向 |

所以「全片锁定低饱和青灰调」与「黄昏变体色温 2000–3500K 强暖橙」**并不矛盾**：黄昏是**光源**暖，成片的**调色**仍可以压回青灰基调（这正是志怪 / 武侠题材的常规做法——暖光落在低饱和的整体色调里）。

反过来说，`color_rhythm` 的「一处刻意破」破的是**调色**，不是取消该场景的光照锚点。两者叠加，不是二选一。

（同一结论另见 `质控层_门禁与过审.md`「为什么调色比换脸更重要」一节。）

### 场景级光照锚点

光锚定在时间上，还要锚定在空间上。每个场景必须登记**进光口**：

```
light_port: { desc: "高处带木栅栏的小窗", wall: "东墙高处", fixed: true, note: "进光口位置全时段固定，变的只有太阳角度" }
```

**`fixed: true` 是关键**。进光口位置是建筑结构，跨时段不变——变的只是太阳角度决定了光斑落在地面哪里、影子多长。这条保证了"同一场景不同时间"既有变化又可辨认是同一个地方。

### 时段版本的互锁词

场景的时段版本，本质就是**多版本**，沿用 liqi 的版本互锁机制：

| 版本 | 禁止内容必写（互锁词） |
|---|---|
| 停尸房·正午 | 暖橙夕照、长投影、烛火光晕、月光、浓黑 |
| 停尸房·黄昏 | 正午顶光、冷白天光、短锐阴影、月光、浓黑 |
| 停尸房·深夜 | 日光、天光、均匀照明、暖橙夕照、长投影 |

**🔴 两条硬要求**：

1. **每个变体的 `lock_out` 必须覆盖「其余所有变体」的标志性特征**（不是只写一两条）。
   **「其余所有变体」= 2.4.0 全文判读出来的时段集合，不是 registry 里碰巧登记的那几个。**
   三变体的场景里，正午版要同时禁住黄昏特征与深夜特征。**写得全不全直接决定 C2 门查得出来查不出来**——
   `audit_project.py` 的 C2 门按「声明时段 × 该时段 lock_out」判定，`lock_out` 里没写到的别版特征它就看不见。
   **建议每版 ≥3 条，覆盖全部时段数。**
2. **从色温、光质、影子形态三个维度同时下刀**。只禁一个维度挡不住串版——夜版只禁了「日光」，
   模型仍可能给它一个均匀照明的顶光。

（上表就是按这两条写的：正午版禁的是黄昏/深夜的光，黄昏版禁的是正午/深夜的光，深夜版禁的是白天/黄昏的光。）

### 变体的出图怎么跑（v5.6.2 补，v5.6.3 起归入四阶）

场景时段变体在注册表里是 `scenes.<slug>.variants.<时段>` **子键**，不是新条目、不建新卡。但**图还是要各出一套**——**完整出图路径见 2.4 四阶**，此处只留四条速记：

| 阶 | 基准时段 | 其余时段变体 |
|---|---|---|
| 一阶 单视图基准图 | 出 | **不出**（复用基准版） |
| 二阶 俯视空间结构图 | 出 | **不出**（空间跨时段不变） |
| 三阶 多视角图 | 出（基准时段的） | — |
| **四阶 不同时段的多视角图** | — | **出**，同时喂「基准一阶 + 基准二阶」 |

**🔴 第零条：要出哪几个时段，按全文判读，不按 `variants` 字段**（见 2.4.0）。上表解决"怎么出"，2.4.0 解决"出几个"——顺序错了，出得再对也是漏的。

**变体的提示词只有三段可改**（光源 / 氛围 / 时间线锚点），其余逐字复用基准版三阶——完整清单见 2.4.3。

**变体的禁止内容必须补上互锁词**（见上表，且**按 2.4.0 的全文时段集合补**）。这条是变体之间唯一的隔离手段。

**陈设与空间复用不是可选项**：`baseline_time` 的用法就是「基准版锁死空间结构、陈设布局、色板；其余时段变体只改光照字段」。所以四阶的提示词里，陈设清单的**数量与位置关系必须与基准版逐字一致**，一个物件都不能增减。

### 人工光规则

一条容易忘的纪律：**白天不点烛，入夜必点烛**。写时段锚点时必须显式声明人工光状态（"烛火熄灭"／"烛火点亮"），否则生图模型会在正午场景里给你点上灯笼。

## 四、一致性自检矩阵

出图后按这个矩阵验，两个方向都不能漏：

**纵向（同场景 × 跨时间）——查"有没有区分开"**

| 检查项 | 不合格表现 | 修法 |
|---|---|---|
| 色温差异 | 晨昏夜长得一样 | 强制按锚点表拉大色温差，写进提示词 |
| 光斑位置 | 光斑钉在同一处不动 | 写明"随太阳角度移动，光斑落在{具体位置}" |
| 阴影长度 | 影子长度没变 | 按锚点表写明影子长度与拉伸程度 |
| 人工光 | 白天也点着灯 | 显式写"烛火熄灭" |
| 曝光水平 | 深夜和正午一样亮 | 写明整体曝光档位 |

**横向（同时段 × 跨场景）——查"有没有统一"**

| 检查项 | 不合格表现 | 修法 |
|---|---|---|
| 色温一致 | 同一场戏冷暖打架 | 所有场景从同一 `lighting_anchors` 取值 |
| 光位一致 | A 场景光从左、B 从右 | 登记各场景进光口朝向，跨场景对齐 |
| 对比度一致 | 有的硬光有的软光 | 同时段光质写死同一档 |
| 粒子/空气感 | 有的有尘埃有的没有 | 尘埃是**逆光产物**，同时段要么都有要么都没有 |
| 曝光一致 | 明暗跳变 | 统一写曝光档位 |

## 五、场景资产专用负面词

每次都必带的：

```
出现任何角色或人物、人物剪影、人影
画面上出现任何可读文字（纯场景模式）
面板分隔线双重加粗、黑色粗边框
不同面板出现不同陈设或不同环境
不同面板光照方向不一致
```

**畸变三件套（v5.36.0 新增 · 来源 shuohao novel-art 反向提示词打底）**：

```
warped perspective / 透视畸变
melted geometry / 几何融化
floating objects / 物体漂浮
```

这三条治的是「结构性崩坏」而非「风格偏差」——透视歪了、几何化了、物体飘了，图就废了，
而风格词一个都没违规。之前只禁了人物与文字，漏了这层。**按场景类型追加时保留这三条，不要被替换掉。**

按场景类型追加：

| 场景类型 | 追加禁止 |
|---|---|
| 内景·白日 | 烛火光晕、暖黄点光源、均匀无方向照明 |
| 内景·夜晚 | 日光、天光、冷白顶光 |
| 外景·白日 | 人工暖光、光域过小 |
| 外景·夜晚 | 均匀天光、日照暖橙 |
| 古装/东方题材 | 现代建材、混凝土、金属反光、玻璃幕墙、电线 |

## 六、场景资产失败模式

| 症状 | 优先怀疑 | 修法 |
|---|---|---|
| 画面里冒出人 | "无角色"约束不够靠前 | 把"出现任何角色或人物"提到禁止内容**第一项** |
| 四面板环境不一致 | 缺"完全相同的环境"约束 | 加"四个面板展示完全相同的环境与陈设布局" |
| 四面板视角雷同 | 角度描述太软 | 写死角度数值（"向上倾斜60度"而非"仰视"） |
| 分隔线变粗黑框 | 没写"不要双重加粗" | 加"内部边缘线，1pt，不要双重加粗，不要外框" |
| 画面出现乱码文字 | 模型自作主张加标注 | 禁止内容加"画面上出现任何可读文字" |
| 跨场景色温打架 | 没用光照锚点表 | 全场景从 `lighting_anchors` 取值 |
| 同一场景晨昏无差别 | 没写时段唯一特征 | 按锚点表写明该时段色温+入射角+影子三件套 |
| 正午场景点了灯 | 没声明人工光状态 | 显式写"烛火熄灭" |
| 光斑位置不动 | 没写光随太阳移动 | 写明光斑落点随太阳角度变化 |
| 场景缺关键陈设 | 陈设列得太粗 | 把分镜需要的道具全部写进"次要陈设" |
| **写了雨天却是晴天的硬阴影** | 只给了天气名词 | 查天气耦合表，写出物理后果（散射高光／软化阴影／冷蓝偏移／湿反射） |
| **尘埃忽有忽无** | 大气规则写成绝对值 | 改成条件句："尘埃是逆光产物，只有逆光或光柱场景才可见" |
| **墙上的裂缝场次间消失** | 没登记 `permanent_marks` | 登记场景痕迹，出图写进"场景"行，`lock_out` 加"改变既有痕迹" |
| **全片一个色调太平** | 缺色彩节奏设计 | 规划一处情绪转折点的刻意偏移，且持续整场 |
| **同一场景两个镜头镜头语言打架** | 没定相机语言锚点 | 登记 `camera_language`（焦段／运动／景深／机位高度） |

**字段含义**：
- `identity_verdict` 挂在**场景本体**上，四桶（characters / props / creatures / scenes）口径一致，取值 `reuse` / `new_variant` / `new_asset` / `unresolved`。判定走 `资产层_锁定与一致性.md` 5.1—5.3；判为 `unresolved` 的场景**不得写 `outputs`**，也不得出 4 View。
- `variants` 装**时段变体**（时间漂移），`damage_states` 装**破损态变体**（状态漂移）；两者是并列容器，都受 F 门双向 `lock_out` 约束。字段定义见 `资产注册表_asset-registry.md`。
- `weather` 挂在**变体**上，不挂在场景上——同一个场景不同时段可以有不同的天气。取值后必须去天气耦合表查它对该时段光的具体改造，写进提示词。
- `permanent_marks` 挂在**场景**上，跨时段复用，出图时写进"场景"行，并在 `lock_out` 加"改变既有痕迹"。
- `camera_language` / `atmosphere` / `color_rhythm` / `forbidden_elements` / `generation` 是**项目级**字段，定义在 `资产注册表_asset-registry.md`，与本文档的 `lighting_anchors` / `scenes` 同属一个 JSON 文件。

**`baseline_time` 的用法**：先定一个基准时段（通常是该场景第一次出现的时段），把它的光照、色板、陈设全部锁死；其余时段变体**只改光照相关字段，陈设与空间结构一律复用基准版**。这样既保证跨时间可区分，又保证跨变体不会把场景画成两个地方。
