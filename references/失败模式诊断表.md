# 失败模式诊断表

出图崩了之后的排查手册。按「症状 → 优先怀疑 → 修法」查表，**只改受影响字段，不要整条重写**（整条重写会引入新的漂移）。

## 一、身份与五官

| 症状 | 优先怀疑 | 修法 |
|---|---|---|
| 三视图脸不一样 | 参考图锚定太弱 | 参考角色行加"严格沿用参考图片全部五官样貌"，并把它提到提示词**最前面** |
| 脸跟参考图完全不像 | 图生图参考没生效 | 确认参考图真的传进去了；或改用"单视图分批出图 → 后期拼接" |
| 眼型/瞳色漂移 | 特征埋在长句中间 | 把"全黑瞳孔、无眼白"这类硬特征提到"参考角色"行，不要放在细节面板里 |
| 年龄忽大忽小 | 年龄描述含糊 | 写"外表20岁"而非"年轻女子" |
| 脸被美颜/塑料感 | 缺肤质约束 | 加"真实皮肤纹理，禁止磨皮、禁止塑料感皮肤" |

## 二、比例与构图

| 症状 | 优先怀疑 | 修法 |
|---|---|---|
| 身高线穿模、压在身上 | 构图约束不够硬 | 加"与人物身体留出空隙，绝对不能遮挡、穿插人物躯体" |
| 三个视图高矮不一 | 缺共同基准线 | 加"三个角色的脚底严格贴合同一条水平地面基准线" |
| 动漫角色显得成人化 | 头身档位错用了写实 7–7.5 | 按目标观感重选：日式 3D 动漫 6–6.5、日式 2D 5.5–6.5（档位全表见 `扩展面板与比例色彩速查.md` 第四节「头身档位速查」） |
| 四肢长度不一致 | 只锁了头身没锁四肢 | 核心强制约束里补全"肩宽、躯干长度、四肢长度全部统一" |
| 身高线刻度数字乱码 | 模型数字渲染能力弱 | 刻度数字允许简化为短线刻度，cm 数值移到 `.md` 承载 |

## 三、版本串版（本 skill 独有风险）

| 症状 | 优先怀疑 | 修法 |
|---|---|---|
| A 版混进 B 版配色 | 互锁词缺失或位置太靠后 | 把另一版本特征写进禁止内容的**最前面**（负面词位置越靠前权重越高） |
| 烧焦态道具自己复原了 | 缺"禁止恢复完好" | 禁止内容补"恢复完好、还原成未烧毁状态" |
| 新版本出了但旧版本没加锁 | 只给新版本加了互锁 | **回头给旧版本的 `lock_out` 补上新版本特征**（最高频的漏项） |
| 两个版本越出越像 | 版本间可区分特征太少 | 强化"结构差异"而非只靠颜色（如：有无腰带、衣摆长度不同） |

## 四、面板与元素丢失

| 症状 | 优先怀疑 | 修法 |
|---|---|---|
| 面板被吞（少画了一两个） | 超过密度预算 | 面板砍到 ≤ 3 个，或拆成两张图 |
| 道具消失 | 被模型当装饰处理 | 加"必须作为独立物体完整呈现" |
| 道具被藏到角色身上 | 独立面板约束不足 | 加"禁止只藏在角色头发内部/衣内，必须作为独立道具物体呈现" |
| 局部放大面板没画 | 位置描述不明确 | 明确"主三视图四周排布"并编号列出 |
| 色板缺失 | 色板描述埋太深 | 提到禁止内容之前 |

## 五、文字与注释

| 症状 | 优先怀疑 | 修法 |
|---|---|---|
| 引线中文乱码 | 模型中文渲染能力不足 | 走降级预案：编号引线+图例区 → 纯图无字 |
| 出现英文注释 | 提示词里混入了英文术语 | 全包检索英文引线词，改中文；禁止内容加"禁止出现英文单词" |
| 文书类道具文字变符号 | 汉字渲染能力 | 文书类本就允许"生成变形则以留白处理、后期合成"，按预案走 |
| 图丢字后信息找不回 | 没落盘 `.md` | **图可能丢字，文档不能丢信息**——`.md` 必须完整保留全部中文注释 |

## 六、风格与色彩

| 症状 | 优先怀疑 | 修法 |
|---|---|---|
| 跨批次色偏 | 只有中文色名没有 HEX | 补 HEX，且从注册表取色而非现场编 |
| 道具风格跟全片脱节 | 缺"整体风格"行 | 道具条目**必须**有整体风格行（渲染方式+色调+做旧+与全片风格锚一致） |
| 布料像一块纯色板 | 面料细节不足 | 补织法、厚度、缝线、袖口、褶皱、垂坠、光泽、做旧中至少 4 项 |
| 出现透视畸变 | 正交相机约束丢失 | 收尾句保留"全部视图采用严格正交相机，无透视畸变"（**仅角色/道具**——场景条目要保留透视，不适用本条） |
| 画面大面积留白 | 缺填满约束 | 首行保留"画面填满无大面积空白" |
| 场景四视角看起来一模一样 | 误加了正交约束 | 场景收尾句删掉"严格正交相机"，改为保留透视的版本 |
| 场景图上冒出色卡/色票 | 提示词残留了色板行 | 场景模板已无色卡（色卡文字违反"默认无文字"）——删掉色板行，色值落盘注册表即可 |

## 七、诊断纪律

1. **一次只改一个变量**。同时改提示词和参数，崩了不知道是谁的锅。
2. **修完回写注册表**。修法里凡是改了身高、色值、互锁词的，必须同步更新 `asset-registry.json`，否则下次又犯。
3. **记录修订日志**。`.md` 里留「修订日志」小节，写明改了什么、为什么改、改之前是什么样。
4. **超过三次修不好就换路径**（本条只管**生图链 / 资产出图**）。比如三视图一致性反复失败，直接改为单视图分批出图再人工拼接——不要在同一条死路上加更多约束词。
   ⚠️ 不要和视频返修混用：`失败诊断与返修映射.md` 第二节（返修决策树）给的是**视频生成返修**的**连改 2 次**阈值。两条链的试错成本不同（一次出图远比一次生成便宜），所以阈值不同是有意为之，不是矛盾。
