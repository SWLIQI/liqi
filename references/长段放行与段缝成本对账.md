# 长段放行与段缝成本对账（v5.19.0 新建 · 时长规则唯一权威）

> **本文件是「单条时长怎么定」的唯一权威**（判据 / 对账 / 方法论层）：SKILL.md Step 1 只保留分档表摘要。
> ⚠️ v5.43.0 分层澄清：**硬参数数值（15s / 20s / 30s 等）的唯一事实源是 `references/model-limits.json`**，
> 本文件管的是判据与规程——两层各管各的，数字冲突以 JSON 为准。历史上「20s 滑窗红线」是一条平铺 WARN——见 §一，它把三个
> 不同的问题（时长长 / 内容少 / 没结尾）混成一条，v5.19.0 起废止，改为**三条件放行制**。

## 〇、先对齐两个上限（别和放行制搞混）

| 线 | 值 | 性质 | 越了怎么办 |
|---|---|---|---|
| **官方硬上限** | 2.5 面 30s / 2.0 面 15s / H3 面 15s | 官方口径（API 不接更长的） | **强制滑窗拆分**，`E-OVER-30S`，无例外 |
| **放行线** | 2.5 面 20s | 本库社区实测（非官方，见 §四） | 满足 §一 三条件 → 放行到 30s；缺任一 → `W-OVER-20S` |

2.0 / H3 面没有 20s 档（官方 4–15s 封顶），长内容走 `Shot N` 标签单调用内切分，
**不适用本文件的放行制，也不存在段缝**——这是 2.5 面独有的问题。

## 一、为什么要改：平铺红线的三个病灶

「>20s 不拆，模型只稳出约 20 秒、剩余循环播放凑」这条规则治的病是真的，但它的写法把三个
不同的问题混成了一条：

1. **时长长 ≠ 会循环**。循环的机理是模型在描述内容耗尽后，用已发生的运动填满剩余时长。
   20s 里铺 6 个独立节拍，比 25s 里铺 2 个节拍安全得多。病根在**内容供给**，不在时长数字。
2. **告了之后没有出路**。W-OVER-20S 只会说「建议拆」，但拆的代价——段缝跳切风险、多一次
   生成、末帧锚定工作流——从不对账。结果是「保险」拆成 16~24s 碎段，段缝数量翻倍，
   用跳切风险换循环风险，账没人算。
3. **阈值是断言不是实证**。「约 20 秒」没有样本、没有测法、没有口径标注。按本 skill 的
   口径三态文化（官方口径 / 平台特性 / 社区实测），它必须落成可复算的社区实测（见 §四）。

v5.14.0 立的「段末接戏全景」曾被当作现成的停止语义候选；**v6.4.0 起该机制废止**（实测效果不佳，见空间层 §十三留档），长段的停止语义由条件 C 的**末拍可见终态**承担，不依赖全景拍。
**停止语义**——这是治循环最直接的手段，但时长规则从没用过它。

## 二、长段放行三条件（>20s 单条，全部满足才免 W-OVER-20S）

| # | 条件 | 判据（机械可查） | 治什么 |
|---|---|---|---|
| **A 声明** | 段头写 `【长段声明】Ns · 节拍 N · 收束：末1s定格` | 段头存在 `【长段声明】` 字样（`check_prompt.mjs` 按块文本匹配） | 把「我知道这是长段」从默认变成明示——同【打戏声明】【配额声明】【段缝声明】先例，**声明不是免检，是换一道检查** |
| **B 密度** | 节拍供给 ≥ 时长档下限：21–30s 需 ≥4 个时间轴段，每段一个独立主动作 | 时间轴段数 ≥ `beatBand` 下限；不足由 `W-BEAT-BUDGET` 另行报出 | 循环的第一病根：内容供不上时长 |
| **C 收束** | 末拍是收束结构：① 末拍景别装下全员（档 1~3，禁大远景）② 收束窗措辞（「镜头运动收束」/「停止大幅动作」）③ 定格措辞（「动作完全静止、画面定格」/「保持该姿态与站位」） | 末段时间轴段文本命中 `定格\|完全静止\|保持该姿态`；景别装下全员由人工核（不再绑接戏全景判据——v6.4.0 该机制废止） | 循环的第二病根：没有明确的停止语义，模型只能靠循环收尾 |

**三条件与既有机制的关系（不新造概念）**：
- 条件 C 借用过 v5.14.0 段末接戏全景的判据；**该机制 v6.4.0 起废止**（实测撤销），条件 C 收窄为末拍可见终态要求（收束窗＋定格措辞＋景别装下全员），不再要求补全景拍。
- 条件 B 的段数带宽 `check_prompt.mjs` 早就有（21–30s：4–6 段），只是过去只查上限
  （>6 报 W-BEAT-BUDGET）不查下限；v5.19.0 起补下限判定，两码合起来才是完整的密度门。

## 三、分档处置表（替代旧四行表）

| 单条时长 | 处置 |
|---|---|
| ≤15s | 直出，无附加条件（质量实践：单段高动态直出最稳） |
| 15–20s | 放行条件：`[起-止秒]` 时间戳分段 + 一镜连贯运镜过渡（模型不支持组内硬切）。**满足即放行，不另需「写明理由」**——旧规则「需写明理由」是模糊门槛，v5.19.0 起废止，理由只挂在「偏离密度匹配时长」上 |
| 20–25s | **三条件放行**：A+B+C 齐 → 免 W-OVER-20S；缺任一 → W-OVER-20S（消息点名缺哪条） |
| 25–30s | 三条件放行 + **收束结构强制** + 建议配首帧参考（I2V 长段比 T2V 稳） |
| >30s | 强制滑窗（官方硬上限），每窗 ≤20s（30s→2 窗，45s→3 窗）；窗间禁「接上/继续/仍穿着」 |

**滑窗阈值仍记 20s**：它是「密度不足时的拆分线」，不是「时长禁区」。

## 四、20s 阈值的实证口径（社区实测态，可复算）

- **口径三态定位**：官方口径只有「2.5 单条 ≤30s」；「20s 之后模型只稳出约 20 秒」是
  **本库社区实测**，不声称官方。写进任何对外文档前按此行内标注转述。
- **测法**（要复算时照此跑）：同一内容双跑——20s 直出 vs 目标时长（25s/28s）直出，
  数两件事：① 有效独立画面事件数（20s 基准内的节拍是否都出现）② 尾段重复起始秒。
- **循环判定指纹**（返修时用）：尾段出现与已发生动作**同构**的运动（同起止点、同路径、
  同幅度）且**无新事件**——是循环；尾段动作减速收势、有新信息——不是循环，别误判去拆段。
- **样本与结论存档**：随项目复盘更新本节的实测记录（日期 / 模型版本 / 目标时长 /
  重复起始秒 / 节拍供给数），攒够样本再谈阈值修订。**在样本攒够前，20s 不放也不动。**

## 五、段缝成本对账表（拆不拆，把账摆到桌面上）

一条 60s 的内容，三种拆法的全成本对账（段缝成本按 v5.16.0 段缝四选一已锁定
【段缝声明】计；末帧锚定 = 实际尾帧验收 + 下一段 `first_frame` 硬绑定 + 首拍保持与首帧复核，能降低漂移但不承诺 100% 一致——v5.45.0 起取帧首选 API 原生
`return_last_frame: true`（任务完成直接返回无水印尾帧 jpeg，省掉手动截图的选帧与压缩损失），
无该参数的工具再回退手动截图，截帧与接线仍占少量人工）：

| 拆法 | 段数 | 段缝数 | 生成次数 | 循环风险 | 段缝/跳切风险 | 适配 |
|---|---|---|---|---|---|---|
| 4×15s | 4 | 3 | 4 | 无 | **最高**（3 个跳切点） | 高动态动作戏、单镜信息量小的快切段 |
| 3×20s | 3 | 2 | 3 | 低（贴线） | 中 | 默认推荐区间 |
| 2×30s | 2 | 1 | 2 | **最高**（除非三条件全齐） | 最低 | 节拍供给充足（每段 ≥4 独立节拍）+ 收束结构完备的长叙事段 |

**对账三条纪律**：
1. **段数越少、段缝越少、一致性越好**——这是上游（老李 V7.4.20）的口径，liqi 认同其
   方向；分歧只在默认值（见 §六）。放行制的意义就是让「2×30s」从违规变成**可选策略**。
2. **不要为「保险」拆段**：把 30s 内容拆成两个 15s，多一个段缝 = 多一次跳切风险 +
   多一轮末帧锚定——用确定性损失换不确定性规避，不签。
3. 拆法一旦定了就**全片一致**，不要第 3 段 20s、第 4 段 15s 地随机跳——段长节奏本身
   是视听语言（同 §F 锁 2.0 时长分配铁律：禁「段长÷镜数」机械等分）。

## 六、与上游（漫剧老李 V7.4.20）的已知分歧

老李的同位规则：**2.5 默认 25~30s 吃满上限，禁 16~24s 碎段区**（「段数越少段缝越少」）。
liqi v5.19.0 前：20s 红线建议拆。**本版起 liqi 实际已能表达 25~30s**（三条件放行），
分歧只剩**默认值**——老李默认长，liqi 默认贴 20s 线。**不折中**：两边各有实证
（liqi 怕循环凑、老李怕段缝跳切），在 §五 对账表里让项目自己选，CHANGELOG 记明这是
已知分歧不是遗漏。下游任何人不得引用「liqi 规定必须 ≤20s」——没有这条规定。

## 八、返修顺序（治「后半段重复」的正确次序）

旧顺序（失败诊断表 v2.0）：「单条超过 20s 没拆 → 走滑窗拆分」——**把第三步当第一步**。
v5.19.0 起改为：

```
后半段重复 / 循环感
 ├─ ① 先查密度：节拍供给够不够（段数 ≥ 时长档下限？每段独立主动作？）
 │     不够 → 补节拍或拆段（补戏不注水：加冲突不加寒暄）
 ├─ ② 再查收束：末拍有收束窗 + 定格措辞吗？景别装下全员吗？
│     没有 → 补收束窗与定格措辞（可见终态收束），不要先拆段
 └─ ③ 最后才拆段：①②都满足仍循环 → 走滑窗拆分（每窗 ≤20s），
        并按 §五 对账表重新选拆法（拆完核对段缝声明）
```

**判据先行**：动手前先按 §四 的循环指纹确认「是真循环还是收势」——尾段减速收势、
有新信息的长段是合格长段，拆它才是事故。
