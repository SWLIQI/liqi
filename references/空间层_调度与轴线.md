## 一、 站位与轴线的两层写法

```
轴线：查验台—门框连线，旅客甲在画面左三分之一（西侧），查验员乙在右三分之一（东侧）（台账记「建立」）
站位：@旅客甲（查验台沿 · 画面左 · 侧身45°朝右 · 双手按台）；@查验员乙（门框内侧 · 画面右 · 正面朝左 · 单手扶框）
位移：@旅客甲 案前→查验台西端半步（起身上前，终态面向乙）；@查验员乙 全员原位，无位移
```

**三层各管一件事，但不许把同一事实抄三遍。**轴线管空间几何，站位管本拍初始状态，位移只写发生变化的终态；时间轴 / 事件脚本不再复述整组站位，只写动作及其可见结果。多人冲突、打斗、遮挡等高漂移镜保留末尾锁行，普通镜不靠重复罗列换取稳定。

> **v4.7.5 起：站位挂死物不挂活人。** 上面的「查验台沿 / 门框内侧」是**固定锚物**，「距某人 N 步」只能作补充——人的位置会变，物的位置不会。轴线行除状态词外要写明挂在哪些锚物之间。完整规范与场景方位卡模板见 `场景方位卡与固定锚物.md`；机械门禁 `W-STAGING-RELATIVE` / `W-AXIS-NO-GEO`。

### 第 1 层 · 轴线行（liqi 的三态状态机）

**状态只认三个**：

| 状态 | 含义 |
|---|---|
| **建立** | 本场第一个双人镜，确立左右关系 |
| **保持** | 沿用上一镜，左右不变 |
| **跨越** | 要换边，**且必须写明用哪种过渡** |

**不写轴线 = 把左右交给模型随机决定，第一次反打就会崩。**

**v4.7.5 起：状态词之外还要写地理参照**——这条轴线挂在场景的哪两个固定锚物之间。只写「保持」，多镜同场时每镜各自解释保持什么，第 3 镜就开始漂；写上「柱—隔断墙连线」，跨镜对账才有据可依。左右按场景方位卡的屏幕方向映射写（画面左 = 西侧）。触发 `W-AXIS-NO-GEO`。

**合法越轴的四种手段**（「跨越」状态必须写明用哪一种；与 `轴线与反打规则.md` 第三节是同一套目录——该文件有逐种写法与注意事项，此处用别名标注）：

1. **镜头内过轴**（反打规则称「运动镜」）：摄像机在单个镜头内跟随角色走位连续旋转穿过轴线，跨轴过程被完整记录下来，不能切
2. **中立镜头过渡**（反打规则称「中性镜」）：中间插入正对轴线的中立镜头（Neutral Shot），画面里没有左右信息，之后可去任一侧；主体必须居中且无侧向参照
3. **插入特写**（中立镜头过渡的特写变体，反打规则同名）：插入与轴线无关的物件或局部特写（Cutaway），切断空间连续性；特写本身不能含左右信息
4. **重新建轴**：明确声明新轴。**最常见的中途变体是剧烈反弹 / 受击倒地**——角色受到重大物理打击翻滚位移后重建；换场景或换人物关系同理，不要沿用旧轴

### 相邻镜机位角差 ≤30°（v5.13.0）

**同段相邻两镜，机位相对轴线的夹角差不得超过 30°；超过就必须用上面四种过渡手段之一，
并在轴线行写明用的是哪一种。**

> ⚠️ **口径防混（本文件有两个 30°，不是一回事）**：
>
> | 说法 | 指什么 | 出处 |
> |---|---|---|
> | **30°~60° 斜角** | **单镜取景角**——中景全景必须用斜角，禁 90° 侧面正拍 | §三 机位编号 |
> | **相邻镜角差 ≤30°** | **机位之间的变化量**——跨镜别跳太狠 | 本小节 |
>
> 前者管「这一镜怎么摆」，后者管「下一镜能挪多少」。**一个合规的 45° 斜角镜，
> 下一镜跳到轴线另一侧 60°，单看都合规，连起来观众就找不到北了。**

**为什么是 30°**：相邻两镜角差在 30° 以内，观众能凭「同一个空间的两张照片」自动补全机位；
超过 30° 就开始像换了个地方，而 AI 视频没有真实拍摄的空间记忆，它不会替你补。
**跨轴（180°）是角差的极端值，所以一定需要过渡镜。**

**触发 `W-STAGING-CROSS-NO-TRANSITION`**：正文写了越轴 / 跨轴，却没写用哪种过渡。

### 第 2 层 · 站位行（四要素，写成生层）

每人一段括号，四项缺一不可：

| 要素 | 作用 | 例 |
|---|---|---|
| **固定锚物**（v4.7.5 起**放第一位**） | 空间锚点——**防「人悬空飘着」，也防基准随人漂** | 承重柱侧后 / 查验台沿 / 背靠断裂石柱 |
| **位置** | 画面左 / 右 / 中，或画面左三分之一 | 画面左三分之一 |
| **朝向** | 躯干朝向，与视线**分开写** | 侧身 45° 朝右 |
| **姿态** | 手在干什么、身体什么状态——**防「站桩对话」** | 双手按台 / 长枪斜扛 |

**锚物优先三级**（详见 `场景方位卡与固定锚物.md` 第五节）：① 固定锚物（柱/台/门/墙，默认）→ ② 物理接触（手搭/背贴/脚踩）→ ③ 人物间距（距 X 三步，**只作补充，不许单独用**）。

选锚物三条：不动（人与道具不算）、可见（在本场多数镜的取景半径内）、可跨镜复用（至少两镜出现）。

**为什么四要素比「谁在左谁在右」强**：liqi 只给左右，模型知道谁在左，但**不知道他靠着什么、身体朝哪、手在干什么**。结果是两个人笔直站着念台词。

> **v5.13.0 补充**：站位四要素里的「**距离**」现在有了量化口径——过肩镜必须给出退距数值，
> 见 §三；人物间距与表演强度档的联动见 `表演层_FACS微表情.md` §七 Proxemics 四档。

### 第 3 层 · 位移行

本镜要发生的移动**逐人写** `起点→终点`，**每步必须有动作原因**（攻击 / 闪避 / 击退），**禁瞬移**。

静态镜与对话段写 `全员原位，无位移` 即可。

**位移当前态锚点**：登记过位移的角色，在其后每一镜被点名时**必须带当前位锚点**——

```
@白珩（保持镜2进言位：帅案前半步·拱手而立·全程仅此一处）
```

**禁止悬空点名**。已位移角色只写名字不给当前位置，模型会把**起点实例和终点实例各渲染一次**（拉镜 / 全景把全场拉进画面时尤其高发）。位移行另需注明「**单实例迁移，旧位不得残留**」。

## 二、 空间风险分级 S0~S4（决定写到哪一层）

低等级不加载高等级规则——否则单人特写也会被要求写轴线位移链，纯属浪费预算，还会触发无用的校验警告。

| 级 | 场景 | 写到哪一层 |
|---|---|---|
| **S0** | 单人 | 简版站位一行（位置 + 朝向 + 动作），**免轴线、免位移链** |
| **S1** | 双人静态 | 站位行（四要素）+ 轴线行 |
| **S2** | 多人静态（3~4 人） | 站位行**全员具名**（每人四要素）+ 轴线行 |
| **S3** | 多人移动 | 在 S2 基础上加**逐人位移因果链** + **决策证据与被否决方案**（§十二） |
| **S4** | 复杂战斗 / 多空间切换 | 全量空间规则——CAM1~4 编号调度、合法越轴 + **决策证据与被否决方案**（§十二） |

**判定不清按高一级处理。**

> 这条补掉了 liqi 的一个边缘问题：原 `W-AXIS-MISSING` 对单人特写也会报「出场对象 ≥2 却未声明轴线」，实际上单人镜根本不需要轴线。接入分级后 S0 免检。

⚠️ **编号防混**：**S0~S4 是「空间风险分级」（写多细），不是场景类型。**
场景类型用 **V / W / X** 编号，见 §九。两套编号互不相干，别跨体系对数。

## 三、 机位编号 CAM1~CAM4（S4 用）

S4 复杂调度时给机位编号，方便资产图标注与分镜引用。

| 编号 | 任务 | 典型规格 |
|---|---|---|
| **CAM1** | 主建立镜头 / 空间全景 | 30°~60° 斜角俯拍或中远景，确立空间几何与角色左右朝向 |
| **CAM2** | 正拍 / 双人交锋中景 | 平视或微仰角，承载二人对抗与动作发起 |
| **CAM3** | 过肩反打 / 单人近景 | 主观视点过肩镜头，捕捉对手压迫感与生理反应。**机位须自对话轴线后退 1.5~2 米**（见下） |
| **CAM4** | 特写 / 顶视俯拍 / 动力学跟随 | 微表情特写、要害接触俯拍或大招运镜 |

**180° 轴线防护**：所有 CAM1~CAM3 必须严格布置在轴线的同一侧。

**禁止 90° 侧面正拍**：中景与全景必须使用斜角（30°~60°），保持透视进深感与空间立体度，**彻底杜绝街机横版感**。只有近景 / 特写允许 90° 侧拍。

### 过肩机位退距 1.5~2 米（v5.13.0）

**CAM3 过肩镜的机位必须自对话轴线后退 1.5~2 米**，并在提示词里写出这个距离。

**不写距离会发生什么**：模型默认把过肩镜拍成「贴背特写」——前景那颗后脑勺占掉画面三到四成，
主体被挤到边角，压迫感是有了，**但观众看不到主体的表情**。而过肩镜的用途恰恰是
「同时看到对手的压迫与主体的生理反应」，压太近就只剩前者。

**写法**（放进站位行或机位描述里）：

```
镜头：过肩反打，机位自对话轴线后退 1.8 米，前景@乙 后肩占画面右侧两成
```

**允许的单位**：米 / 厘米 / 步（须写明该角色一步约多少）。**「稍退后」「保持距离」这类弱指令不算写了距离**——模型没有米尺，只认数字。

**触发 `W-STAGING-OTS-DISTANCE`**：正文出现「过肩 / 过肩反打 / 过肩镜头」却没有任何距离数值。

## 四、 人员连续性（AI 视频特有，与空间连续性同等重要）

AI 模型每段独立生成、零记忆——**谁在本镜出现完全取决于本镜提示词写了谁**。有「空间连续性」还不够，必须补「人员连续性」。

### 在场声明

同场景多镜的每一镜，人物段必须**点名本镜全部在场角色**（动作主角 + 静止配角全列，写身份 + 位置 + 状态）。无「来人 / 离开」描述时，**默认全员原样在场**。

### 画内 / 画外清单

每镜时间轴行内：

- **入画者逐个具名**（含只听不说的听话者——他们物理上就在取景半径内，不写模型就会自行决定删或加）
- **画外者明写「×不入画」**
- 道具支撑视线动作时（如「视线落在军牌上」）必须锚定道具的入画方式（前景虚化等），并注明持有人不入画，**防凭空长出手**

### 主次同框四件套

第二人（含远景 / 背景人）必须 **具名 + 具象 + 定位 + 状态**：

```
@B（远景·灰袍老者·断桥尽头·背身而立）
```

**严禁「远处站着个人」这类弱指令**——被主体「看见」（视线 / 动作连接）的配角不会被省略；双主体关键镜首帧用同框图锁定。

### 同框动作分配三档（多人镜的默认档位）

多人同框时模型会把每个人的动作都当主动作，结果是一群人同时乱动、权重互相稀释。**按下表分档，一镜内只允许一个人走 ①**：

| 档 | 对象 | 写法 |
|---|---|---|
| ① 聚焦动作 | **一镜只给一个人** | 完整动作链（执行动词 + 幅度 + 接触关系） |
| ② 持续微动 | 其余在场者 | 呼吸起伏、手指轻动、衣料随气流微摆——**只写微动，不写新动作** |
| ③ 禁默认大动作 | 全体配角 | Must not 行显式写「@配角 静止，禁止起身/转身/抬手」 |

**依据**：Seedance 官方自认「极多主体交互的稳定性」仍是弱项（见 `视频人物工作流_行业对照.md` 第四节）。分档是行业实测下最省事也最有效的降风险手段。

> 注意：② 写「微动」而不是「不动」——完全静止会被模型判为道具，反而让它去补动作。

### 人员承接链

跨镜显式声明延续，如 `承接上镜：@B 仍在门口`。

## 五、 取景半径铁律（分身 / 乱位的真正根因）

**镜头能框住谁，由「景别 × 站位物理距离」共同决定，不由台词需要决定。**

- **可见动作必须在取景半径内**：点名做可见表情 / 动作（侧目、点头、回望）的角色，必须处在该镜景别能框住的物理距离内。
  - 中近景 ≈ 单人
  - 中景 ≈ 相邻 2~3 人
  - 全景 ≈ 同屋全员

站位隔着沙盘 / 半个厅的角色与持镜主体不在一个取景半径里，却在提示词里被要求做可见反应——**模型无法让画外人物入画，只能把人物位移到主体身边渲染或复制分身**。

**三种合法处理**（按戏优先选）：

1. **升景别改全景**，全场同框做反应
2. **拆反应镜**——主体镜（中近景，画内仅主体，明确写「其余角色不入画」）+ 反应镜（全景，众人各归其位做反应）
3. **降级为画外音 / 声音反应**，不入画

**禁止**：中近 / 中景里点名远处角色做可见动作。
**「缓慢拉镜拉出全员」不算合法处理**——拉镜只是景别渐变，**改不了物理距离**，模型照样补人。

## 六、 单实例铁律（防分身）

**每个点名角色在画面中全程只有一个身体。**

凡【强制禁止项】必须含：

```
单人单实例——每个点名角色全程只有一个身体，禁止同角色分身、复制人、同框重影
```

**人数锁定（仅 X 人）只防「多出陌生人」，防不了「点名人自己变两个」——两条都要写。**

## 七、 跨段关系：默认蒙太奇直切

段与段是 **各自独立生成的剪辑关系，不是连续拍摄关系**。

跨段位置 / 场景不一致时，**默认用蒙太奇直切**（前段终态 → 后段开场，剪辑点自然衔接），接续状态只需标明「跨段蒙太奇衔接」与两端画面。

**严禁为凑连续性把两个场景塞进同一个生成单元**去表现「连续走位」——双场景穿梭是穿帮高发源，蒙太奇才是零成本转场。

**判定口诀**：**跨段切、同段连**。跨段蒙太奇，同段内才讲连续性。

### 跨段锚点钩子

蒙太奇直切省了走位，但**前段尾帧必须为后段核心登场元素埋钩子**——后段要登场的人物 / 物 / 景，在前段尾拍以**远景剪影、视线指向、声音预告**等方式提前入画。

同时，前段【禁止项】的人数锁定**必须为该钩子元素开单例豁免**（写明唯一豁免条件：何时 / 何处 / 剪影级 / 静止 / 仅一人）。**豁免要收窄到不会引发人数失控。**

## 八、 绝对视角基准

**所有「画面左/右」严格指观众看画面的左/右**，不是角色的左右。

**空间锚点固定**：每个场景先出一张**场景方位卡**（罗盘方位 + 固定锚物清单 + 屏幕方向映射 + 禁变约定），全场景共用；镜内所有左右按卡写。详见 `场景方位卡与固定锚物.md`。

**移动轨迹闭环**：角色移动必须具备 `起点 → 可见运动路径 → 终点`。上一镜在左侧的角色，下一镜严禁瞬间移动到右侧。

## 九、 场型分型 V1~V4 / W1~W2 / X（v5.13.0）

**场型 = 这个空间本身长什么样**，决定景别上限与运镜禁令。
与 §二 的 S0~S4（写多细）是两套独立编号，**先看场型定上限，再看风险分级定细度**。

> ⚠️ **为什么不用 S1~S4**：上游用 S1~S4 表示场景空间类型，**liqi 的 S0~S4 早已被「空间风险分级」
> 占用**。照抄会造成同一串字符在本文件里指两种东西——这正是 liqi 全库最忌的那类编号冲突。
> 故改用 **V（室内 Volume）/ W（室外 Wide）/ X（特殊）**。

### 室内 V

| 型 | 空间特征 | 景别上限 | 运镜禁令 |
|---|---|---|---|
| **V1 窄室** | 单人尺度，如轿内、牢房、壁橱、船舱 | 中近景（胸部以上）为主，全景几乎不成立 | 禁环绕、禁长距离推轨；**可用手持轻微晃** |
| **V2 厅堂** | 3~8 人尺度，如正厅、书房、审讯室 | 中景到全景 | 禁大俯（会拍出天花板空面）；环绕半径受限，须贴墙走 |
| **V3 纵深** | 强纵深，如走廊、甬道、楼梯、巷道 | 全景可用，但**主体须在中景段** | 禁横向摇（会扫到两侧墙）；**推轨是主场** |
| **V4 开阔** | 大跨度，如大殿、市集、演武场 | 全景与大远景 | 无特殊禁令；**注意取景半径铁律**（§五）与人数锁定 |

### 室外 W

| 型 | 空间特征 | 景别上限 | 运镜禁令 |
|---|---|---|---|
| **W1 开阔** | 无遮挡远景，如原野、草原、湖面、战场 | 大远景 | 禁室内型手持晃；**风与光的方向必须全片一致** |
| **W2 街巷** | 两侧有边界，如街道、胡同、桥面、城墙 | 全景为主，大远景会拍穿布景 | 禁大仰（露出天空空白）；横向摇可，纵向摇受限 |

### 特殊 X

**非 Euclidean 空间**：梦境、幻境、水面下、失重、镜面空间、时间静止的白室。

- **不套用 V / W 的任何一条禁令**——但必须**显式写出本场自己的两条空间规则**（什么方向是"上"、什么算"远"）
- 🔴 **X 型必须声明**：不声明会被当成 V2 处理，而 X 型最典型的崩法就是模型偷偷按普通房间拍
- 写法：`场型：X（水下）· 上 = 水面方向 · 远 = 光线衰减程度，不用物理距离`

**场型写在哪**：场景方位卡的「场型」行（`场景方位卡与固定锚物.md`），全场景共用一张、中途不改。

## 十、 权力几何五维 + 节拍五段闭环（v5.13.0）

### 10.1 权力几何五维

**调度不是让人站好看，是让人站出关系。** 五个维度，每次调度至少动其中一维：

| 维 | 问什么 | 例 |
|---|---|---|
| **高低** | 谁在物理上更高 | 站着 vs 坐着 / 台阶上下 / 一方俯身 |
| **前后** | 谁更靠近镜头（谁占画面更大） | 前景压迫 vs 后景退让 |
| **远近** | 两人实际间距 | 从 3 米逼近到 0.8 米 |
| **左右** | 谁在画面优势侧 | 按方位卡；**轴线跨越才换** |
| **视线** | 谁看谁、谁回避 | 直视 / 垂眼 / 越过对方头顶 |

🔴 **场末必须 ≠ 场初**：一场戏结束时，五维中**至少一维要发生变化**。
没有变化的场＝两个人站着把话说完了，观众读到的是「什么都没发生」。

**过场（跨段蒙太奇）必须显式声明重置**：段与段之间五维重置了哪几维要写明，
否则下一段的「场末」无从比较（§七 的蒙太奇直切不豁免这条——它免的是走位，不免关系变化）。

### 10.2 节拍五段闭环

一场戏的调度按五段走，**缺第五段是 liqi 之前漏的**：

```
① 起势 → ② 路径 → ③ 接触 / 阻挡 → ④ 落点 → ⑤ 接收者反应
```

| 段 | 演什么 | 常见漏法 |
|---|---|---|
| ① 起势 | 动作从哪来（呼吸、重心、眼神先动） | 直接开打 / 直接走，没有预备 |
| ② 路径 | 走什么路线，**路径上有什么** | 瞬移（§一 位移行的老问题） |
| ③ 接触 / 阻挡 | 碰到什么、被什么拦住 | 隔空发生，双方没有物理接触 |
| ④ 落点 | 停在哪个位置、什么姿态 | 动完就切，没有终态 |
| ⑤ **接收者反应** | **被施加动作的那个人怎么回** | 🔴 **最高频的漏项**——打完了不给对手反应，观众不知道打没打中 |

**为什么第五段最贵**：AI 视频没有「剪辑节奏」的概念，你不写反应，它就切走。
结果是一串动作没有因果——**观众看到的是"他们动了一通"，不是"他打中了他"**。

## 十一、 同段相邻镜：动作重合 60~80%（v5.13.0）

**同段内相邻两镜如果表现同一个连续动作，两镜的动作必须保留 60~80% 的重合。**

| 区间 | 后果 |
|---|---|
| **< 60%** | 动作断掉——观众读到的是两个不相干的动作被拼在一起（AI 视频最常见的"跳帧感"） |
| **60~80%** | ✅ 正常剪辑的重叠区 |
| **> 80%** | 重复——同一个动作被演了两遍，观感是卡顿 / 模型没听懂要切 |

**写法**：后一镜的起手必须**接上前一镜的尾段**，写清"接着上一镜的哪个瞬间"：

```
镜 3（承接镜 2 挥刀至肩的过程）：刀锋自肩位继续下劈——重合段为挥刀中段
```

**与 §七 的关系**：**跨段不要求重合**（蒙太奇直切，两段本就是剪辑关系）；
**同段内才要求重合**，这与「跨段切、同段连」是同一条口径的延伸。

## 十二、 决策证据与被否决方案（v5.13.0 · S3 / S4 必写）

**S3 / S4 级调度必须留两行**：

```
决策证据：为什么这么摆——（例：乙背光而立，使其面部不可读，压迫感来自轮廓而非表情）
被否决方案：考虑过但不用——（例：对坐平视，否决原因：两人等高，读不出审讯关系）
```

**为什么要有这两行**：

1. **可复核**——改稿时能判断「这么改会不会破坏原来的意图」，而不是凭感觉重摆；
2. **防倒退**——liqi 的返修常常是「换个摆法试试」，没有记录就会在两三种摆法之间来回横跳
   （v5.6.4 全库矛盾排查里最费时的就是这类「改了又改回去」）；
3. **下游有用**——连续性台账的「场景账」需要知道"这个空间为什么是这样"，
   否则打戏之后陈设状态变了没人知道是有意还是穿帮。

🔴 **只查「写没写」，不查「写得好不好」**（触发 `W-STAGING-NO-EVIDENCE`，WARN）。
S0~S2 不需要写——低风险调度写这两行是浪费预算。

## 十三、 段末接戏全景（按需触发 · 实际尾帧硬绑定 · 非一致性保证）

> 🔴 **v6.4.0 废止（2026-10-29 ·《无人出席的圆桌》实测撤销）**：「末拍前补 1 秒接戏全景」的强制设定不再执行——量产实测效果不佳（挤占节奏与时长预算、对跨段一致性的实际贡献低于预期；机检催报 197 次无一被采纳，对应机检码同批移除）。跨段衔接由既有机制承担：**【跨段继承】声明＋实际尾帧验收＋`first_frame` 硬绑定＋锁行复述（C13）**。若某段确需手动补一个全景出口拍，下文写法判据（缓拉承前式 / 景别按跨度选 / 施工行注记）仍可参照——**以下原文留档**。

### 13.1 它的性质与边界

| 问题 | 答案 |
|---|---|
| **什么时候生成？** | 仅当**下一段需要继承本段人物 / 道具 / 场景空间状态**，且现有末拍不能提供合格尾帧时；片终、空镜过渡、换场硬切不强制 |
| **要不要进成片？** | 专用于接戏的出口拍不进成片，剪辑时剪掉；如果它本身承担叙事，则按正常镜头决定去留 |
| **它能保证什么？** | 只提供一张可检查的实际尾帧。**不保证**下一段站位、构图或身份一致 |
| **怎样才算接上？** | 尾帧验收通过 → 下一段把该图上传角色设为 `first_frame` → 首拍先保持 → 复核实际首帧 |
| **算不算时长与字数额度？** | 算。占本段 1 秒与正文字数，不为没有后续继承需求的段落白付成本 |

> 🔴 **文字里的“首帧参考”不是硬绑定。**Seedance 2.5 必须在界面 / API 设置上传角色；只写正文，结果只能“像该帧”，不能承诺逐像素或站位一致。

### 13.2 治什么病

liqi 原本只要求「每组至少 1 个大景别」（构成要求 C1），**没规定放在哪**，实战全景全堆段首（CAM1）。
而 AI 视频**每段独立生成、零记忆**——下一段拿不到上一段末的方位，只能靠文字重述，
**重述就会漂，漂了没人知道**（见 `连续性台账.md` 〇节）。

段末接戏全景把本段末态**真的渲出来**成一张全景帧（**只占 1 秒**），但“渲出来”只是第一步：

```
本段末拍 → 实际尾帧验收 → 下一段以 first_frame 硬绑定 → 首拍保持 → 实际首帧复核
```

**CAM1 是计划入口，实际尾帧才是跨段继承的事实源。**计划站位与实际渲染冲突时，以实际尾帧为准；尾帧不合格就重出或改出口机位，不得把计划帧冒充实际帧。

### 13.3 规格

| 项 | 要求 |
|---|---|
| **位置** | 本段**最后一个时间轴拍**，占 **1 秒**（拍长 3s 下限对它豁免，见构成要求 C2 附） |
| **景别** | 档 1~3，**按跨度选**（v5.15.7）：**3 人及以上 / 跨 3 个锚物 → 远景**；**2 人相邻 → 全景**；大空间一览 → 大远景。⚠️ 判据是「**框不框得下**」不是审美——**全景画高＝一人身高，16:9 下画宽只有约 3.1 米**；殿里三人跨「门槛边 ↔ 香炉边 ↔ 供桌」是 6 米量级，**全景一定有人被切出画**。反向也不行：2 人挨着的段用远景，两人缩成一小簇，「挨多近」的读数被拉小，且持物左右手只剩几像素 |
| **运镜** | **首选「缓拉」（承前式，v5.15.1）**：镜头自**上一拍机位**往后拉，站位 / 朝向 / 持物**承前不变**。<br>🔴 **拉程护栏（v5.15.7）**：**末拍景别到接戏全景的档差 ≥6 时，明写「快速后拉」**——大特写→全景是 6 档、→远景 7 档，1 秒拉 6~7 档模型多半**停在半路**，出口帧落到「既无表演细节、又无站位」的中间态，两头的价值一起丢。<br>**备选「固定机位」**：需要换角度看清全部人时退回。<br>⚠️ 别写「不推不摇」——**「摇」会被判成第二个运镜原语群，触发 `E-MULTI-CAMERA`** |
| **必须可见** | ① 每人的**画面左右**；② **朝向**；③ **持物左右手**；④ 与**固定锚物**的相对位置 |
| **必须标注** | **写进施工行**（`Must not` 之后，**不在正文内**）：「本镜末拍为段末接戏全景（1 秒），剪辑时剪掉，仅作下一段首帧与站位参考」。不写，剪辑的人不知道要剪 |
| **不可见** | 不要求表情与动作——那不是这一拍的活 |

#### 13.3.1 承前式拉镜头（首选 · v5.15.1 用户提议）

**用户原话：「全景能不能做成一个拉镜头，直接保留前面的站位，不重新设计」。能，而且这是首选。**

**为什么拉比「重切一个全景」好：**

| | 重切一个全景（原写法） | **承前式拉镜头（现首选）** |
|---|---|---|
| 站位 | **重新设计一次**，还要把画面左右 / 朝向 / 持物 / 与锚物关系**再罗列一遍** | **承前不变**，正文一句「一概承前」就够 |
| 字数 | 一截（四个人就要写四遍） | 极少 |
| 给模型的机会 | 一次**重新构图**的机会 —— 会漂 | 构图从上一拍直接放出去，**没有重构图的口子** |
| 段内关系 | 硬切到新镜 | 同一个镜内的连续运动，不切 |

**写法**（末拍 + 施工行）：

```
【时间轴】29-30s：全景，缓拉。段末接戏全景：自上一拍机位后拉，柳七、祝翁
站位承前；拉到位全员入画
｜镜头：全景 缓拉｜音效：环境底噪延续

（以下在 Must not 之后，不进正文）
施工：硬切 → 段 N …；本镜末拍为段末接戏全景（1 秒），剪辑时剪掉，仅作下一段首帧与站位参考
```
实测 **73~101 字**（逐人罗列 + 把注记写进正文的老写法 130~200 字）——承前式与「注记出正文」两件事
一起把字数额度省了出来。

> 🔴 **正文只放投喂内容，制作注记一律进施工行。**
> 「剪辑时剪掉…」「不重新设计…」「【接戏全景豁免】…」这类话**机器用不上、模型读不懂**，
> 写在正文里只有两个后果：**白占 800 字额度 + 让模型分心**。

🔴 **同段承前、跨段写实**：同一次生成内，出口拍只写「站位 / 朝向 / 持物一概承前」，让模型只负责拉远；
**下一段是独立生成，禁止只写“站位承前”**，必须按实际尾帧和固定锚物重写可见起点。换机位继承的是世界站位与锚物关系，不要求画面左右不变；反打或跨轴后屏幕左右可合理改变。

**四条纪律：**

1. **1 秒是一记 reveal 拉，不是慢推轨**——写「缓拉」就够，不要写速度分档（「每秒 0.3 米」之类废字）。
2. **出口帧 = 实际拉到位且验收合格的那一帧**；验收后还需在下一段上传为 `first_frame`，不是正文自称首帧就生效。
3. **上一拍是缓推时，本拍缓拉 = 推–拉**，节奏上成立，不必刻意避开。
4. **只有需要「换个角度看全部人」时才退回固定机位全景**（比如上一拍是背面/过肩，拉出来仍是背面）。

**备选写法示例**（固定机位全景；仅当需要换角度看清全部人时用）：

```
【时间轴】29-30s：全景，固定机位。柳七跪在殿中偏左、面朝供桌，祝翁立在供桌右侧、
面朝左，右手食指仍按在铃身裂纹上｜镜头：全景 固定｜音效：环境底噪延续
施工：本拍为段末接戏全景（1 秒），剪辑时剪掉，仅作下一段首帧与站位参考
```

**下一段怎么接**（与 `Seedance2.5适配.md` 第二节第 4 条一致）：

1. **验收实际尾帧**：全员数量正确、位置可辨、朝向可辨、关键持物与固定锚物可见；拉不到位或人物漂移就不许用作接戏帧。
2. **硬绑定**：把该图在下一段界面 / API 的上传角色设为 `first_frame`，正文另写 `@图片N作为首帧。`；普通“参考”不算锁定。
3. **施工留痕**：下一段正文外写 `# 首帧来源：段N实际尾帧（验收通过）` 与 `# 首帧绑定：first_frame`。这两行供机检查生产链，不进投喂正文。
4. **首拍保持**：首拍先维持首帧人物姿态、锚物关系和机位，再进入新动作；不要在起点同时换机位、拉镜和多人位移。
5. **复核实际首帧**：对照世界站位与锚物关系，不机械要求换机位后的屏幕左右相同；不一致则先修链接，不继续往下生成。

#### 13.3.2 拉多远 × 拉到哪一档（v5.15.7 · 实测算出来的）

两件事都会翻车，各有各的判据。

**① 拉到哪一档 —— 看跨度（框不框得下）**

| 在场 | 跨度 | 选 |
|---|---|---|
| **3 人及以上 / 跨 3 个锚物** | 6 米量级 | **远景**（画宽约 6~7 米） |
| 2 人相邻 | 2~3 米 | **全景**（画宽约 3.1 米，够；且持物左右手读得出） |
| 大空间一览 | 10 米+ | 大远景 |

**② 拉多远 —— 看档差（拉不拉得完）**

「承前式缓拉」的起点是**上一拍机位**，所以拉多远由末拍景别决定：

| 末拍景别 | 拉到**全景** | 拉到**远景** | 处理 |
|---|---|---|---|
| 中景 | 2 档 | 3 档 | 缓拉 ✅ |
| 近景 | 4 档 | 5 档 | 缓拉（偏快，可接受） |
| **大特写** | **6 档** | **7 档** | **改明写「快速后拉」** |

> 🔴 **档差 ≥6 就是警报**：1 秒拉 6~7 档，模型常常停在半路——
> 出口帧既不是原来的大特写，也不是全景，**是一个既无表演细节也无站位的中间态**，两头的价值一起丢。
> **`W` 系列没有这道门（量不出「拉到位」），靠人判**：写完数一眼档差，≥6 就把「缓拉」改成「快速后拉」。

### 13.4 触发与豁免

#### 触发条件（按后续继承需求，不按人数或“每段”一刀切）

| | |
|---|---|
| ✅ **加** | 下一段需要继承本段空间状态，且本段实际末拍无法清楚呈现全员、朝向、持物和固定锚物时，补 **1 秒**接戏全景；多人净位移、多人冲突后接续是高优先级触发 |
| ❌ **不加** | 片终、换场硬切、空镜过渡、下一段明确重建空间，或现有末拍已经能作为合格出口帧时，不另加 |
| ⚠️ **长段例外** | >20s 长段仍需满足收束结构；这是停止语义，不等于所有长段都必须向后一段传站位 |

**自动豁免**：X 型无参照空间 / 连续长镜 / 片终 / 无后续空间继承需求。
**声明式豁免**：`【接戏全景豁免】：<理由>`——写进施工行，不进正文。豁免只免出口拍，不免台账出口末态与后续实际首帧核对。

**位移行怎么写（写法纪律 · v5.15.6 起不再作为触发判据）**

位移行按 `；` **逐人**解析——这个判定现在**只服务两件事**：① 台账「出口末态」行**只列有净位移的人**；② 保证「姿势变化不写成位移」。某人的条目判为「无位移」需满足其一：

| 判据 | 例 |
|---|---|
| 以 `(全员)原位` / `(全员)原地` 开头 | `@乙 原位，无位移` ｜ `@甲 原地，仅抬手点香` |
| 无 `→` 且含「原位 / 原地」 | `@乙 门外原位，无位移` |
| 位移链**首尾同一锚点**（走一圈回原点，净位移为零） | `@庚 香炉边→门槛边取灯→香炉边` |

> 🔴 **旧写法（≤ v5.14.1）是整行匹配**——只要一行里出现「无位移」二字，**整段就跳过不查**。
> 于是「甲挪了位置、乙站着没动」这种最常见的多人段**永远不查**，正是 liqi 最忌的**假绿**
> （「解析出 0 条也报 OK」）。**姿势变化不是位移**——想让一段不触发，就写
> `原地，弯腰捡铃后扶桌坐下`，别写成 `弯腰捡铃→扶桌坐下`（后者含 `→`，会被判成位移）。

> **写位移链的两条纪律**（v5.14.2，实盘踩过才补）：
> ① **链首与链尾都该是位置词**——`站立→跪下`（全是动作）、`小桌前→站起来→院门口→推门`
> （尾节点是动作）都会让「走一圈回原点」判不出来。动作写进拍内描述，位移链只留位置。
> ② **返回原地要写成同一个词**——起点 `供桌前`、终点写 `回供桌` 是**两个不同字符串**，
> 机器认不出是回原点；写 `回供桌前`。

#### 为什么是 1 秒，不是 1.5~2 秒（v5.15.0 · 用户定）

v5.14.0 我把规格定成 1.5~2 秒，理由「1 秒读不出谁在左谁在右」。**用户否掉了**，原话：
「最后一秒留一个一秒全景」「不能为了全景而把最好的一个镜变成全景」。**以用户口径为准，定为 1 秒。**

代价要说清：1 秒只是预算，**不保证模型一定拉到位**。这一帧必须经实际渲染验收；不合格就重出或改用固定机位出口帧。读不细的部分由下一段站位行补充，但站位行与实际尾帧冲突时必须先修尾帧或文字，不能靠“以谁为主”硬盖过去。
谁想再加长，先回答「凭什么让戏剧给站位让路」。

#### 那 1 秒从哪来（v5.15.4 立 · 这条比「豁免」重要）

**接戏全景那 1 秒，从中段或前段扣——绝不从戏剧高点的末拍扣。**

这是「不能为了全景而把最好的一个镜变成全景」的**正解**。v5.15.0~5.15.3 我走的是「豁免」路线
（末拍是高点就整段不加），结果是**观众看不到尾帧站位**；而正确的做法是**换一个来源**：

```
末拍是 8 秒大特写？ → 前段 0-11 / 中段 11-22 / 大特写 22-30
改成：                前段 0-10 / 中段 10-21 / 大特写 21-29 / 接戏全景 29-30
                      ↑ 1 秒从**前段**扣，大特写仍是满 8 秒
```

**选谁扣的一把尺**：先看哪一拍**台词密度最松**（`W-DIALOGUE-DENSITY` 的余量最大），
从那拍扣。扣完复核那句台词的字/秒有没有被推过 5.0——**扣 1 秒会让密度涨约 10%**。
别从台词最密的拍上扣，也别从高点扣。

#### 戏剧高点豁免（v5.15.0 新增 · v5.15.4 降为兜底）

**兜底用**：末拍是戏剧高点、且**前中段实在匀不出这 1 秒**（三拍都绷满）→ 才不加。
**优先用上面「那 1 秒从哪来」的换来源法**——它既保住高点，又保住尾帧站位。

典型：全片最重要的一句台词落在特写上（「……那谁来叫。」）、仪式动作的落点在大特写上
（把头发塞进裂纹、按住）。**这些段原本被砍掉 2 秒去腾全景——把最好的镜让给站位，不干。**

处理：末拍保持原样（该多长多长），**施工行**写
`【接戏全景豁免】：末拍为戏剧高点，景别有刻意性`（不进正文），台账照记出口末态。
下一段的站位本来就写在**它自己的站位行**里，不依赖这一帧。

### 13.5 与既有机制的接口

| 机制 | 分工 |
|---|---|
| **CAM1 主建立镜头** | 段首的空间参考。**接戏全景是它的对位物（出口）**。⚠️ 站位行才是主，这两帧是辅 |
| **跨段锚点钩子**（§七） | 尾帧为下段**新元素**埋伏笔。**钩子可以长在接戏全景这一拍里**——同一拍，前半秒是本段末态，后半秒可带钩子，不要拆成两拍 |
| **首帧 / 尾帧参考图**（`Seedance2.5适配.md` 第二节第 4 条） | **接戏全景渲出来的那一帧，就是下一段的 `first_frame`** |
| **构成要求 C1** | **接戏全景天然满足 C1**——它本就是本组的大景别，不用另凑一个 |
| **时间轴账「出口」** | 接戏全景渲出的那一帧**就是**出口末态实物——**它是台账要核对的实物，不是台账的抄本**。台账「变更」行加一条 `出口末态（见接戏全景）：@甲 <位移链>；…`，**只列本段有净位移的人**（与包内位移行同源，不另立文字）；没有净位移就不加这条 |

> 🔴 **不要机械地每段都加。** 没有后续继承需求时还加全景，成片即使剪掉，
> 生成成本、字数预算、核对成本都翻倍。**有位移的多人段才加。**

## 十五、 机检六码（空间三码 + 首帧生产链三码；v6.4.0 起接戏出口一码随机制废止移除）

| 码 | 判据 | 级别 |
|---|---|---|
| `W-STAGING-OTS-DISTANCE` | 正文出现「过肩 / 过肩反打 / 过肩镜头」但该镜无任何距离数值 | WARN |
| `W-STAGING-CROSS-NO-TRANSITION` | 正文出现「越轴 / 跨轴 / 过轴线」却没写用哪种过渡（四种手段任一） | WARN |
| `W-STAGING-NO-EVIDENCE` | 声明了 S3 / S4 分级却无「决策证据」行 | WARN |
| `W-FIRST-FRAME-NOT-BOUND` | 正文声明首帧，参数区无 `# 首帧绑定：first_frame` | WARN |
| `W-FIRST-FRAME-UNVERIFIED` | 跨段首帧无 `# 首帧来源：段N实际尾帧（验收通过）` | WARN |
| `W-FIRST-FRAME-NO-HOLD` | 跨段首帧未写首拍保持 | WARN |

> 首帧三码只核对施工留痕与文本声明，**不能证明 API 已实际设置或图像内容真的合格**；未触发不等于像素级通过。

🔴 **三条全是 WARN**——几何是护栏不是铁律。与分镜配额同一取舍
（v5.7.0 里 11 项配额只有三项是 ERROR，其余 WARN）。

**未触发 = 本镜不适用，不算通过**：三码都只在触发词（过肩 / 越轴 / S3·S4 声明）出现时才判断。
没出现过肩镜的段落不会收到 OTS 警告，**这不代表它的过肩镜合格了**——它根本没有过肩镜。
与 `--combat auto`（文戏包不出现打戏段，不是通过，是本门不适用）同一口径。

**为什么不做成 ERROR**：群戏、打戏、多空间切换里，几何越界常常是**有意为之**
（比如刻意贴背拍压迫感）。做成 ERROR 会逼出「为过门而改摆法」的假合规。

## 十七、 开场站位四规（v5.36.0 新增 · 吸收 shuohao novel-staging）

> 来源：`eternityspring/shuohao-skills`（★4714，Apache-2.0）`skills/novel-staging/references/staging-pass.md`。
> liqi 第一节已有站位四要素与锚物优先三级，本节补它没有的四条——每条都带具体事故依据，不是通用建议。

### 14.1 给镜头留路

排位时同时看**摄影机要什么**，不只人物关系：

1. **对话最多的两个人之间不要隔第三个人**——否则正反打时第三人入画，轴线白设计；
2. **不要把所有重要的人排在同一侧背对入口**——入场的人没有反应可拍，背对入口的一方整场没有正面镜头；
3. 主角与站在他那边的人**在同一侧**；对立的两方**隔着桌子相对**或一坐一站——权力关系要一眼读懂（与第十节权力几何五维同向，本条是它的排位落地）。

### 14.2 群演默认 0

**剧本没写还有别人，就是没有别人，其余座位空着。**

理由不是省事，是模型行为：视频模型会把多出来的空位**画成一个个有脸的人**。剧本写了「满座宾客」「旁观的人群」，才给群演人数和位置。

与既有纪律的分工：Step 3 的「人物须列全本镜所有出场对象」管**写了的必须列**；本条管**没写的不许加**——两头都要守。

### 14.3 同侧多人要拉开（along 坐标 · v5.37.0 升级为可断言字段）

同一侧多人时，站位行里为每个人写 **`along` 坐标**——沿该锚物的归一化位置（0 = 该侧起点，1 = 该侧终点）：

```
站位：@甲（查验台沿 · 画面左三分之一 · along 0.25 · 侧身45°朝右 · 右手提箱）；
      @乙（查验台沿 · 画面左三分之一 · along 0.62 · 正面朝右 · 徒手）
```

三条纪律：

1. **同侧任意两人的 along 差值 ≥ 0.12**（机检 `W-STAGING-ALONG-TOO-CLOSE` 兜底）；
2. **只在同侧多人时写**——单侧一人、或两侧各一人，不必写（写了反而占字数）；
3. along 描述的是**沿锚物的相对位置**，不是屏幕横向像素；锚物换了，along 跟着重算。

理由：两个人贴在同一个点上，模型会把他们**合成一个人**（或一个双头身影）。这是「分身」的另一种成因——不是生成两个一样的，是该两个的挤成一个。文字写「拉开一些」模型没有可执行的量，给坐标才有。

围桌而坐的人落在**桌子那一件的哪一侧**（「坐在长餐桌东侧」），不要落在「椅子上」——椅子在画面里不一定存在，桌子一定在。

### 14.4 开场不在的人要标出来

分清谁开场就在、谁是后来才进来的。**剧本没写某人进场，当他开场就在。**

与既有纪律的分工：Step 3 的「画内/画外清单」管**本镜**谁入画；本条管**本场第一镜**——开场不在的人若被写进第一镜站位行，模型会让他在第一镜就出现。
