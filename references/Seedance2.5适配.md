# Seedance 2.5 适配规范（liqi 格式 × sd25-pe 对接）

本文件规定本 skill 的终稿格式（卡通轨见 `终稿格式示例.md`，写实轨见 `写实向终稿示例.md`）投放到 **Seedance 2.5**（火山方舟 Ark / 即梦 2.5 / 豆包视频生成，
底层模型 Seedance 2.5）时的改写规则。依据 sd25-pe（Seedance 2.5 官方提示词优化器）的不可违反原则
与模板体系整理。

**总原则：liqi 的增值层全部保留（风格锚、预算体系、可见性限定式、四层混音、连续性台账、转场注记、
参数行、滑窗拆分），只改与 2.5 冲突的部分——符号系统、素材引用、任务路由、能力边界。**

## 〇、投放面判定与轨道对照

| 投放面 | 代表平台 | 骨架 | 符号 |
|---|---|---|---|
| Seedance 2.5 面 | 火山方舟 Ark（doubao-seedance 2.5）、即梦 2.5、豆包 | liqi 镜块骨架 + 【时间轴】保留；任务级段落用【生成目标】【事件脚本】等 | 台词 {} 音乐 () 音效 <> |

2.5 面继续分卡通轨 / 写实轨，规则与 Step 0 ① 完全一致，不因模型升级混轨。
2.5 支持最长 30 秒单条；20—30 秒按 Step 1 的长段声明、节拍密度、收束结构三条件放行，不再一律强制滑窗；超过 30 秒才必须拆分。

## 一、符号系统对齐（硬变更，五条）

sd25-pe 的符号表是模型官方设计，2.5 面逐镜正文必须按此替换：

| 内容 | liqi 旧写法 | 2.5 写法 | 示例 |
|---|---|---|---|
| 台词 | 「原文」 | {原文} | 查验员乙开口对白（平稳专业）：{请配合前往人身查验室。} |
| 音乐 | 混在音效行 | (描述) | (背景播放舒缓的钢琴乐) |
| 音效 | 混在音效行 | <描述> | <远处传来钟声> |
| 字幕 | 文字铁律禁 AI 生成 | 【字幕内容】（仍只用于"后期合成"声明场景） | 画面不显示字幕 |
| 结构标签 | 【时间轴】等 | 【时间轴】【生成目标】【事件脚本】等照常使用 | 与 sd25-pe 官方模板一致 |

**台词语言前缀**：2.5 要求 `语言 + 可选口音 + 说话人 + {台词}`。liqi 的语气/语速括注保留，
写在说话人后：`查验员乙（平稳专业，使用普通话）：{请配合前往人身查验室。}`。
台词有外语时必须显式写"使用英语"等，不得省略语言声明。

**注意**：使用 <> 标记音效后，本镜主体名称不得再含尖括号（避免同符号双职责）。
「」在 2.5 面只用于资产锚注记（`锚「主要角色」图`），且这类注记必须移到 # 参数行，不进正文。

**台词三写铁律不变**：同一句台词在【时间轴】对应段、镜行尾行内 `台词：`、声音设计「对白」行**各出现一次，三处逐字一致**，
只是「」换成 {}。check_prompt.mjs 已兼容两种符号。

## 二、素材引用与逐份职责（2.5 核心机制）

2.5 以 @图片N / @视频N / @音频N 引用素材。liqi 的 I2V 参考图五分工（身份/首帧/环境/风格/材质）
**逐条翻译**为 2.5 的逐份职责句式：

```text
【参考素材职责】
@图片1用于旅客甲的五官、闪电形灰色高光短发与深灰西装，不采用图片背景。
@图片2用于海关查验台的空间布局、灯带与浅蓝白色调，不采用图中人物。
@视频1用于三段快切的切换节奏，不采用视频中的人物身份与场景。
```

规则（与 sd25-pe 一致，均为硬约束）：

1. **一行一职责**：一行只定义一个主体 + 一份素材。禁止"人物A和人物B参考@图片1、@图片2"这类范围句。
   （多张图指向**同一个**主体的例外写法见第 9 条多视角素材。）
2. **不采用声明**：每份素材写清"不采用 Y"，阻断身份/服装/场景污染（等价于 liqi 五分工的"仅用于 X，不继承 Y"）。
3. **【未采用素材】**：已上传但本镜不用的素材，在职责段后集中列出：
   `@图片5、@音频2未参与本任务，不用于人物、场景、道具、动作、镜头或声音。`
4. **首帧句式**：用参考图锁首帧时，必须单独成句 `@图片1作为首帧。`，再补一句该帧定义的构图、
   主体位置与镜头方向。禁止弱化为"以参考图X为首帧参考"。尾帧同理。首尾帧画幅必须一致。
   **官方锁定机制（2.5，v5.0.1 补）**：仅靠正文写「@图片1作为首帧。」并不锁定——模型只把它当参考，
   结果会像该帧但不匹配。必须在生成界面 / API 把该图的上传角色设为 first_frame / last_frame，
   Ark 才会把输出画幅锁到该帧。**文字句式与上传角色是两件事，缺一不可**；角色漏设时参数行照常
   声明画幅，但首帧对齐不保证——交付说明里要提醒用户上传时设角色。
5. **素材上限**：图片 ≤30、视频 ≤10（总时长 ≤30s）、音频 ≤10、合计 ≤50。超限先砍素材再写 Prompt。

   **推荐区间（稳定档，v5.4.0 补）**：上限是「不超过就会报错」，推荐区间是「在这个范围里出片最稳」——
   **两个口径不同，不要按上限塞满**。官方给的稳定区间：

   | 维度 | 稳定区间 | 说明 |
   |---|---|---|
   | 主体数 | 1–5 | 超过 5 个主体，官方自认稳定性下降（与资产层第一节「角色分档软阈值 >5 提示拆分」是同一个数） |
   | 图片 | 1–8 | 上限 30，但 8 张以上注意力开始分散 |
   | 音频 / 视频 | 单条 5–10s | 上限各 10 条、视频总长 ≤30s |
   | 宫格图 | <15 面板 | 见第 9 条宫格故事板 |
   | 编辑片段 | <20s | 超 20s 的编辑拆成多段 |
   | **素材总量** | **4–5 份** | 官方推荐值。liqi 的判据：够用就停，不要为了「信息给全」堆素材 |

   冲突时的取舍：**先减素材，再减描述**。素材过多造成的串味，靠改措辞救不回来。

6. **白模参考**（v2.0 补）：`@白模N` 用于锁空间结构、运镜轨迹、机位路径与光照方向，
   职责声明格式与图片一致，且**必须写明不采用白模的材质与配色**——
   否则白模的灰白会被当成最终画面色调继承下来。
   例：`@白模1用于查验台的空间布局与镜头绕行轨迹，不采用白模的材质与灰白配色。`

7. **区域编辑**（v2.0 补）：框选局部区域改写时，必须给出范围闭环句，
   声明范围外的一切保持原样。
   例：`只修改画面右侧的标示牌区域。除该区域外，人物、动作、光照、镜头运动与声音全部保持原样。`

8. **纯音频驱动**（v2.0 补）：仅用音频驱动镜头节奏与口型时，
   画面描述要**留白给节奏**——不要写满动作，只写主体、景别与情绪方向，
   具体动作时点交给音频。写满会导致画面动作与音频抢拍。

9. **多视角素材：同一物体多张图必须声明「成片中只有一个」**（v5.4.0 补，官方 2.5 指引）：
   用多张图定义同一个物体（不同角度 / 不同部位 / 不同参考职责）时，模型默认会把它们当成
   **多个不同的东西**——人物会分裂成好几个人，道具会多出好几个。
   必须显式写「成片中只有一个 X」，把多张图压回同一个对象。

   **这条对 liqi 是高频场景**：4 View 资产板投喂时正是 `face_hd` + `front` / `side` / `back`
   四张裁片定义同一个人（见 `4View资产板_模板.md`）。典型翻车是人物在画面里变成三四个。

   写法（声明句跟在最后一份素材之后）：

   ```text
   【参考素材职责】
   @图片1用于旅客甲的五官、闪电形灰色高光短发与肤色，不采用图片背景。
   @图片2用于旅客甲的深灰西装正面廓形与配色，不采用图片中的头部与背景。
   @图片3用于旅客甲的侧身厚度与西装侧面结构，不采用图片中的头部与背景。
   以上四份素材描述的是同一个人物，成片中只有一个旅客甲，不出现第二个人物，
   不出现该人物的重复身影、分裂身影或镜像身影。
   ```

   三条判定口径：

   - **必须写**：多张图指向同一人物 / 同一道具 / 同一场景的不同角度或不同部位时。
   - **不用写**：多张图分别指向**不同**对象（人物甲 + 人物乙 + 场景）——那时靠第 1 条一行一职责就够了。
   - **写完还要自检**：数一遍画面里该对象应该有几个。官方对「同一主体始终保持为同一个连续对象，
     不重复、不分裂」有明确要求（延长模板里也写了同一句），多视角时这句是硬约束不是修饰。

## 三、任务路由（2.5 特有，先路由后写镜）

2.5 区分三类主任务，liqi 镜块投 2.5 前必须先判定路由，一条 Prompt 只承担一个主任务：

| 任务 | 判定条件 | liqi 对应写法 |
|---|---|---|
| 视频生成 | 从文字+参考生成新画面 | 默认。走第四节单镜模板 |
| 关键帧生成 | 有首帧/尾帧图 | 【参考素材职责】里写 `@图片N作为首帧。`/`@图片N作为尾帧。`，事件脚本写首帧到尾帧的连续过程 |
| 视频编辑 | 以一条原视频为唯一母版改局部 | 见第五节 |
| 视频延长 | 在原视频前/后接新片段 | 见第五节 |

**画幅/时长闸门**：目标画幅或时长与参考视频不一致时，**不是视频编辑**，按普通生成处理，
参考视频只承担内容/动作/运镜参考，并在【生成目标】后加一句 `请注意这不是视频编辑。`

## 四、2.5 面单镜模板（liqi 镜块 × sd25-pe 结构）

liqi 镜块的小节顺序保留，素材职责段按 2.5 要求插入。单镜模板如下（可直接替换原 Step 3 结构投 2.5）：

```text
镜 8｜欲逃被控（10s）
场景：查验台旁（浅蓝白）｜人物：旅客甲、查验员乙、值守员
出场人物：旅客甲——深灰西装，黑色短发带闪电形灰色高光；查验员乙——寸头，深蓝制服，肩章铜扣

【生成目标】
生成查验大厅内查验员乙察觉异常并控制旅客甲的三段快切卡通动画。

【参考素材职责】
@图片1用于旅客甲的五官、闪电形灰色高光短发和深灰西装，不采用图片背景。
@图片2用于查验员乙的寸头、深蓝制服与沉稳神情，不采用图片背景。
@图片3用于海关查验台的空间布局、白色灯带与浅蓝白色调，不采用图中人物。

【未采用素材】
@图片4未参与本任务，不用于人物、场景、道具、动作、镜头或声音。

【主体与关系】
旅客甲始终穿@图片1定义的深灰西装。查验员乙位于查验台内侧，旅客甲在台外侧，两人隔台相望。
值守员身形敦实，深蓝制服，仅在第三段入画。

【事件脚本】
【时间轴】0-2s：特写，固定机位。X光机屏幕占满画面，高亮浅绿纯色块，内部空白供后期合成。
背景虚成浅蓝白色块。声音：大厅人声嗡鸣底噪。
【时间轴】2-6s：特写，固定机位随视线轻微横移。查验员乙眯眼，目光扫向画外旅客甲，落在其僵硬步伐
与微隆腰腹上。查验员乙（内心独白，画外音）：{箱子没问题，动作不太对劲。} 声音：心跳微起、衣料摩擦。台词：查验员乙（内心独白，画外音）：{箱子没问题，动作不太对劲。}
【时间轴】6-10s：中景，固定机位。值守员从右侧入画按住旅客甲双肩，旅客甲挣动两下停住。
查验员乙起身走近。声音：<金属扣件碰撞>，关员低声指令。

声音设计（四层混音）：
环境层：查验大厅远距离人声嗡鸣（持续，极弱）
动作层：衣料摩擦、金属扣件碰撞、脚步两声
呼吸层：查验员乙一次缓慢吸气（2-6s 段）
逼近层：心跳由微弱渐强（2-6s 段）
对白：2-6s 查验员乙（内心独白，画外音）：{箱子没问题，动作不太对劲。}

刚性约束：
必锁：平涂色块、粗黑轮廓线、硬边单色阴影，画面保持干净色块（锚「终稿格式示例」卡通轨）
可见性：值守员仅第三段入画，上半身与手部；X光屏仅色块无内容

Must not：可读文字、字幕、水印、logo

—— 以下不进正文 ——
# duration: 10s | # ratio: 16:9 | # 输出规格: 1080p/30fps（示例值，以 API 实际为准）
# 首帧来源：段7实际尾帧（验收通过；无跨段继承时删除本行）
# 首帧绑定：first_frame（须与界面 / API 实际上传角色一致）
```

要点：

1. **出场人物行负责身份短锚，【主体与关系】只负责交互关系与初始空间状态**，不再重复抄整套外观。
   E-IDENTITY-NOT-INLINE 仍逐一点名核对；有干净首帧图时只写简称与变化点，无图时才补颜色 + 轮廓识别。
   【事件脚本】只写动作变化和可见终态，不整组复抄初始站位。
2. **【时间轴】段头保留**：用户明确写的数字时间段属于创作内容，2.5 允许保留；
   时间轴连续性校验照常生效。无明确时间轴需求的长镜可改用【阶段一】【阶段二】组织
   （sd25-pe 阶段化写法），每阶段一个主动作 + 结束状态。
3. **保真预算 / 光色基调 / 色彩预算** 小节照常保留（本文示例从略，格式同 Step 3），
   作为画面描述写进正文——2.5 不禁止这些正向锁定。
4. **Must not 保留 ≤1 行**，置于正文末（2.5 无独立 negative_prompt 字段时附于正文末一行）。
   通用负向约束不滥加（sd25-pe 原则 8）：只保留平台期望类别 + 本片轨道必需项。
5. **参数行照旧**：画幅、时长、分辨率、帧率不进正文。2.5 的生成参数由页面/API 设置。

## 五、编辑与延长（2.5 特有任务的 liqi 写法）

**视频编辑**（liqi 镜块改写既有视频时）：

```text
【编辑目标】
编辑@视频1，只把<原对象>修改为<目标内容>。
【原视频职责】
@视频1是唯一编辑母版，负责原始场景、机位、镜头运动、动作轨迹与事件顺序。
【编辑对象与范围】
只修改<明确对象>。全片目标对象数量为N。
除以上明确修改对象外，@视频1中其他可见人物、道具和背景元素保持原样，不参与替换或删除。
【时间线继承】
<目标对象>继承<原对象>每次出现、运动与遮挡的时点与路径。
```

范围闭环句必须保留其一（局部修改兜底 / 只保留目标对象删除其余）。声音编辑同理：
只改指定声音，画面、口型时点、剪辑节奏全部保持。

**视频延长**（滑窗拆分后的窗间衔接，替代 liqi 的"上一窗末帧作下一窗首帧参考"文字写法）：

```text
@视频1是需要向后延长的原视频。
向后延长@视频1。延长片段的第一个画面直接承接@视频1的尾帧：保持主体姿态与朝向、
道具位置、机位与构图、光线和声音状态连续。
随后，<新动作与事件>。
延长过程中保持人物身份与服装、关键道具、背景布局和摄影轴线连续。
同一主体始终保持为同一个连续对象，不重复、不分裂。
```

向前延长把衔接写成"延长片段最后一个画面自然衔接@视频1的首帧"。方向不明时先问，
不要猜（sd25-pe 将方向列为高影响信息）。

### 编辑与延长的 API 参数（v5.4.0 补）

正文句式解决"模型怎么理解"，**参数解决"API 怎么执行"**——两件事缺一不可。
（同理第二节第 4 项的首帧：正文写 `@图片1作为首帧。` 只是参考，真正锁定要靠把该图的
上传角色设为 `first_frame` / `last_frame`。）

| 场景 | 参数 | 取值 | 为什么 |
|---|---|---|---|
| **视频编辑** | 画幅 | `adaptive` | 编辑是"改局部不是重拍"，画幅必须跟随母版。**显式写死 16:9 会让 API 重新采样，母版构图对不上** |
| **视频编辑** | 时长 | `-1` | 同上：沿用母版时长。写具体秒数会触发裁剪或重采样 |
| 首尾帧生成 | 上传角色 | `first_frame` / `last_frame` | 见第二节第 4 项。角色漏设时参数行照常声明画幅，但首帧对齐不保证 |

**liqi 落地写法**：编辑与延长任务的参数行按上面取值写，并在交付说明里提醒用户——
界面/API 上传素材时把首帧图的角色设成 `first_frame`；只写正文句式不设角色，出来的画面
"像那一帧但不匹配"。

⚠️ 这组值是 **2.5 编辑线专属**，不要套到普通生成：普通生成的画幅走三锁锁②、
时长走 Step 1 的预算，两者不是同一套参数。

## 六、能力边界（2.5 面 + liqi 铁律合并）

1. **可读文字**：精确字幕、公式、标牌、产品参数无法仅靠 Prompt 保证——与 liqi 文字铁律一致，
   一律"后期合成"。无字幕需求时显式写"画面不显示字幕"。
2. **帧级时间点**：【时间轴】数字是事件预算，不是帧级剪辑点，不承诺精确到 0.5 秒。
3. **抽象卖点**：高效、智能、可靠等改写为"初始状态 → 具体操作 → 可观察结果"三段
   （sd25-pe 产品流程规则，与 liqi 可执行动词原则同源）。
4. **情绪与运镜**：情绪 = 方向 + 触发事件 + 可观察表现；小众摄影术语保留术语名 + 展开为可观察结果。
   每段一个主运镜原语群的规则不变。
5. **称谓保真**：用户写"人物/主体"就保持中性称谓，不从素材外观反推身份、年龄、关系（事实与观察分离）。
