## 一、 依赖分级（先分级，再决定要不要建资产链）

不分级会让单镜小活被整套资产流程拖死。

| 级别 | 条件 | 资产动作 |
|---|---|---|
| **A0** | 纯文字 / 单镜 / 无一致性要求 | 不强制资产链，文字描述可直投，禁用 `@锚点` 即不受门禁约束 |
| **A1** | 单角色单镜 | 资产可选（有参考图更稳）。出 4 View 板即可，不补任何额外卡 |
| **A2** | 跨镜角色 / 场景一致性 | 启用相关角色与场景资产出图，角色走完整 4 View 板 |
| **A3** | 多人 / 多场景 / 连续剧集 / 高一致性 | 完整执行本层（默认档）：4 View 板 + 按需补卡 + 注册表全量维护 |

**判定不清按高一级处理**（宁全勿缺）。

**角色分档软阈值**（参考 shuohao 质量门与 2.5 官方口径，两个独立来源同数）：单包出场角色超过 **5 个**时，提示拆分或明确风险——官方 1-5 主体最可靠、超过稳定性下降；shuohao 的门限同值（主角组 1-5 / 重要配角 ≤10 / 功能性 ≤10）。阈值是提示不是拦截，多人场景按第七节注册表与 5.3 身份判定逐个数，不凑数。

> 两边的分级原意不同：liqi 默认所有角色都出三张卡——对 A0/A1 是纯浪费；分级是为解决这个浪费补进来的。
> 本层现在**版式只有一种（4 View）**，分级只决定「要不要建资产链、要不要按需补卡」，不再决定用哪套版式。

## 二、 角色资产板：统一的 4 View 版式

**本 skill 只用一种角色资产版式——4 View 资产板。**不分 A 级、不分题材、不设第二套。

### 出图顺序（图生图链，前一张没锁定不进下一张）

```
4 View 角色资产板（文生图，全链唯一身份锚）
  ↓
专属道具表（独立文生图）
  ↓
人物使用道具图（图生图，参考 4 View 裁片 + 道具表）
```

**前一张没锁定（脸稳、色准）不进下一张。**

### 4 View 资产板的构成

| 区 | 内容 | 作用 |
|---|---|---|
| **左区** | Face Close-up 头部近景 / 面部特写 | **身份锚**——五官骨相、眉眼间距、瞳孔色泽、皮肤肌理 |
| **右区** | 保头无脸 Front View 正面全身 | 服装正面廓形、配色、结构、头身比 |
| **右区** | 保头无脸 Side View 90° 侧面全身 | 侧身厚度、服装侧面结构（**纯侧，面部无五官**） |
| **右区** | 保头无脸 Rear View 背面全身 | 背面结构、后颈发际线以下的发尾走向、衣背纹样 |
| **附** | 全身比例尺（身高如 180cm / 168cm、头身比按目标观感档位选（见 `扩展面板与比例色彩速查.md` §四 头身档位速查；非写实风格另见 SKILL.md 头身比表）） | 跨镜身形一致 |
| **附** | **图底音纹条**（声纹波形图形 + ≤8 词英文音色速览标签，通宽、不计入格数，v5.10.0） | 跨图匹配同一角色的视觉标记 + 音色交接，见下节 |
| **附** | HEX 三色（Primary / Secondary / Accent） | 跨批次色偏的唯一锚 |

> 🔴 **v5.10.0 版式变更**：原「**附：细节材质三联**」（布料微距肌理 / 发型流向与碎发高光 /
> 纽扣袖口配饰）**已整体取消**，改为**细节归并**写进服饰段、配饰与鞋履行、面部特写格——
> 理由是**鞋只存在于特写格 → 主图上没有鞋**（上游实测），且 4 格 + 3 细节面板 = **7 个**，
> 超过第十二节的「单张独立面板 ≤4 个」铁律。详见 `4View资产板_模板.md` 第一节。

### 音色交接文本与图底音纹条（v5.10.0 · 吸收漫剧老李「图底横向细节条」）

**图底音纹条只装两样东西**：① **声纹波形图形**（纯图形，不占「入图文字」名额）；
② **音色速览标签**（≤8 词英文，全卡唯一允许出现的英文）。**通宽、不计入格数、不占主视图区。**

#### 术语正名（先立这条）

| 术语 | 指什么 | 性质 |
|---|---|---|
| **声纹 voiceprint** | 「这个人是谁」的生物特征 | **本 skill 不做**。图底波形只是**抽象图形**，**绝不宣称能锁声线** |
| **音色 timbre** | 「听起来什么样」——音高 / 质感 / 语速 / 情绪层次 | 图底那行英文交接的就是它，正式名 = **音色交接文本（Voice Description）** |
| ~~音色锁~~ | —— | **旧称，已废止**——它把「听起来什么样」说成了「是谁」 |

🔴 **声线锁定走音频侧（TTS 音色 ID / 参考音），不走资产图。** 波形条的作用是
**跨图匹配同一角色的视觉一致性锚 + 工作流标记**，不是声学凭证。

#### 三档交付（做了就三档齐）

| 档 | 内容 | 进图？ | 落到哪 |
|---|---|---|---|
| ① 完整音色交接文本 | 英文 2–4 句（音色特质 / 语速语调 / 情绪层次 / 适用场景） | **不进图** | **《素材接线单》**（§15.4）+ 提示词文档，供配音 / TTS / 下游读取 |
| ② 音色速览标签 | ≤8 个英文词（音高 / 质感 / 情绪核心词） | **进图** | 图底条右侧 |
| ③ 声纹波形图形 | 抽象波形 / 频谱图形 | **进图** | 图底条左侧 |

**① 为什么不进图**：生图模型渲染 100+ 字符长英文易**崩字 / 缺字 / 变形**；即便渲染出来，
也会被当**字幕 / 水印残留**处理（撞平台合规），还可能被嫌画面脏手动模糊掉 → 线索归零。
缩到 ≤8 词后崩字率大降，而**非文字的波形条抗模糊抗压缩**——两者互补，谁崩了另一个还在。

**与 M 轴的接点**：完整音色文本是**纯文本交付物**，所以它天然属于 **M0 / M1 形态**——
M0（纯提示词）下音色文本走提示词文档，**图底音纹条整条省略**；M1（编号占位）下写进
《素材接线单》（`素材形态` §15.4），与其他接线信息同处一份文件。**M0 不因省略音色而被判缺项**
——音色是**按需启用**的东西，不是契约硬产出（见下）。

#### liqi 的克制（三条，别自行加码）

1. **按需启用、不做机检**：只有需要配音 / 对白的项目才写音色交接文本；纯视觉项目在交付声明里
   写「音色：不启用」即可。**音色是语义项，做成门就是假绿门**（同 v5.8.0「完播自评只作自评」）。
2. **不进 16 项文字锁、不进 CT3 硬指纹**：16 项是**外观锁**（五官 10 + 服装 6），锁不住听感。
   `audit_contract.py` 的 CT3 指纹仍为「4 View + 五官 10 项 + 服装 6 项」，**不因音色改判**。
3. **一个角色一套**：同一角色的多套造型**共用同一条波形与同一条音色标签**，换装卡不重复渲染
   （音色跟随人，不跟随衣服）——口径同本文件第八节「换装走图生图编辑」。

### 🔴 右区「保头无脸」的措辞纪律（2026-09-16 补入，2026-10-15 修正口径）

**不要只写「无脸」。** 右区三格实测仍会画出清晰五官，三层原因叠加：

1. **「无脸」是否定式约束**，人物立绘的先验太强，模型多半照画一张完整脸。
   必须给**工程实现**——`featureless face, no facial features`
   （或柔和失焦式 `face softly out of focus`）。给模型一个**可执行的替代动作**，
   遵循度远高于只告诉它「不要」。
2. **提示词里带五官特征等于点名让它画**：瞳色、眼神、唇形、眉眼间距这些词一出现，
   右区就会多一张清晰脸。五官 10 项**只作用于左区**，抄进右区描述前必须先删干净。
3. **一次出三格注意力分散**，漏一格整板就废。

> ⚠️ **2026-10-15 口径修正**：本小节原写「**无头**」——要求右区三格「从颈根以下取景，
> 头部完全落在画框之外」。该写法**已废弃**，两个原因：
> ① 它与同一张卡的英文负向词（`head out of frame` / `cropped head`）**直接矛盾**，
> 模型收到相反指令只能自己选一个；
> ② **砍头会让模型失去画面里唯一的头身比参照**，头会忽大忽小、头身比走形。
> 该结论来自漫剧老李 V7.4.20 六轮粉丝实测迭代（2026-10-09 至 10-12）。
> 现行口径 = **保头去五官**：头部完整入画（头型、发型、颈部、肩线全保留），
> 只让面部区域不刻画五官。同时满足「不锁脸」与「头身比不失真」两个目标。
> 详细对照表、两种工程实现与「马赛克」转译纪律见 `4View资产板_模板.md` 第一节。

**右区取景强制串（逐字照抄，中英文都要）**

```
中文：右区三格头部完整入画，保留头型、发型、颈部与肩线，但面部一律不刻画五官，
以 featureless face 无五官平面处理；三格全身自头顶至鞋完整入画，不裁脚不裁头。
英文：The three right panels each keep the full head visible — head shape,
hairstyle, neck and shoulders all in frame — but with a featureless face and
no facial features; each panel shows the complete body from the top of the
head to the shoes.
```

Negative 追加：`sharp facial features on body views, detailed eyes on secondary views,
a second recognizable face, duplicate front view panel, extra fifth panel,
five-panel layout, mosaic censoring bar, pixelated face, text, letters, words,
caption, label, subtitle, watermark, chinese characters`。
⚠️ **不要写 severed / decapitation / blood**——那会激活切面与血肉语义，
撞本 skill 的血肉 / 切面类安全边界。

**图生图补板时尤其危险**：投喂的参考图（双视图）里本身有清晰脸 + 有头全身，
模型会直接把「清晰脸」抄进右区。走三步法：
① 先把参考图的**面部区域**处理成无五官平面，得到保头无脸的正面全身；
② 以它为参考**分格**出侧面与背面，每次只出一格；
③ 左区头部近景 + 右区三格 + 图底音纹条拼版，拼版用外部工具，不要让模型重画。

**仍画出清晰五官时的兜底**：右区改写成服装展示语义
「这套服装穿在人台上展示（garment on a mannequin）」。
人台无头，**只作兜底、不作默认版式**——无头正是头身比失真的来源。

💡 **为什么只用一卡**：4 View 板在同一张图上同时给出**身份锚 + 三个方向的身体参考**。原 liqi 三卡体系需要分别出「双视图人设卡 + 侧背补锚卡 + 九视图人设卡」三张，其中侧背补锚卡要做的事（侧面 / 背面头部）与九视图要做的事（表情 / 机位）**在短片工况下大部分用不上**——多出的两张卡是纯成本。

💡 **90° 侧面与镜头机位的取景禁令不冲突**：本表里的 90° 是**设定图的画法角度**（人物在纸面上被转过来），镜头侧禁的是**中景/全景镜头的机位角度**（防街机横板感，见 `空间层_调度与轴线.md`）。两回事，不要互相套用。

### 🔴 像素账（liqi 的实测结论，升级为独立铁律保留）

在 3840×2160 原生分辨率下实测：**4 View 板左区头部近景裁开后，脸约 1922 px；右区全身格裁开后，脸仅约 320 px。**

两者的差距是 6 倍。这直接定死了一件事：

> **全身图不能当身份锚。**把右区的全身格单独投喂，模型读不清五官，只能现编——脸必漂。

⚠️ **v5.10.0 起图底条预留会等比缩小全部裁片约 12%**（`slice_reference.py` 默认 `--band 0.12`）：
新裁切下 `face_hd` 约 **1710 px**、右区全身格的脸约 **285 px**。**两者仍差 6 倍，结论完全不变**——
`face_hd` 依旧远超 900 px 的「优秀」线，全身格依旧在 250~500 px 的「勉强 / 偏小」区间。
报数字时**要写清是哪一档口径**，别把 1922 与 1710 混着用（这正是本 skill 反复强调的「版本漂移」）。

由此定死投喂分工：

| 用途 | 用哪一区 | 理由 |
|---|---|---|
| **身份锚（正面五官）** | 左区头部近景 `face_hd` | 唯一像素足够的（约 1922 px；新裁切约 1710 px，见上方像素账） |
| **侧脸轮廓 / 后脑发型** | 右区 Side / Rear View | 正面脸给不了鼻梁、下颌线、耳朵、发髻结构 |
| 服装款式 / 配色 | 右区 Front View | 锁廓形与配色 |
| 机位 / 体型参考 | 右区全身三格 | **别指望它锁脸** |

### 按需补出的单卡（默认不出，共 2 类 + 兼容保留 2 张，合计 4 张）

4 View 板覆盖不了以下两件事，**只有剧本确实用得上时才补单卡**，不列入默认流程：

| 补卡 | 触发条件 | 说明 |
|---|---|---|
| **侧 / 背头部特写卡** | 片中有侧脸或背身**特写**（不是中远景） | 右区三联是**保头无脸**的，给不了侧面/背面头部的清晰五官。用图生图从 4 View 裁片出，要求「纯侧面 / 纯背面，不露出任何正面五官」 |
| **表情参考卡** | 剧本需要 ≥4 种差异较大的表情，且这些镜要走全量 FACS | 出**纯表情网格**（不要连全身三视图一起出）。注意 liqi 的像素账：表情格约 600 px，**够看表情怎么摆，不够锁五官**——它只当参考，不能当锚 |

⚠️ **触发条件的判据是上表两列，不是片长。**60 秒以上的短片与情绪重的角色通常会有 ≥4 种表情，
但片长只是经验提示——拿它当门槛会把短但情绪密集的片子漏掉。

另有两张**兼容保留**的旧版式卡，默认不出，只有用户明确要「一张图承载角色出厂基准」
（游戏人设卡风格 / 更干净的单角色图）时才考虑，模板与纪律见 `扩展面板与比例色彩速查.md`：

| 兼容保留卡 | 为什么默认不出 |
|---|---|
| **九视图人设卡**（左 2/3 全身三视图 + 右 1/3 六表情） | 全身三视图部分与 4 View 右区重复，表情部分精度不够锁五官，却要多占一张卡的生成成本与投喂位。**真需要表情参考就出纯表情网格，不要九视图。** |
| **双视图人设图**（左头近景 + 右全身正面） | 身份锚这个职责已由 4 View 板的左区头部近景承担；只有需要一张更「干净」的单角色图时才补。**注意它的右侧是带头全身，与 4 View 右区保头无脸三联是两套版式，不要照它的排版出 4 View 板。** |

### 🔴 三条投喂铁律

1. **任何镜头都要带一张 `face_hd`（左区头部近景）。** 全身图单独喂，脸一定漂——320 px 的脸模型仍读不清五官，只能现编。
2. **侧面和背面镜头必须额外带对应的高清头部图。** 4 View 右区三联是**保头无脸**的，只给正面清晰脸，模型不知道这人侧脸什么样、后脑勺什么样，转过去就换了张脸。**片中有侧/背特写就补侧背头部特写卡**（见上）。
3. **Hero Image 锁定，中途不换参考集。** 4 View 板裁完后选定一张最优图做全项目主参考。**中途更换参考集是重新引入漂移最快的路**——哪怕新参考「看起来更像」。要改，回板上改。

**分层投喂（省钱且防漂）**：

| 镜头类型 | 投喂方式 | 理由 |
|---|---|---|
| 特写 / 近景（脸是重点） | I2V + 参考图；**prompt 只写动作运镜，不重复描述长相** | 参考图已锁长相，重复描述反而干扰 |
| 远景 / 切出镜头（脸小） | **文生视频 + 提示词锚**，不投参考图 | 观众对小脸不敏感；服装+体型描述足够维持错觉 |
| 群戏 | 从已确立的角色图 I2V 出 | 多主体从文本直出是重灾区 |

**转身镜头技巧**：首帧给背身、尾帧给正脸，模型必须在两个锚之间保持同一个人——**用动作本身强制身份一致**，比「喂一张背面图求它别漂」稳得多。

**转头 60° 禁区**：跨模型实测的共同弱点——侧脸超过约 60°，五官就开始靠先验编。**分镜设计时侧脸镜头角度尽量 ≤60°；必须大转头的戏用转身首尾帧法拆解。**

## 三、 文字锁：16 项必写

**4 View 资产板上必须写满。**这 16 项是清单化后的最低要求——只写「严格沿用参考图片全部五官样貌」是笼统指令，不是清单。

> 📌 **16 项是「外观锁」（五官 10 + 服装 6），音色不在这 16 项里。**音色（听起来什么样）锁不住外观，
> 是另一条正交的交接链，见第二节「音色交接文本与图底音纹条」。**`audit_contract.py` 的 CT3 硬指纹
> 仍是「4 View + 五官 10 项 + 服装 6 项」，不因是否启用音色而改判。**
>
> 📌 **卡面文字纪律自 v5.10.0 起为「三处带字」**：身高线数值、色板色名、**图底音色速览标签（≤8 词英文）**。
> 声纹波形**属图案不算文字**。未启用音色时回到「两处带字」。**零引线、零标注线、零箭头**不变。

### 五官 10 项（杜绝脸部漂移）

1. **脸型骨相**（方圆脸 / 冷艳瓜子脸 / 重颌方脸）
2. **眉形细节**（平直剑眉 / 微挑柳叶眉 / 断眉）
3. **眼型与眼窝**（狭长丹凤眼 / 深邃眼窝杏眼）
4. **瞳色与反光**（深褐琉璃瞳 / 赤金锐利高光）
5. **鼻梁山根**（高挺直鼻 / 小巧微翘驼峰鼻）
6. **唇形与唇色**（薄唇微抿 / 朱红饱满唇峰）
7. **下颌线条与折角**（下颌线清晰锐利 / 方正刚硬）
8. **耳廓耳型**（贴脑耳 / 白净分明耳廓）
9. **标志性特征**（眼角泪痣 / 眉心浅疤 / 断鼻骨）
10. **面部肌肉与肤色**（冷白无暇 / 古铜粗糙 / 刀削般体块）

### 服装 6 项（杜绝塑料感）

1. **面料类别**（重磅斜纹棉麻 / 做旧哑光皮革 / 高密生丝）
2. **编织与表面纹理**（粗糙麻织肌理 / 皮革龟裂细纹）
3. **垂坠受力与硬挺度**（厚重硬挺垂坠 / 贴身流线）
4. **战损污损与做旧细节**（袖口磨损起毛 / 衣角泥水浸润 / 领口汗渍）
5. **金属与扣具光泽**（哑光拉丝古铜扣 / 冷银拉链反光）
6. **缝纫与剪裁工艺**（双排工整明线 / 暗青色提花刺绣）

### 🔴 性别锚点（必写）

**面部特写句必须以 `X~Y岁男性/女性（身份代称）` 收尾**（如 `24~26岁青年女性`、`55~60岁老年男性（老将）`）。

**为什么**：只写「老将 / 文士 / 武将」等身份代称，或只写年龄段，**模型会自行推断性别导致漂移**。所有下游投喂词（人物入场句）提及该角色时，性别指向必须与资产板一致——女文士不能写成「青衫文士」。

## 五、 出现记录与身份判定（资产清单的产出规程）

> 本节设计借鉴自三个开源项目，均已按许可处理并登记根目录 `THIRD-PARTY-NOTICES.md`：
> 出现记录与身份判定的两层分离借鉴 zenstory-ai/drama-skills 的 short-drama-assets（MIT）；
> 关键道具准入门与场景去重键的方法论借鉴 chatfire-AI/huobao-drama 的 extractor
> （CC BY-NC-SA——不收编其内容，判定逻辑以本条自己的话重写）；
> 角色分档阈值参考 whatyun/shuohao-skills 的质量门（MIT）。

### 5.1 出现不等于资产：先记录，后判定

剧本里提到一个名词不等于需要一个资产。跳过这层直接建卡有两个典型事故：
**同一人物的几套衣服被拆成两个角色**；**两个同称谓的人（都叫「值班员」）被误并成一人**。
规程：先记出现，再判身份。

逐段过剧本时，对每个制作相关对象记六个信息：

1. **谁或什么需要被看见、听见**——人物、群体、动物、地点或可操作道具。
2. **以什么方式出现**——见 5.2 四态。
3. **此刻能直接看到什么**——只摘录剧本已经给出的外观、状态、位置和动作后果，不发明脸型年龄配色。
4. **制作时必须实现什么**——服装、伤污、可读文字、内容物、功能状态、关键入口。
5. **它为什么重要**——识别、行动、信息揭示、关系与权力、交接、气氛或普通布景。
6. **它从哪里来、要去哪里**——进入状态、同场变化和结束状态；有变化只留指向连续性记录的位置，
   不在出现记录里另造第二份事实。

一个动作句常带出多种资产，但**不把细节各自建成资产**：「顾禾推开旧渡站值班室的北门，
把带裂口的白瓷号牌放进铁皮匣，匣盖内侧写着潮位 7」——记：顾禾出镜；值班室出现且北门可能是
固定空间锚点；号牌有裂口；铁皮匣被打开且匣盖内出现必须保留的文字。北门、裂口、潮位各自
不建条目。每条出现判断都要指向准确的场景 ID 并用动作、对白或必要短引文说明依据。

### 5.2 出现四态

| 态 | 定义 | 资产动作 |
|---|---|---|
| 出镜 | 本场画面中可见 | 正常进身份判定与出图链 |
| 画外音 | 只有声音 | 记人物或声音事实，本场不一定绑造型 |
| 影像出现 | 照片、屏幕或画像中出现 | 按剧情要求处理，不默认露脸；可能是同一人物的历史造型 |
| 只被提及 | 台词提到 | 只做故事追踪不建图；但若台词要求观众必须读到某份文件，建道具记录 |

环境中的普通桌椅标为布景（set_dressing）；只有承担动作、识别或连续性时才升级为道具。
四态与视听层的可见性预算同源——「只被提及」的对象写进可见性就是浪费预算。

### 5.3 身份判定：四选一，不许模糊

按顺序问三个问题：**去掉临时状态后，持续身份是否相同；下游是否需要区分一个可复用状态；
只写变化记录是否够用。** 结果只能是四类之一：

| 判定 | 含义 | 下游动作 |
|---|---|---|
| 复用 | 已有条目覆盖本次事实 | 沿用编号、身高、色值与互锁词 |
| 新变体 | 同一身份的可复用新状态 | 基础身份不变，只写差异 |
| 新资产 | 持续身份不同 | 新建条目 |
| 未决 | 证据不足 | 挂起：列候选、缺失证据与影响；**禁止带默认 ID 进 4 View 出图** |

「已处理」不是判定结果；未决项不许假装有 ID 流到下游——错误身份一旦被 4 View 固化成参考图，
返工是全线的。A0-A3 分级可以模糊升级（判定不清按高一级），**身份不许模糊**。

**判定结果必须落盘**（v5.6.8）：四桶里每一条都要写 `identity_verdict`，字段名与四值（`reuse` / `new_variant` /
`new_asset` / `unresolved`）一字不改——这是机器口径，`audit_project.py` 的 F4/F5 按它查。中文含义见上表，
落盘只写英文值。**`scenes` 也要填**：场景判错正是"同一地点被建成两个场景"的直接成因。
`damage_states` 里的态**不填**（它是状态容器，不是身份）。

判为 `unresolved` 的条目额外写 `identity_unresolved` 四键，且**不得写 `outputs`**（写了就出图了）：

```json
"identity_unresolved": {
  "candidates": ["与 S07 同人：雨衣颜色一致", "新人物：体型与步态不同"],
  "missing_evidence": ["S03—S06 无面部描写", "无动作可交叉指认"],
  "impact": "此时出图等于替剧本决定一张脸，S07 起全部返工",
  "unblock_when": "拿到 S07 的指认台词，或用户确认合并/分列"
}
```

`unblock_when` 是**解除条件**，不写这条，后面拿到证据的人不知道该补什么。字段规格与完整示例见 `资产注册表_asset-registry.md`。

⚠️ **门禁边界**：F4/F5/F6 只能证明「判了、值合法、未决没出图」，**判得对不对脚本查不出来**——
F 门通过 ≠ 身份判定正确。这条活路在 5.1—5.3，不在门里。

**易误判的四类**（判错代价最高，逐条对照）：

| 易误判 | 常见错判 | 正确口径 |
|---|---|---|
| 服装相同 = 同一人 | 「穿雨衣的人」→ 直接并入 S07 的角色 | 必须出示前后剧本证据，否则标 `unresolved` |
| 同一地点 = 一个场景 | 两个各有独立地理与入口的同址空间合成一张卡 | 5.5 去重键：同地点同时段一张；不同地理/入口建新卡 |
| 状态变化 = 新资产 | 受伤的角色建成第二个人物 | 去 5.3.1：先问"去掉临时状态后持续身份是否相同" |
| 群体 = 单个资产 | 「候车乘客」逐个建卡 | 无个体连续性作群组布景；接过关键道具的那个单独建 |

称谓存疑时的规矩：

- 原文写「她」但本段没有唯一先行人物：保留原称谓并标未决，列候选。
- 「穿雨衣的人」后来被叫出姓名：可以提出合并，但必须展示前后剧本证据，不因服装相同就认定同一人。
- 「另一把钥匙」：先建独立记录，不复用上一把。
- 同一人被职务、关系和名字交替称呼：别名经用户接受后才进人物资产。
- 群体称谓按制作用途处理：没有个体连续性的「候车乘客」作群组布景，后来接过关键道具的那个人单独建记录。

### 5.3.1 身份与状态对照表（什么变化建新版本，什么不建）

| 类别 | 建新变体 | 只写变化记录或不建 |
|---|---|---|
| 人物 | 服装、发型整理、妆容、伤势、污湿、年龄阶段、伪装 | 瞬时表情、姿势、视线、景别 |
| 地点 | 可复用观察视角、陈设阶段、时段、天气、光线状态、**结构性改造（墙破口、梁塌、窗碎、水线）** | 单一镜头角度、焦段、演员站位 |
| 道具 | 持有人、持有手、位置、开闭、破损、内容物、文字、启停的状态版本 | 被抬起的一瞬、画面左右位置 |

变化值不值得建版本看三条：**有明确原因和来源**（换装、受伤、停电、拆封、转交）；
**有清楚的生效范围**（从哪段生效、到何时失效）；**下游需要准确选择**
（角色带伤跨三场，造型版本值得建；指尖刚沾一滴水又擦掉，一条变化记录够）。

易误判情形：剧情双胞胎、复制体和冒名者是不同人物即使视觉识别点近似；易容或制服伪装是
造型版本，不把伪装身份写成真实人物身份；同址空间若各有可制作的地理和入口建两个地点再用
关系引用连接，同一值班室停电前后仍是同一地点不因光线变化新建；两件需要独立追踪的同款
物件建两个身份，十只没有连续性要求的白杯作一类布景；物件被不可逆改造成另一种功能
（号牌熔成钥匙）且之后按新物件使用，可提新资产并保留由原物改造而来的关系。

命名惯例：**版本后缀式**（角色名—状态名，如「苏某—火灾后」），下游一眼看出身份与当前版本；
命名分层——主角用实名，功能人物用姓氏加职务，只作背景的人物用类型加序号；
资产名与描述中的名字必须一致，不能写甲的名字却描述乙。

### 5.4 关键道具准入门（三问加数量上限）

道具是白底单品图加视频特写的高成本资产。准入门三问，**任一答是即不建表，降为文字描述**：

1. **删掉它，剧情是否依然成立？** 成立则它只是道具式背景板。
2. **它只是角色随手使用的日常物品吗**（通讯工具、餐具、杯盏、雨具）？ 是则归角色文字描述。
3. **它是场景陈设的一部分吗**（桌椅、灯具、门窗、挂画、餐具）？ 是则归场景描述。

数量上限建议：**单镜 0-1、单集 1-3、系列 ≤8**。没有符合条件的就留空，不强行提取——
上限口径与 shuohao 的质量门「叙事道具 ≤8」对齐。角色的常规穿戴归妆造，不建道具。

### 5.4b 软肋物（v5.20.0 · 与关键道具同权不同类）

**软肋物 = 挂在主要角色软肋上的物**（叙事层纪律「软肋锚点＝物」的资产侧落点）。判据与准入：

1. **准入同权**：过关键道具三问（删掉它剧情是否依然成立等）——软肋物删掉剧情必然受损，天然过关。
2. **分类不同类**：注册表 props 条目写 `"category": "softspot"`（关键道具写 `key`）。**分类写错会被关键道具的数量上限（≤8）误判**——软肋物按主要角色各 1 配置，12 角色戏轻易超 8；「≤8」上限按 `category: key` 口径理解，**软肋物不占该额度**（由 F8 三码保证分类写对，见 `audit_project.py`）。
3. **挂靠双向**：`characters.<slug>.softspot` 字段指向 props 桶条目；反向也查（标了 softspot 没人挂 = 孤物，多半分类手滑）。
4. **状态弧**：软肋物的破损/恶化（裂头盔的裂纹变大）走 `props.*.state_arc` 或场景 `damage_states`，**不新建卡**——它是同一物的状态推进，不是新资产。
5. **数量纪律**：主要角色（有名字且戏份 ≥2 场）各 ≤1；同帧软肋物 ≤1（多了等于没有软肋）。

### 5.5 场景去重键

注册表场景条目的去重口径：**同地点同时段复用同一张方位卡**（时段变化只改光照变体，
不建新卡）；**不同地理、不同入口或不同固定锚点才建新卡**。这与 huobao 按【地点+时间段】
精确匹配去重是哲学差异——它把同时段视为新场景，liqi 选更省资产的口径（时段归光照变体），
但共同点是**去重键显式化，不靠模型自觉**；zenstory 的判断步骤 D 与 liqi 同结论
（空间拥有不同地理、入口或固定锚点，即使同属一个建筑也建新地点）。

**🔴 三个层级别混（v5.6.2 明确）**——5.3.1 说地点可建新变体的项有五类，落地时按下面三条分开处置：

| 变化 | 归哪一层 | 处置 |
|---|---|---|
| **时段 / 天气 / 光线状态** | `scenes.<slug>.variants` | 只改光照字段，陈设与空间逐字复用。**不建新条目、不建新卡、不占新编号** |
| **陈设阶段**（桌椅挪位、拆封、布置改变） | 先判断动没动**固定锚物** | 没动锚物 → 仍是同一场景，写变化记录；**动了锚物 → 建新卡**（锚物是方位卡四要素之一，锚物变了方位卡就失效） |
| **不同地理 / 不同入口** | `scenes` 新条目 | 建新条目、新方位卡，新 `S` 编号 |

判据回到 `场景方位卡与固定锚物.md` 的锚物选品三条：**不动、可见、可跨镜复用**。锚物清单本身变了，方位卡必须重出；只是物件的临时位置变了，方位卡不动。

## 七、 注册表：跨批次一致性的唯一保障

会话记忆会丢，**注册表不会**。

### 定位顺序

1. 用户指定的资产目录
2. 项目根或 `characters/`、`assets/`、`设定/` 目录
3. 与输入参考图同目录

找不到就在对话中声明「未发现资产注册表，本次新建」并确定落盘位置。

### 动手前先扫已有资产

- 列一遍注册表中已存在的**角色 / 道具 / 场景**条目
- 场景条目按 5.5 的去重键核对：同地点同时段应是同一张方位卡（光照变体不计新卡），不同地理或入口或固定锚点才是新卡——键不一致就并卡或说明理由
- **复用既有条目编号、身高、色值与互锁词**；场景条目还要复用 `lighting_anchors`、`light_port`、`permanent_marks`
- **禁止为已注册资产另起一套数值**——这是跨批次穿帮的头号来源

### 主动检索参考图

不要假设用户会主动给图。主动扫项目内已有资产图（`characters/`、`assets/`、`storyboard/`、`*.png`），存在相关图就作为图生图参考并记入 `reference_files`。

### 回写

本轮产出的每个条目结束后必须写回注册表——编号、身高、色值 HEX、互锁词、参考图路径、`durable` 标志物清单。

**`durable` 不掺情绪**：里面只有**跨场次成立**的事实（长在身上的标志物、义肢、发簪、痣）。表情、姿态、伤口、湿衣、持物等**瞬时状态不许混进去**——它们会污染后续所有场次。

schema 见 `资产注册表_asset-registry.md`。

## 八、 版本拆分与互锁

**状态弧原则（v5.2.0 立 / v5.6.8 改）**：道具有状态弧，**场景也有**——
早期那句「道具有状态弧，场景没有」只对**时段**成立，**被误读成"场景任何变化都不拆卡"，
是 M1 那类"墙被撞穿不建变体、下一镜凭空复原"事故的直接来源**，v5.6.8 起作废，按下表判：

| 漂移类型 | 谁会漂 | 容器 | 判据 |
|---|---|---|---|
| 版本漂移 | 人物、道具、生物 | `versions`（A/B） | 换装、年龄阶段、伪装、形制改造 |
| **时间漂移** | 场景 | `scenes.*.variants`（时段名） | 时段 / 天气 / 光照变，**不新建场景条目**（老话只覆盖这一行） |
| **状态漂移（破损态）** | 场景、道具 | `scenes.*.damage_states`（态名） | 空间被**不可逆改造**（撞穿的墙、烧塌的梁、砸碎的窗、漫过的水线），且后续镜要承接 |

场景状态漂移的判据与道具同源：**该态是否跨镜复用、是否影响识别或交接**。
停尸房东墙被撞出一人宽破口、后面三镜还要从破口穿过去 → 必须建 `wall_breach` 态；
一块砖被蹭掉点灰、下一镜不再提 → 一条变化记录就够，不建态。

**每个态独立出图，双向加锁**：`intact` 禁"墙面破口 / 外翻碎块"，`wall_breach` 禁"完整墙面 / 复原如初"，
并写 `delta`（新增了什么）与 `invariant`（什么必须和 intact 一致：砖缝走向、台位、污渍），
否则破口态会被画成另一个房间。

其余不变：皮箱的合上与打开是两张参考图，卷帘门的降下与升起是两张。

**状态板原则（v5.2.0，借 zenstory）**：状态板只展示**已接受**的状态差异，不把前后对比
默认塞进一个画面——「湿袖」和「干袖」同框会让模型各给一半，要出就出两张。

任何资产需要多版本时，**每个版本独立出图**（硬规则：禁止合并进同一张设定图）。但**版本容器按资产类型分**，不要一律说「拆条目」：

| 资产 | 版本容器 | 何谓「独立」 |
|---|---|---|
| 角色 | `characters.<slug>.versions`（`A` / `B`） | 各自独立出图，共用同一 `slug` |
| 道具 | `props.<slug>.versions`（`A` / `B`），state_arc 记当前态 | 每个要跨镜复用的态各出一张（18A/18B） |
| 生物 | `creatures.<slug>.versions`（`A` / `B`） | 同角色 |
| 场景·时段 | `scenes.<slug>.variants`（时段名） | 每个时段各出一套图，**但不新建场景条目** |
| **场景·破损态** | `scenes.<slug>.damage_states`（态名，如 `intact` / `wall_breach`） | 每个态各出一套图，**也不新建场景条目**；需 `delta` + `invariant` + 双向 `lock_out` |

五者的互锁纪律相同（双向加锁 + 进 `lock_matrix`），只有容器与命名方式不同。`variants` 与 `damage_states`
是**并列**容器：一个场景可以同时有 3 个时段变体和 2 个破损态，出图时取「时段 × 破损态」的交集描述。
完整对照见 `版本拆分与互锁清单.md` 第一节。

| 版本触发条件 | 示例 | 处理 |
|---|---|---|
| 服装阶段切换 | 前期素白中衣 → 中秋后藕荷衣裙 | 拆 A/B 条目，各自独立出图 |
| 体态状态切换 | 正常版 → 瘦脱形版 | 拆两条目，正常版负面词禁瘦脱形 |
| 道具阶段切换 | 小衣完好态 → 烧焦态 | 拆两条目（18A/18B），各配互锁负面词 |
| **场景时间线切换** | 停尸房在正午 / 黄昏 / 深夜各一次 | **不拆条目**——走 `scenes.<slug>.variants.<时段>` 子键，各配光照互锁词 |
| **场景破损态切换** | 东墙完整 → 被撞出一人宽破口，后续三镜承接 | **也不拆条目**——走 `scenes.<slug>.damage_states.<态名>` 子键，配 `delta` / `invariant` + 双向互锁词 |
| 单一版本 | 全片一套服装的角色 | 一条目即可 |

### 🔴 版本互锁负面词（硬规则）

拆出的每个版本，**禁止内容里必须写入「禁用另一版本的特征」**（A 版禁藕荷色、B 版禁素白中衣、完好态禁焦黑、烧焦态禁恢复完好），防止生图工具混入其他版本特征。

**场景时段版本要从三个维度同时下刀**——色温、光质、影子形态。只禁一个维度挡不住串版（夜版要同时禁「日光」「天光」「均匀照明」）。

**且每个变体的 `lock_out` 要覆盖「其余所有变体」的标志性特征**（v5.6.3）——三变体的场景里，正午版要同时禁住黄昏与深夜的光。写得全不全直接决定 C2 门查不查得出来：`audit_project.py` 的 C2 门按「声明时段 × 该时段 lock_out」判定，`lock_out` 没写到的别版特征它就看不见。建议每版 ≥3 条。完整示例与两条硬要求见 `场景资产与时间线光照.md`「时段版本的互锁词」。

**先定 `baseline_time`（基准时段）再出变体**：基准版锁死空间结构、陈设布局、色板；其余时段变体**只改光照字段**，陈设与空间一律复用。否则同一场景的不同时段会被画成两个不同的地方。

### 换装走图生图编辑，不重出全卡

```
以这张图片为参考（角色全身正面站姿）。
保持人物面部五官、发型、头饰、姿势、构图与背景完全不变，
仅将服装{旧描述}替换为{新描述：颜色+材质+款式+结构}。
Negative Prompt: 面部改变，发型改变，姿势改变，背景改变，{旧服装特征}，{版本互锁词}。
```

**脸和发型被锁住** → 新卡天然继承锚定能力，不会出现「换了衣服换了个人」。

## 九、 光照锚点

**四值只从 `lighting_anchors` 取，禁止现场编**：色温、入射角、影子形态、人工光状态。

| 时段 | 色温 K | 入射角 | 影子 | 人工光 |
|---|---|---|---|---|
| 拂晓 | 6500–8000 | 无明确方向 | 几乎无、极柔 | 烛火将熄 |
| 晨 | 5000–5600 | 15–30° | 长、较清晰 | 灭 |
| 正午 | 5500–6500 | 60–90° | 最短、锐利 | 灭 |
| 午后 | 4500–5000 | 30–45° | 中长 | 灭 |
| 黄昏 | 2000–3500 | 5–15° | 极长、拉伸 | 将燃 |
| 入夜 | 2000–2700 | 点光源 | 短、围绕光源 | **点亮** |
| 深夜 | 7000–10000 | 单一 | 浓黑、对比极强 | 残烛 / 无 |

⚠️ **黄昏与入夜最容易混**：都是暖色，但黄昏是低角度日光（有明确方向、投长影），入夜是点光源（无方向性、光域小、衰减快）。**互锁词必须能区分这两者。**

**两条铁律**：

1. **同一场景 × 不同时间 → 必须可区分**：色温、光斑位置、影子长度、人工光、曝光，**五项至少变三项**
2. **不同场景 × 同一时间 → 必须一致**：色温、光位、光质、粒子、曝光，**五项全部对齐**

**进光口登记为固定项**（`light_port.fixed = true`）：进光口是建筑结构，跨时段不变——变的只是太阳角度决定光斑落在哪里、影子多长。这是「同一场景跨时间既有变化又可辨认」的几何基础。

## 十、 色值双轨

**中文色名 + HEX，缺 HEX 视为不合格。**

「藕荷色」「瓷白」这类中文色名在不同生图模型里解释漂移极大，是跨批次色偏的主因；HEX 给出确定锚点。

- 色值**只从注册表取**，已注册角色的色值禁止重新编造
- 4 View 板与所有下游卡共用同一套色板 HEX，**改色必须全卡同步**
- 生图模型对色板上的 HEX 字符渲染不稳时，允许弱化 HEX（保留中文色名），但**落盘 `.md` 里 HEX 必须完整保留**，作为人工校色依据
- 场景条目**不画色卡**，色值只落盘注册表与 `.md`

## 十一、 非写实风格适配（皮影 / 剪纸 / 水墨 / 版画）

本层模板默认**写实 PBR 3D**。遇到平面侧影风格时，六处必须改：

| 原模板 | 非写实适配 | 理由 |
|---|---|---|
| 三视图（正/侧/背） | **侧影 / 正面 / 关节分解** | 皮影角色本身就是侧影，正背视图无意义；关节分解才是工艺核心 |
| 写实 PBR 材质渲染 | **平面材质 + 透光**（牛皮雕刻 / 宣纸晕染 / 水墨渗化） | 光是背后透射，不是正面布光 |
| 严格正交相机 | **平面化构图，无透视** | 无纵深 |
| 头身比 7（写实档） | **按风格取区间（以 SKILL.md 为准）**：皮影 / 剪纸 **4–4.5**｜水墨 **5.5–6.5**｜年画 **5–5.5**｜国潮 **6–6.5** | 民间造型的夸张比例，写实档会失去味道 |
| 身高参照线 | **影人 / 画面实体尺寸线** | 皮影影人约 30–45cm，用工艺尺寸更有依据 |
| 场景三阶多视角图（2×2 四视角） | **全景 / 前景层 / 陈设特写 / 空镜无特效版** | 平面背景板没有仰视俯视；改出「分层」与「可合成的空镜」。（四阶「不同时段的多视角图」沿用这套替换，只改光照三段） |

**保留不动**：六层结构 → prompt 双输出、色板中文色名 + HEX、场景禁止出现人物、面板 ≤4、版本互锁、全部引线中文。

### 两条非写实专属纪律

1. **特效层是独立物理层，不是后期效果**。皮影的雾、光柱，剪纸的衬底，水墨的留白——都要在提示词里写成**独立的半透明皮料层 / 独立的宣纸层**，否则后期无法分层合成。
2. **暗部必须提亮一档**。写实里的暗部在平面化后会变成死黑一片，镂空花纹全丢。换算规律：**提亮一档 + 降饱和一档**，再把色值归到该风格的限定色板内。

## 十二、 面板密度与字数

- **面板密度预算**：单张设定图的独立面板（局部放大、独立道具、细节面板）**不超过 4 个**（超过 4 个先砍到 3 个，见「十三、生成后诊断」高频故障速查「面板被吞」行）。面板过多时生图模型会丢元素或互相污染，宁可拆成两张图。
  **4 View 板正好用满这 4 个名额**（左区头部近景 + 右区三格）——这也是 v5.10.0 必须取消右区下方三个细节材质特写面板的直接原因：4 + 3 = 7，超预算一倍。**图底音纹条不计入面板数**（它不承载主体内容，只是索引标记），故 4 View 板仍是 4 个面板。
- **正文字数按面板数分档**：面板 3–4（完整档）约 **650–900 字**；面板 ≤2（精简档）**200–320 字**。判据是**面板数**，不是字数。
  **启用图底音纹条时可放宽 120–180 字**（波形写法 1 段 + 标签 1 段），属额外的固定开销，不从正文其他段挤。
- **服饰 / 布料条目必须写出织法、厚度、缝线、袖口、褶皱、垂坠、光泽、做旧中的至少 4 项**，禁止只有「布料垂坠」一句带过。
  ⚠️ v5.10.0 取消细节面板后，**这两项要求更硬了**——原来「布料微距肌理」那张小图替你把材质画出来，现在只能靠这一行的文字锁扛住。

## 十三、 生成后诊断

### 每张卡必做的七项漂移检查

出图 ≠ 完成。拿到手先过一遍，**检查基准＝注册表 `durable` + 卡面提示词逐项比对**，不凭印象。

| # | 检查项 | 对照什么 |
|---|---|---|
| 1 | 脸：脸型 / 五官 / 年龄感与锚点卡一致 | 4 View 左区头部近景 vs 下游卡、左右脸互检 |
| 2 | 剪影：整体轮廓（发型外轮廓、身形）没变形 | 与 4 View 右区三联比对 |
| 3 | 服装：款式 / 结构 / 配色与卡面描述一致 | 提示词外貌段逐项 |
| 3b | **全身有没有完整到鞋** | 三格均头顶至鞋在画内，无裁脚无裁头（v5.10.0 取消细节格后，鞋只有全身格一个去处） |
| 4 | 色板：画面实际用色 vs 注册表 HEX | 抽 2–3 个主色目测 |
| 5 | 标志物：`durable` 清单里的东西都在且形制正确 | 提示词里写死的形制细节 |
| 6 | 风格：渲染方式 / 背景体系与全包统一 | 总起句背景 vs 实际背景 |
| 7 | **图底音纹条在不在**（启用音色时） | 波形是纯图形；音色标签**有没有崩字 / 缺字 / 变形**；词数 ≤8。**崩字了也不要重出整卡**——降级处置见下 |

**任何一项不过 → 先修，不要带着瑕疵进图生图链**（瑕疵会被下游全部继承）。

### 图底音纹条崩字时的降级处置（v5.10.0）

音色标签是全卡唯一要求渲染的英文，也正是最易崩的一处。**崩了不要重出整卡**：

| 症状 | 处置 |
|---|---|
| 标签缺字 / 变形 / 乱码 | **不要在图上手动补字**——补上去的字与模型渲染的字天生不同款，看起来就是水印残留。改用外部工具**把图底条整行裁掉，贴一行系统字体文本**；卡片本体不重出（重出会引入新的随机漂移，得不偿失） |
| 波形被画成带刻度 / 数字的图表 | 这是最需要避免的一种——**印上去的假数据比没有数据更危险**。重出时把「无坐标轴、无刻度、无数字、无图例」提到强调位；仍不行就改用最简写法「波形居中、两侧大片留白、整条素色」 |
| 图底条被模型吃掉（整条没画） | 先确认排版段有没有写「图底细节条约占 12%」——**漏写这一句是首因**。补写后再出；若平台一贯吃正面要求，改用外部工具后期加条 |
| 音色交接还没定，不想阻塞出图 | **先出图、后补条**：图底留空出图，音色文本定稿后用外部工具把条贴上去。**这不算降级**——完整文本本来就不进图，图底条只是索引标记 |

### 🔴 Fix at the sheet, not the shot

某个分镜里角色细节错了，**不要反复重抽那个镜头**——回设定卡定位错误面板，修正卡片，之后所有镜头继承修复，只重抽受影响的镜头。

反复重抽同一镜头会引入新的随机漂移，且每次重抽都在消耗「这张卡还是对的」的信心基准。

### 高频故障速查

| 症状 | 优先怀疑 | 修法 |
|---|---|---|
| 左右两张脸不一样 | 一致性约束太弱或太靠后 | 把「必须保障左右两侧角色长相特征完全一致」提到排版段末尾强调位；仍不行则拆成两张独立图各出一次，取各自最优再人工拼 |
| 一张图里两个人 / 人脸重影 | `@` 标签缺失，模型猜错了 | 补 `@ImageN is …` 用途声明 |
| 脸漂（每个镜头长得不一样） | 没带 `face_hd` | 加 4 View 左区头部近景图 |
| 侧脸轮廓不对 | 只有正面锚，侧脸靠脑补 | 补侧背头部特写卡的 `face_side` |
| 后脑发型不对 | 只有正面锚 | 补侧背头部特写卡的 `face_back`；或改用转身首尾帧法 |
| 该纯侧不纯（混进 3/4 侧脸） | 侧背头部特写卡没锁死角度 | 卡上补「纯侧面」「不露出任何正面五官」重出 |
| 服装款式对但布料像塑料 | 只有款式锚没有材质锚 | prompt 补面料词 ≥4 项；服装大特写镜头按需出服装局部特写 |
| 换装后「换了个人」 | 换装时整卡重出，脸跟着漂 | 别重出——用图生图换装编辑，面部发型姿势构图全部锁死只改衣 |
| 不同场景里衣服颜色跳 | 把光照偏色误当成服装问题 | 服装色锚 = 注册表 HEX；场景内偏色由光照锚点管，**禁止改服装卡** |
| 跨批次色偏 | 只有中文色名无 HEX | 补 HEX，并从注册表取色而非重编 |
| 动漫角色显得成人化 | 头身档位错（用了写实 7–7.5） | 按目标观感重选：日式 3D 动漫 6–6.5、日式 2D 5.5–6.5 |
| 面板被吞（少画了） | 密度超预算 | 拆成两张图，或砍到 ≤3 个面板（硬上限 4，砍的目标是 3） |
| **主图上没有鞋** | 脚部被细节格吃掉了 | **v5.10.0 已取消三类细节格**；鞋改由三个全身格承担——排版段必须写「全身自头顶至鞋完整入画…鞋型鞋面与鞋底完整可见」，见 `4View资产板_模板.md` 第一节 |
| **图底条被吃掉 / 音色标签崩字** | 排版段漏写图底条占比，或长英文超出渲染能力 | 排版段补「图底细节条约占 12%」；标签收到 ≤8 词；仍崩用外部工具裁掉整条重贴（**不在图上手补字**），见第十三节降级处置 |
| **波形被画成带刻度数字的图表** | 波形要求写得太像数据图 | 强调位补「无坐标轴、无刻度、无数字、无图例」；仍不行改「波形居中 + 两侧大片留白 + 整条素色」 |
| 混入另一版本特征 | 互锁词缺失或太弱 | 强化互锁负面词，并把另一版本特征写进禁止内容的**最前面** |
| 角色卡里冒出道具 | 缺道具分离约束 | 角色卡加「空手站立，不持任何道具」硬约束 + 负向词「角色手持或佩戴任何道具」 |
| 持物图道具形制漂移 | 双锚定失效 | 核心强制约束点名道具表条目并写「禁止重新设计道具」，道具表 HEX 直接列进提示词；负向词加「道具融进身体或衣料」 |
| 场景里冒出人 | 无角色约束不够靠前 | 把「出现任何角色或人物」提到禁止内容**第一项**，并追加「人物剪影、人影」 |
| 四面板环境不一致 | 缺环境同一性约束 | 加「四个面板展示完全相同的环境与陈设布局」 |
| 四面板视角雷同 | 角度描述太软 | 写死角度数值（「向上倾斜 60 度」而非「仰视」） |
| 分隔线变粗黑框 | 没写全限定词 | 加「内部边缘线，1pt，不要双重加粗，不要外框」 |
| 跨场景色温打架 | 没用光照锚点 | 全场景从 `lighting_anchors` 取值，禁止现场编 |
| 同一场景晨昏没差别 | 只改了色温 | 按五项（色温/光斑/影子/人工光/曝光）至少变三项 |
| 白天场景点了灯 | 没声明人工光状态 | 时间线锚点显式写「烛火熄灭」 |

**诊断后需要修订的，只改受影响字段，不要整条重写**（整条重写会引入新的漂移）。修订记录写入 `.md` 的「修订日志」小节。

## 十四、 双输出（硬规则）

每个资产条目都按 **(A) 结构层 → (B) 生成 prompt** 两段给。

- **A 结构层**用六层结构（环境气候 / 主体构成 / 外观造型 / 状态版本 / 质感细节 / 氛围终层）——给人看，用于定位迭代
- **B 生成 prompt** 是可直接复制的提示词正文

**迭代时先判断哪一层出问题，只改那一层再重压 B，禁止整条重写。**

**第 6 层氛围终层不能是前五层的复述**——把它删掉，如果画面描述完全不变，说明它是复述，重写。

## 十五、 素材形态 M0 / M1 / M2（v5.9.0 · 图在不在你手里）

### 15.1 缺口：本层长期隐含「图要在册」

本层前十四节的写法都预设了一件事：**参考图是存在的、有编号的、能被引用的**。
但 liqi 用户的真实工作流是：

```text
liqi 出提示词 → 用户自己拿去 Seedream 5.0 Pro / 即梦 / Seedance 跑图
             → 图留在用户平台侧 → liqi 只负责让提示词里的图号「对得上」
```

即 **图这个实体，从不进入 liqi 的上下文**。于是本层出现两条互相打架的隐含规则：
① 「角色资产板 / 场景母版要在册」（第十四节的出图链）；
② 「图不回传」。执行者要么卡死（一直催用户交图），要么假装通过（写一堆用户根本没有的图号）。
这一节就是为消除这个矛盾而设。

### 15.2 三形态

| 形态 | 名称 | 图在哪 | 提示词写法 | 一致性靠什么 | 门禁可核验性 |
|---|---|---|---|---|---|
| **M0** | 纯提示词 | **哪儿都没有** | **不出现任何图号 / 参考图槽位** | 全量文字锁（第三节 16 项 + 第十一节） | 不可核验图像，只核验文字 |
| **M1** | **编号占位（默认）** | 在**用户平台侧**；liqi 只有编号与用途 | 出现 `@图片N` 槽位 + **必附《素材接线单》**（15.4） | 文字锁（主）+ 编号一致（辅） | 可核验「编号对不对得上」，不可核验图像 |
| **M2** | 已入库 | 用户**主动交回**，登记进资产注册表 | 出现 `@图片N` 槽位，可标「已登记」 | 文字锁 + 编号 + **图像级核验** | **可做图像级核验** |

**默认形态 = M1**。不写默认值执行者就会各写各的，故默认明确定为 M1：
用户说「我没有图 / 不要图号 / 只要提示词」→ **降级 M0**；
用户主动把图交回（贴图 / 给路径 / 说「图已经出好了」）→ **升级 M2**。
**形态切换必须显式，禁止静默切换**——M0 交付里夹带图号、M1 交付里漏掉接线单，都是**形态违约**。

**形态声明（每次交付首行必写）**：

```text
素材形态：M1（编号占位 · 图号 3 个 · 接线单见文末）
素材形态：M0（纯提示词 · 未使用参考图 · 一致性靠文字锁）
素材形态：M2（已入库 · 图1/图3 已登记 · 可图像级核验）
```

未声明 = **形态未定**，机检告警（F7），不得交付。

### 15.3 与 A 轴（依赖分级）是两条正交轴

| | 问什么 | 决定 |
|---|---|---|
| **A 轴**（第一节 A0~A3） | 任务复杂度 | **要不要走资产链** |
| **M 轴**（本节） | 图在不在你手里 | **门禁怎么判、一致性靠什么** |

组合建议（**M 轴由用户实际条件决定，不强制**）：

| A 轴 | 建议形态 | 说明 |
|---|---|---|
| A0 纯文字 / 单镜 | M0 | 无跨镜一致性要求，图号反而增加噪声 |
| A1 单角色单镜 | M0 或 M1 | 有图更稳，无图可用文字锁 |
| A2 跨镜一致性 | **M1**（默认） | 图号 + 接线单收益最大 |
| A3 多人 / 多场景 / 连续剧集 | M1 或 **M2** | 连续剧集值得建图册（用户愿意交回图时） |

A 轴判不清按高一级处理（第一节口径）；**M 轴判不清按用户实际条件处理**，不按最高档——
不要为了「合规」逼用户出图。

### 15.4 素材接线单（M1 / M2 必附）

**接线单是「图片入库」的正向替代物**：用户不需要把图交回来，只需要按单子把图挂上。

```markdown
素材接线单

> 用法：本单是你**在平台侧挂图**的说明书。提示词里出现的每一个图号，本单都有一行。
> 你只需在平台的参考图 / 素材区，按「你该挂哪张」把图挂上——不需要把图发回来。

| 图号 | 类型 | 用途（只控制什么） | 你该挂哪张 | 不控制什么 |
|---|---|---|---|---|
| 图1 | 角色参考 | 锁定 沈知微 的脸型 / 发型 / 服装 / 体态 | 你出的「沈知微」4 View 板（任一张正面全身） | 姿态、表情、场景、光线 |
| 图2 | 场景参考 | 锁定 河岸栈桥 空间结构 / 固定锚物 / 光源方向 | 「河岸栈桥」场景母版图 | 人物、剧情动作、第 0 秒构图 |
| 图3 | 道具参考 | 锁定 旧皮箱 外观 / 材质 / 颜色 | 「旧皮箱」专属道具表 | 手持姿态、光效、镜面反射 |
| 视频1 | 动作参考 | 只参考 出刀节奏与运镜 | 上一段成片 | 角色外观、场景、画风 |

**未挂图会怎样**：平台上未挂 `图1` 时，模型仍按提示词中的**外观复述**渲染——
一致性下降，但不会报错、不阻断交付。
**挂错比不挂更糟**：图号与用途必须一致——把场景图当角色图挂上，会直接污染形象。
```

接线单四条硬约束：

1. **图号只能有两个来源**：① 用户提供；② 本单在本次交付中显式定义。**禁止凭空写图号**。
2. **双向一致**：提示词里出现的每个图号接线单必须有行；接线单每行提示词至少要引用一次
   （未引用标「本次未使用」）。→ 机检 F7。
3. **每个图号必须写明「只控制什么 / 不控制什么」**——这是防「一张图被当四张用」的关键。
4. **不写内部 ID**（`@CHR-` / `asset-xxx` / `CH001`）——用户看不懂。写 `@人名` / `@场景名` /
   `@道具名`。

⚠️ **M1 交付 = 《素材接线单》 + 全套出图提示词，缺任一类 = 交付不全**。
接线单是「挂图说明书」，出图提示词才是「图的来源」——只给接线单，用户拿着单子无从生图。

### 15.5 文字锁：M0 / M1 下的一致性保障路径

没有图，跨镜 / 跨段一致性依然要有保障。答案是**文字锁**——把一致性锚在**可复述的文字**上，
而不是锚在**liqi 看不见的图**上。

| # | 铁律 | 理由 | 落地处 |
|---|---|---|---|
| 1 | **外观复述块**：某角色在某段首次出现时，必须完整复述外观要素（发 / 服装 / 体态 / 年龄感 / 标志物），**禁止写「同上 / 同前 / 照旧」** | 模型**每段零记忆**——「同上」等于没写。这是「没有参考图时一致性下降」的唯一真实病根 | 第三节 文字锁 16 项 |
| 2 | **编号只承担接线职责**：M1 下 `@图片N` 只负责「告诉用户该挂哪张」，**不得把一致性全押在编号上**——复述照样要写 | 图号可能挂错 / 未挂 / 被平台忽略，复述块是唯一不依赖用户操作的保险 | 本节 |
| 3 | **场景锁**：方位卡 + 时段变体，跨镜跨段复用**一字不改** | 场景一致性靠参数化描述，不靠图 | `场景方位卡与固定锚物.md` |
| 4 | **摆位锁**：站位与位移必须入画 | 跨段穿帮第一来源是「人凭空消失」 | `空间层_调度与轴线.md` |
| 5 | **命名锁**：同一角色全篇**同一名字**，禁「青年男子 / 黑衣人 / 他」混用指代同一人 | 名字是模型唯一可靠的跨镜指代手段 | `资产注册表_asset-registry.md` |

⚠️ **文字锁是 M0/M1 的替代路径，不是降级方案**——不得因为「没图」就放宽上表任何一条。

### 15.6 四铁律（总纲）

| # | 铁律 | 反面（禁止） |
|---|---|---|
| 1 | **不索要** | **禁止**把「请把图发我 / 请上传素材」作为继续流程的条件。换形态可以，卡流程不行 |
| 2 | **不阻塞** | **禁止**因「没有图」而阻断分镜 / 投喂 / 质检——门禁按本节改判，而不是停下 |
| 3 | **不假装** | **禁止**写不存在的图号当锚点；**禁止**声称「已核验 / 与资产册一致」而实际从未见过图 |
| 4 | **要声明** | 每次交付首行必须写明形态（15.2），并说明一致性靠什么保障 |

### 15.7 门禁改判（liqi 侧的落点）

| 门 | 原规则 | M0 | M1（默认） | M2 |
|---|---|---|---|---|
| **B 门 资产锚覆盖**（`audit_project.py`） | 逐块查首帧参考 / `@图片N` | **不适用**（无图号可引；不传 `--assets`） | 原样 + 图号须在接线单内 | 原样 + 可图像级核验 |
| **F 门 F7 素材形态**（v5.9.0 新增） | —— | **M0 出现图号 = ERROR** | 有图号无接线单 = WARN；图号 ∉ 接线单 = ERROR；有图号无声明 = WARN | 同 M1 |
| **CT3 角色资产板**（`audit_contract.py`） | 查 4 View 结构指纹 | **不变**（资产板是**提示词**结构，与图在不在无关） | 不变 | 不变 |
| **CT7 投喂稿过机检** | 查机检结果 | **不变** | 不变 | 不变 |

🔴 **F7 不是形态门，是形态违约门**——它只在「声明与稿子不符」时报，
不会因为你是 M0 就要求你出图。**跳过 ≠ 通过**：M0 不传 `--assets`，
B 门那一行在报告里是跳过，不是 OK。
