# 任务模板路由（v2.0 新增）

Step 3 写镜前先判任务类型。**混合任务只指定一个主模板**，辅模板只补必要字段，
不把两套完整骨架叠加——叠加会让模型失去主次，长提示词渲染成一镜到底。

判定优先级：动作接触 > 连续长镜 > 口播对话 > 通用（走镜头骨架库）。

---

## 一、动作接触戏

liqi 原本对动作戏没有专项处理，全靠通用流程硬扛，这是高发翻车区。

**强制链条**：起势 → 发力 → 路径 → 接触 → 反馈 → 结果 → 下一接口

规则：

一、**一拍只写链条上的一段**。八秒做完整个链条必然丢动作，按拍拆开，
每拍对应骨架库第六类的三条之一（起势蓄力 / 接触瞬间 / 反馈余波）。

二、**接触点必须写死**：谁碰谁、碰在哪里、反作用力落在谁身上。
写「两人交手」等于没写，模型会自由发挥成推搡或错过。

三、**接触时长不超过一秒**。超过就变成持续推搡，不是打击。

四、**随动物件必须列**：衣料延迟、尘土扬起、液体飞溅、头发滞后。
没有随动，动作会像游戏引擎里的橡皮糖。

五、**结果即终态**：动作镜的末拍必须停在可交接的状态——
谁在画面什么位置、手里拿着什么、是否失衡。这是下一镜的起幅。

六、**禁止在同一拍内写两个发力方向**。发力方向只有一个，转身再发力要拆成两拍。

时间轴骨架（5 秒典型）：
【时间轴】0-2s：起势，重心落 <位置>，发力方向指向 <目标>
【时间轴】2-3s：发力与路径，肢体沿 <路径> 移动
【时间轴】3-4s：接触，<A> 的 <部位> 触及 <B> 的 <部位>
【时间轴】4-5s：反馈，<B> 向 <方向> 位移失衡，<随动物件> 跟进

## 二、连续长镜（一镜到底）

**先声明真伪**，这是最容易出事的地方：把多镜剪辑伪称一镜到底是自欺欺人。

| 类型 | 判定 | 必写 |
|---|---|---|
| 真一镜 | 全程无切点，机位连续运动，空间连续 | 机位起点、路径、速度变化、停止构图，全程同一组空间关系 |
| 伪一镜 | 存在遮挡黑场或匹配剪辑 | 明写接缝位置与匹配方式，不宣称「一镜到底」 |

**接缝合同**（伪一镜必写）：
接缝发生在第几秒；用什么完成接缝（遮挡物扫过 / 黑场 / 光色渐变 / 形态匹配）；
接缝前后空间如何变化；接缝后哪些元素保持不变。

**真一镜的硬约束**：
机位必须有起点、相对位置、触发、路径、速度变化、焦点、停止构图，七项缺一不可。
自然遮挡可以重构构图，但不得把隐藏剪辑称为真一镜。
口型、接触、身份或反应覆盖不足时，主动放弃长镜改拆镜——不要硬撑。

**时长**：超过 20 秒仍走 Step 1 的滑窗拆分，与是否是长镜无关。

## 三、口播与对话

**口型主镜规则**：

一、谁在说话谁占主镜。说话者的口型只为当段台词服务，不说话时嘴唇静止。

二、接收者反应单独成拍。强信息、长句、关键句之后必须给反应拍，
不要在同一拍里既说话又给反应。

三、VO（旁白）不要求口型，OS（画外）的说话者留在画外不入画。

四、台词时间按 Step 1 的密度红线算：旁白 ≤4.0 字/秒，对白 ≤5.0 字/秒。
超了先精简台词，不要靠加快语速解决。

五、**说前 / 说时 / 说后**三态：
说前——吸气或停顿，给台词一个起点；
说时——口型与台词同步，其余身体动作减弱；
说后——停在某个状态，等待回应或转向下一动作。
详见「情绪表演层」。

时间轴骨架（8 秒单人）：
【时间轴】0-2s：说前，<角色> 吸气，视线落向 <目标>，背景 <状态>
【时间轴】2-6s：说时，口型对应台词「<原文>」，身体保持 <姿态>
【时间轴】6-8s：说后，<停在什么状态>，等待回应

## 四、不覆盖的场景

以下内容 liqi 不做，遇到时明确转交：

| 需求 | 去向 |
|---|---|
| 已有视频要拆解成分镜 | cinematic-shot-prompt-expert / infimind-video-analysis |
| 电商带货、抖音促单 | seedance-video-prompt（国内抖音五模块版） |
| TVC 品牌落版 | seedance-video-prompt（TVC 路线） |
| 舞蹈、穿越机 FPV | direct-seedance25-video（有专项模板） |
| 微表情与肤质极致写实 | realistic-actor |
| **专项打戏编排 / 大招终结技 / 兵器流派库 / 玄幻法术** | 本 skill 只做到「动作接触」通用链条（第一节）。专项需求请走 lengyi-shotlist / seedance-video-prompt 等专项技能；另有一套外部的 10 份武打专项库（约 3.1 万字）未随本仓库分发 |

转交不是甩锅：本 skill 的九段风格锚与预算体系仍然适用，

⚠️ **上表的转交目标都不在本仓库内，公开安装的用户一个都没有。** 遇到这些需求时按两步走：

1. 先照 `SKILL.md`「外部依赖与降级方案」表判断有无等效降级——`realistic-actor` 那一行可用
   `表演层_FACS微表情.md` + `质感与可见性预算清单.md` 覆盖大部分微表情/肤质需求，其余五项目前**无等效降级**。
2. 无降级时**如实告知用户本 skill 不覆盖该场景**，并说明推荐去向。
   **禁止用通用流程硬凑一份次品冒充专项交付**——电商带货、TVC、舞蹈 FPV、逆向拆镜这几类，
   凑出来的稿子看起来完整但转化与可用性都不达标，比直说做不了更坏。
可以先用它立锚，再交给对应 skill 做场景化落地。
