# 版本拆分与互锁清单（批量任务前必读）

## 一、何时需要拆分多版本

| 触发条件 | 判定标准 | 处理 |
|---|---|---|
| 服装阶段切换 | 设定/剧本中出现"换装、新裁、改穿"等时间节点 | 拆 A/B 两条目，各自独立出图 |
| 体态状态切换 | 同一角色出现"瘦脱形、衰老、状态恶化"等体态变化 | 拆两条目（正常版/状态版），同衣不同状态 |
| 道具阶段切换 | 道具出现"完好→烧焦/破损/使用后"等状态变化 | 拆两条目（如 8A 完好/8B 烧焦） |
| 道具状态弧切换 | 同一道具的开合/破损/内容物等态跨镜复用、且影响识别或交接 | 每个要复用的态各出一张（18A/18B） |
| **场景时段切换** | 同一场景出现晨/午/昏/夜等不同时段 | **不拆条目、不建新卡**——走 `scenes.<slug>.variants.<时段>` 子键，每个变体各配光照互锁词。**先定 `baseline_time` 基准时段**，其余变体只改光照字段，陈设与空间一律复用——否则同一场景的不同时段会被画成两个地方 |
| **场景破损态切换**（v5.6.8 新增） | 同一场景被**不可逆改造**（墙被撞穿、梁烧塌、窗砸碎、水漫过线），且后续镜要承接 | **同样不拆条目**——走 `scenes.<slug>.damage_states.<态名>` 子键（如 `intact` / `wall_breach`），每态配 `delta`（新增什么）+ `invariant`（什么必须一致）+ 双向 `lock_out`。不建态＝下一镜凭空复原 |
| 单一版本 | 全片/全程一套服装、无状态变化 | 一条目即可，不拆 |

**场景与道具的版本维度不同，别混用**（v5.6.8 修正）：道具的状态（开合 / 破损 / 内容物）各出一张卡；
场景的**时段**变化归光照变体不拆卡——但**这条只管时段**，场景的**结构性破损**要建 `damage_states`，
早期"道具有状态弧、场景没有"那句话已作废，详见 `资产层_锁定与一致性.md` 第八节。

**🔴 场景也是「多版本」，但版本容器名不同**——这是最容易写错的一处：

| 资产 | 版本容器 | 键名 | 版本名从哪来 |
|---|---|---|---|
| 角色 | `characters.<slug>.versions` | `A` / `B` | `codename`（如「素白中衣」） |
| 道具 | `props.<slug>.versions`（`state_arc` 记当前态） | `A` / `B` | 态名（如「展开可读态」） |
| **场景·时段** | `scenes.<slug>.variants` | **时段名**（`noon` / `dusk` / `night`） | 时段名本身（**无 `codename` 字段**） |
| **场景·破损态** | `scenes.<slug>.damage_states` | 态名（`intact` / `wall_breach`） | 态名本身（**无 `codename` 字段**） |

四者的**互锁纪律是同一条**（双向加锁、进 `lock_matrix`），区别只在容器名与版本命名方式。
场景变体**不进 `characters`**，也**不另起一个 `scenes` 条目**——它就在原场景条目的 `variants` / `damage_states` 下。
`variants` 与 `damage_states` 并列，出图时取「时段 × 破损态」交集描述。

判断口诀：**有切换点（时间/剧情节点）→ 拆分；无切换点 → 单条目**。不确定时按拆分处理，多一张图比穿帮好。

## 二、条目编号规则

- 主编号连续：1, 2, 3, 4...
- 拆出的版本用字母后缀：`2` 与 `2B`、`18A` 与 `18B`
- **场景用 `S` 前缀编号**（`S1` / `S2`…），与角色、道具的数字编号分列——这样「条目 3」与「场景 3」不会互相误引
- **场景变体不再编号**，用时段名作后缀，落盘文件名 `<slug>-<时段>.md`（如 `scenes/xianya-morgue-noon.md`）。变体不是独立条目，**不占新编号**
- **🔴 易错点**：条目拆分后，其他条目中引用该道具的编号会失效——批量生成后必须全包检索旧编号并改为当前包内实际编号（如旧包引用"条目8A"→新包实际为"条目18A"）。

## 三、版本互锁负面词对照表

| 版本 | 禁止内容必写（互锁词） |
|---|---|
| 角色A A（素白中衣） | 藕荷色系 |
| 角色A B（藕荷衣裙） | 素白中衣（本版禁用A版配色） |
| 角色B正常版 | 瘦脱形（正常版禁用四幕状态） |
| 角色B瘦脱形版 | 换脸、换服装颜色、骷髅化 |
| 藕荷小衣完好态（8A） | 焦黑痕迹、恢复完好 |
| 藕荷小衣烧焦态（8B） | 燃烧中的火焰、明火元素、恢复完好 |
| 停尸房·正午（`noon`） | 暖橙夕照、长投影、烛火光晕、月光、浓黑 |
| 停尸房·黄昏（`dusk`） | 正午顶光、冷白天光、短锐阴影、月光、浓黑 |
| 停尸房·深夜（`night`） | 日光、天光、均匀照明、暖橙夕照、长投影 |

**🔴 场景变体要从三个维度同时下刀**：**色温 + 光质 + 影子形态**。只禁一个维度挡不住串版——例如夜版只禁了「日光」，模型仍可能给它一个均匀照明的顶光。上面三行的词就是从这三个维度取的。

**且每个变体的 `lock_out` 要覆盖「其余所有变体」的标志性特征**——三变体的场景里，正午版要同时禁住黄昏与深夜的光。这条不只是纪律，它直接决定 **C2 门查不查得出来**：`audit_project.py` 的 C2 门按「声明时段 × 该时段 lock_out」判定，`lock_out` 没写到的别版特征它就看不见（词数 < 3 会发 WARN 提示补齐）。

原则：**每个版本的禁止内容里，必须有"禁另一版本特征"的词**——这是版本隔离的关键，防止生图工具串版。

## 四、使用纪律速查

1. **版本独立生成（硬规则）**：多版本每个单独出图，禁止合并进同一张设定图。
2. **图注文字一律中文**：道具/场景表引线注释中文；人物卡零引线零标注线（仅表情名/身高线/色板三处带字）；中文渲染崩了走 SKILL.md Step 3 的三级降级预案。
3. **身高线与头身档位都是硬约束**：所有站立角色条目必须带垂直身高参照线；头身比按**目标观感**档位表选（不默认 7 头身），同包禁止混档；孩童 vs 成人差是构图基础。
4. **无主图条目**：文字版角色收尾句"不篡改参考图人物面部五官结构"按"保持设定五官一致"理解即可。
5. **场景-资产联动**：资产绑定时间节点的（如某服装从中秋才启用），写入使用纪律防止穿帮。
6. **安全约束内嵌**：解剖类=无内脏无骨骼无鲜血；文书类=无可读文字（**文字类道具例外**：文书/匾额类设定图允许可读文字，但必须带"乱码错字"防线，生成变形→留白后期合成；见 `道具展示表_模板.md` 字段注释）；剪影=不露正脸；动物=不露全貌。
7. **注册表回写（硬规则）**：新增版本后，除了给新版本写 `lock_out`，**必须回头给旧版本的 `lock_out` 补上新版本特征**——单向加锁等于没加锁，这是串版最高频的漏项。同时更新 `asset-registry.json` 的 `lock_matrix`。
8. **色值取用纪律**：色值只从注册表取，禁止现场编造；**缺 HEX 视为不合格**（中文色名跨模型漂移极大）。
