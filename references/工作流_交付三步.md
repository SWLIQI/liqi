### Step 4：质量过关

**① 机器校验（强制，先跑）**

```bash

#       管目标面——h3 触发 E-WRONG-SCRIPT 早退改跑 check_prompt_h3.mjs，seedance-off 强行按 Seedance 校；
#       --strict 把 warning 也视为失败（exit 1）；--all 展开每码全量明细（默认每码最多列 4 条）。
```

规则码按 `E-`（阻断级）/ `W-`（建议级）两类，**全表见 `references/质控层_门禁与过审.md` §二**。

另有 2 个输入级码 `E-INPUT` / `E-WRONG-SCRIPT`（文件读不了、或拿 H3 包跑本脚本时早退，退出码 2），不进上述内容码表。**有 error 必须修完再交付**；warning 建议处理。
**超字不再靠猜**：`W-LENGTH-CAP` 的提示里直接点名最长 3 行（行号 + 字数）；要看全量明细加 `--len [N]`——按镜给「字数/额度 + 节小计（降序）+ 最长 N 行」，口径与门禁同源（同一把尺），删哪行一眼可见。
`--beats` 给节拍清单时另查节拍认领对账（`E-BEAT-CLAIM-UNKNOWN` 认领不存在的拍 / `E-BEAT-CLAIM-OVERLAP` 重复认领 /
`E-BEAT-CLAIM-GAP` 有拍遗漏 / `E-BEAT-SCENE-MISMATCH` 场次对不上 / `E-BEAT-LINE-MISSING` 台词未逐字进镜 /
`W-BEAT-TIME-OVERRUN` 认领拍预估超镜长 15% / `W-BEAT-CLAIM-MISSING` 部分镜没写认领行）。
格式与用法见 Step 3 第 1 小节的「节拍认领行」。

**三类漂移与哪道门管**（v5.6.7）：
| 类别 | 登记处 | 由谁查 |
|---|---|---|
| 版本漂移（角色/道具服装形态） | `characters.*.versions` / `props.*.state_arc` | C 门 |
| 时段漂移（正午/黄昏/深夜） | `scenes.*.variants` | C2 门 |
| **状态漂移（破口/血迹/灰烬/撕裂/烧毁）** | **`scenes.*.damage_states`** | **F 门双向 `lock_out` ＋ 人工核对承接** |

⚠️ **第三类此前无任何门禁覆盖**：事件改变了场景的物理状态（撞穿墙、留下血迹、烧成灰），若不开 `damage_states`，下一镜的【参考素材职责】仍指向未破坏状态的图——**画面凭空复原**，观众一眼看出穿帮，而 C / C2 / D / E 四道门一条都不报。
判据：**上一镜发生致变事件 → 该场景必须有一条 `damage_states`，且后续所有镜都指向它的图。** 详见 `references/资产注册表_asset-registry.md`。

⚠️ `--script` 认的是**标准剧本格式**（角色名独占一行 → 可选语气行 → 台词行）。喂纯文本或 docx 直出会抽出 0 条台词，而 A 门用的是全文子串匹配、不依赖结构化提取，于是**整道门报 OK 却一句没查**——假绿。v4.7.3 起抽取为 0 条直接报 ERROR 拦下。转换：

```bash
python scripts/extract_script_docx.py <剧本.docx> --std -o 剧本_标准.txt [--cast 道士甲,道士乙]
```

中文剧本大量台词写作「动作描写…：「台词」」，冒号前没有角色名，`--std` 按「引号前最近出现的角色名」归属说话人；角色名自动识别（2–3 字且出现 ≥2 次），识别不准时用 `--cast` 点名。E 门同理：转场表必须是 `| 镜1→镜2 | 类型 | 要点 |` 的表格行，写成纯文本行会被判「无转场表」而静默放行。

**①c 过审预检（投国内面时必做）**

```bash
python scripts/audit_risk.py <file> [--shot 1,2,3] [--detail]
```

只扫**可复制正文**（自动排除说明行与参数行）——因为只有正文会真正送进模型与审核。风险分 = Σ(词等级 × 出现次数)；**单镜 ≥20 可能被拦、≥50 大概率被拦**（出现等级 3「几乎必拦」词直接退 1，只有中高危词退 2）。
⚠️ **假绿防线**（v4.7.6）：抽不到正文（0 字符 / 0 行）时本门报 `E-NO-BODY-SCANNED` 并退出码 2，不再报「✅ 无可复制正文触发任何高危词」——空文件、段头没被认出、`--shot` 全滤掉，都会走到这条路。`audit_literal.py` 同款防线（扫了 0 行正文就报错）；`check_prompt_h3.mjs` 本就对 0 块硬失败。**门最危险的状态是「什么都没查却说通过」。**

**①d 门失败统计（改规则的依据，项目期内随手跑）**

```bash
node scripts/gates_stats.mjs [目录] [--tool check_prompt.mjs] [--top 10] [--lookback 5] [--fail-on-stall]
```

`check_prompt.mjs` / `check_prompt_h3.mjs` / `check_style.mjs` / `audit_literal.py` / `audit_risk.py` /
`audit_project.py` 六个脚本**默认**把每次运行的规则码计数追加到「被校验文件同目录」的 `.gates.jsonl`（`--no-log` 关闭；
写入失败静默跳过，绝不影响校验退出码）。stats 聚合后回答三件事：**哪道门最常响**（那条规则模型最常无视，

**③ 改稿必跑三步复验**（原 liqi 只有 warning，没有改稿纪律；这条是补的缺口）：

1. **局部验证**：改动处本身达标；
2. **联动冲突检查（七项交叉扫描）**：伏笔 → 角色（人设/脸模/服装）→ 信息量（剧透/节奏）→ 因果节拍 → 资产锚点 → 时长预算 → 画幅一致性；
3. **全量审核**：整片重跑 P0~P2，不允许以「已检查改动处」豁免。

修改类交付物文末必须附**《改动复验报告》**（改动清单 + 联动检查结论 + 全量审核结论），**未附视为未完成复验，禁止交付**。

**④ 去 AI 味 + slop 门禁**：禁「电影感/高级感/氛围拉满/细节丰富」；材质必须可观测（粗糙/反光/湿润/起毛）；抽象意境允许保留但必须**紧跟一句可执行的画面支撑**。slop 词计数：0 → 提交；1–2 → 删除收紧；3–5 → 从主体重写；**5+ → 推倒重来**。
**精度梯度**：Level 0 空泛 → 1 类型 → 2 布光 → 3 角度 → 4 数值。**至少做到 Level 3**；一致性要求极高时才上 Level 4（数值类不进正文）。

**⑤ 预算体检**：可见性预算（每个出镜对象是否都写了可见范围）、色彩预算、材质继承、运动签名、保真预算（主花费是否只有一个）。

**⑥ 文字铁律**：短信、屏幕、报告正文、法条字幕一律「后期合成」，禁止让 AI 生成可读文字。

**⑦ 台词铁律**：「」内文案以剧本原文为准、**一字不差**；三处逐字一致；配音后期统一合成。

**⑧ 防过度锁定**：每段只锁 1–2 个**强条件**（观察关系 / 镜头运动 / 关键动作，三选其一二），其余留白。
**必锁项（不占这 1–2 个名额，每段都得给）**：多镜切点、动作时序、材质、可见性、色彩预算、站位、朝向、景别。
**判定标准只有一句**：删掉它模型会不会乱——会乱的是必锁，不乱的就是可留白的。

**⑨ 台词自检卡**（内部 QC 附件，**不写入提示词正文**）：每条台词输出 台词 / 字数 / 语速档 / 所需时长 / 判定 / 建议。

**⑩ 断言纪律（v5.16.0）**：两条铁律，机械兜底是 `audit_project.py` V 门 `E-UNVERIFIED-CLAIM`——
- **没观察过就不声称观察过**：没跑过脚本、没见过图、没读过官方文档的事项，不得写「已校验 / 已通过 / 全绿 / 已验证」；包内出现这类断言却找不到任何校验结果痕迹，机检直接 ERROR。替代写法照 `references/agent平台适配.md` 铁律 3 的对照表（「未跑机检 · 人工核对 8/10 项 · 未覆盖：G 门台账对账、N 门剧本门禁」）。
- **未核实的能力不断言**：模型能力的存在性与参数，只认两个来源——官方文档口径（「投放面参数总表」）或本机实测记录；社区技巧不得写成「官方支持 / 保证稳定 / 保证一致」。拿不准时就写「未经核实」并给保守写法，**withhold the claim, not the work**——不影响出稿，只影响把话说满。

**人审三态（v5.17.0，吸收 zenstory 独立 reviewer 原则）**：机检之外的三步复验、项目级审计属**人审层**，按三种复核方式之一执行并如实声明——
- **独立复核（优先）**：由未参与本次创作的执行者审查；审查与修改分离，reviewer **只出问题清单**（位置 + 证据 + 影响 + 修订责任方 + 规则码），修改交回责任阶段，不代改；
- **自检并声明**：条件不允许时可以自检，但复验报告必须写明「自检」——既当运动员又当裁判员的事实不隐瞒；
- **跳过即 N/A**：不做的人审项标 N/A + 理由，**N/A 不是通过**（与 CT 表口径一致）。
审查产物落 `审查/<包名>-审查.md`，固定结构：范围 / 结论（OK / REVISE）/ 复核方式 / 问题条目。

### Step 5：转场注记 + 连续性台账 + 制作纪律（整片必出）

**转场注记总表**：必须用镜号锚定，`镜X（场景）→ 镜X+1（场景）：转场方式 + 状态交接`。除转场方式外必须写明交接状态（谁在画面什么位置、手里拿着什么、光从哪来、声音怎么接）。禁止用「引子→第一幕」等幕次指代。

**段缝对（生成单元之间）**：滑窗拆分产生的段与段之间，转场表按普通镜对照常标注，另在包首以 `【段缝声明】` 锁定 Step 1 的四选一方式；段缝两侧的状态交接以尾帧锚定为依据时（API `return_last_frame` 返回帧或手动截图），写明「截帧来源：第 X 段末帧」。

**整合段段间衔接**：每段首拍必须写明怎么接上一段末拍，`接上段（机制）：<本段开画内容>`。机制只认七类：**同场紧接 / 换场硬切 / 换时硬切 / 同院换时 / 同场升机位 / 视线匹配 / 大跳**。

**跨段默认用蒙太奇直切**：段与段是**各自独立生成的剪辑关系，不是连续拍摄关系**。跨段位置/场景不一致时默认蒙太奇直切，接续状态只需标明「跨段蒙太奇衔接」与两端画面。**严禁为凑连续性把两个场景塞进同一个生成单元**去表现「连续走位」——双场景穿梭是穿帮高发源。
判定口诀：**跨段切、同段连**。
**跨段锚点钩子**：前段尾帧必须为后段核心登场元素埋钩子（远景剪影 / 视线指向 / 声音预告），同时前段禁项的人数锁定要**为该钩子元素开单例豁免**（写明何时、何处、剪影级、静止、仅一人）。

**连续性台账**（多镜必出，逐镜记录 9 锚点）：

| 锚点 | 记什么 |
|---|---|
| 角色 | 服装、发型、轮廓、随身道具、情绪状态 |
| 道具 | 形态、位置、在谁手里、朝向 |
| 空间 | 布局、左右地理、门窗位置 |
| **轴线与屏幕方向** | **本镜是建立 / 保持 / 跨越；谁在画面左、谁在右；主体运动方向** |
| 视线 | 每个角色看哪里，反打是否匹配 |
| 光位 | 主光方向、实用光源、时间、大气 |
| 机位 | 镜头感、高度、稳定性、运动族 |
| 动作态 | 上一镜结束时的动作落点 |
| 声音态 | 音乐、环境、对白、同步点 |

「空间」与「屏幕方向」两行**不许留空**——跨镜的站位一致性脚本查不了，只能靠这两行逐镜比对。

**取景半径铁律（分身根因）**：镜头能框住谁，由**景别 × 站位物理距离**共同决定，不由台词需要决定。点名做可见表情/动作的角色，必须处在景别能框住的物理距离内。中近景里点名远处角色做可见动作 → 模型无法让画外人物入画，只能位移或复制分身。**三种合法处理**：升景别改全景；拆反应镜；降级为画外音。
**「缓慢拉镜拉出全员」不算合法处理**——拉镜只是景别渐变，改不了物理距离。

**全局制作纪律**：风格铁律 / 材质铁律 / 运动签名铁律 / 色彩预算铁律 / 可见性预算铁律 / 参数卫生铁律 / 正向表述铁律 / I2V 优先 / 文字铁律 / 台词铁律 / 单实例铁律 / 返修纪律。

**返修分级**：保留 / 后期修 / 编辑 / 重 roll（改一个变量，最多 3 次）/ **重写提示词**（连改 2 次仍失败 → 回 Step 4 重新诊断，禁止靠堆形容词硬修）。
**单次只修一项（v5.38.0 吸收转场 Skill 修正纪律）**：一次只修最影响目标的那一项，合格部分原样保留——同时改三处，改好了也不知道是哪一处起效，下次复发照旧。同一处两次定向修正仍失败：解释问题出在哪，并给缩小范围的具体建议（动作复杂度 / 景别跨度 / 转场手法三选一），**不擅自替换用户明确坚持的效果**。
**先立原则：Fix at the sheet, not the shot**——某个分镜里角色细节错了，不要反复重抽那个镜头，回设定卡定位错误面板，修正卡片，之后所有镜头继承修复。反复重抽会引入新的随机漂移。
**镜头裁定表（v5.17.0，吸收 Emily take lineage）**：改动复验触发重写时，在复验报告里逐镜给状态——`planned（未复核） / accepted（已接受） / rejected（废镜） / superseded（被替代）`。**rejected / superseded 的镜号必须移出本包或由替代镜替换**，其内容不得进台账、不得被后续镜引用——**废镜禁入 canon**（机检 `audit_project.py` R 门 `E-TAKE-IN-CANON`：废镜仍在包内带 live 镜块 = ERROR；包内无「镜头裁定」表时本门不适用）。planned 的镜不能当已接受事实去续写。
**断点续跑纪律**：资产出图、设定卡裁切、看板编译等慢步骤一律「产物存在即跳过」——落盘文件名按镜号 / slug 固定（`images/<slug>-sheet.png`、`<段号>/f<切序>.png`），重跑命令时已存在的产物直接复用，返修只补缺的；单件失败跳过不阻断，最后汇总说明。禁止为「全部重出一遍更保险」而清空已锁定产物——那是把已对账的一致性推倒重来。
改哪个变量查 `references/失败诊断与返修映射.md`（四层定位：锚定 / 预算 / 时序 / 表述 + 15 条症状表）。

## 〇 交付前置（v6.19.5 · 最高优先级，先于一切格式检查）

**交付前必须先跑总账，并把输出贴出来。没贴 = 没交付。**

```bash
python scripts/audit_project.py <提示词包.md> --registry <asset-registry.json> --log
node scripts/check_prompt.mjs <提示词包.md> --model <2.0|2.5> --surface <cn|intl> --log
```

**为什么把这条放在第一位**：2026-11-05 复盘的九个返工点里，绝大多数**门本来能抓**——
三层人物错位能被 `E-IDENTITY-NOT-INLINE` 抓住（注入实测 18 条 ERROR），却没跑；
交付三版 EP20 包时我只跑了 `check_prompt` 单门就宣称 0 error，总账里躺着 3 个 error。

**这是本包最昂贵的一课**：规则不缺，缺的是「规则必须被执行」这条元规则。加十道门，
跑的人只跑一道，等于零。

判读口径：
- **`未查 ≠ 通过`** —— 总账末尾那行「N 项未查」必须逐条看，缺什么输入就补什么输入；
- **`跳过 ≠ 通过`** —— 缺 registry / 缺 ledger 导致的跳过，不算干净；
- 单门全绿只说明**那一道**门没意见，不说明包能投。
