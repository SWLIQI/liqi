# 连续性台账（Continuity Ledger）

> 📒 **流程位置：Step 3 逐镜阶段，每写完一段就登记一段；Step 4 交付前与提示词包对账。**
> 本文件定义三本账（人物账 / 场景账 / 时间轴账）、逐段登记格式，以及 `audit_project.py` 的 **G 门七条机检**。
> 上游来源：外部《灵境AI漫剧制作流》continuity-supervisor 的台账范式，按 liqi 既有机制重新落位（v5.7.2）。

---

## 〇、 为什么需要：状态没有地方存

liqi 在 v5.7.2 之前，跨镜一致性靠**每镜重述**。重述就会漂，而且漂了没人知道：

```
段 1：@长风（承重柱旁 · 右手持桃木剑 · 灰袍束袖）
段 2：@长风（双手结印 · 灰袍束袖）          ← 剑呢？
段 3：@长风（右手持桃木剑 · 灰袍束袖）      ← 剑又回来了
```

三段的提示词单看都合规，连起来是穿帮。问题不在提示词写得不好，在于**「长风此刻手里有没有剑」这个事实没有存放的地方**——每一镜都靠当次重述，而重述是逐镜临时决定的。

AI 视频每段独立生成、零记忆，「世界现在是什么样」必须由人维护。台账就是这个存放处。

**一句话原则：提示词只管这一镜要演什么，台账管世界现在是什么样。**

## 一、 四份机制的分工（不要重复造，也不要互相顶替）

| 机制 | 管什么 | 粒度 | 会不会变 |
|---|---|---|---|
| **场景方位卡**（`场景方位卡与固定锚物.md`） | **空间基准**：罗盘方位 / 固定锚物 / 屏幕方向 / 禁变约定 | 一个场景**一张**，全场景共用 | 不变（锚物变了要另出卡） |
| **资产注册表**（`asset-registry.json`） | **数值事实源**：身高 / 色值 / 版本互锁 / 光照锚点 / 身份判定 | 一个项目**一份** | 改即变更，需回写 |
| **连续性台账**（本文件） | **世界当前状态**：谁站在哪、朝向哪、穿哪版、手里有什么、场景处于哪个阶段、时间推进到哪 | **逐段一本**，逐段更新 | **会变**，每处变化挂触发节拍 |
| **分镜提示词包** | 这一镜**要演什么** | 逐镜 | 只描述本镜，不描述世界 |

**方位卡与台账的分界一句话**：方位卡管**不变的那部分**（门在哪、柱在哪、画面左是西），台账管**会变的那部分**（谁站在门边、门现在是开是关、墙破没破）。

两者不重叠——方位卡全场景共用一张且不含状态；台账逐段更新且不含空间基准。一个角色的站位要写「承重柱旁」（挂锚物，方位卡提供锚物清单）还是「东三步」（挂坐标），答案永远是挂锚物；但**他此刻在不在柱旁**，那是台账的事。

**与 C 门 / C2 门的分界**：C 门判「同一镜同时出现两个版本名」，C2 门判「声明时段 T 却写了 T.lock_out 里的词」——两门都是**在提示词内部找自相矛盾**。台账对账（G 门）是**拿外部事实源去核提示词**——台账说持刀，提示词说空手，两边各自都不矛盾，放一起才矛盾。这是 C/C2 查不到的一类。

**与空间层「在场声明」的分界**：`空间层_调度与轴线.md` 第四节要求每镜点名全部在场角色——那是**提示词内的写法纪律**（防模型自行删人）。台账的「人物账」是**跨段的状态记录**（防人的状态无声回退）。前者保证本镜写了谁，后者保证这个人的状态从上一段带过来。

## 二、 人物账（六项，一项都不能缺）

每个人逐段登记六项。**服装那一项只记「当前处于哪个版本」，不判断该判哪个版本**——那是 `identity_verdict` 与 C 门的事。

| 账目项 | 记什么 | 穿帮病灶（实测） |
|---|---|---|
| **站位** | 挂**固定锚物** + 画面方位（不写「距某人三步」） | 上段「窗洞前」，下段凭空变「隔断墙旁」且无位移说明 |
| **朝向** | 与轴线一致；转头要有触发 | 无故反转朝向、跳轴 |
| **服装** | 当前所处版本名（与注册表 `characters.*.versions` 对齐） | 隐形换装、饰品消失 |
| **道具持拿** | 持有者 + **左/右手位** + 道具状态（完损） | 道具换手、凭空消失 / 出现 |
| **姿态状态** | 站 / 坐 / 卧 / 撑起 / 跪；一旦发生，后续段保持或显式交代回退 | 前段已坐起，后段又躺回去（无声回退） |
| **声音身份** | 音色基线（引用同一角色版本）+ 本段情绪调制 | 跨段音色突变 |

### 三条跨段生死线

1. **摆位必入画**：台账登了站位的人，本段的镜行至少要带到一次（正拍 / 焦外身影 / 全景群像 / 反应镜都算）。实在给不了镜头，站位栏写明「段末离画 · 去向某某」。
2. **入画要交代**：离场的人重新入画，站位栏必须写「段初自门口入画」这类方式，不能凭空出现。
3. **站位不漂移**：相邻两段没写位移的人，站位 / 朝向 / 依托物不得无交代改变。

### 持物字段记「物件级」，不记「手势级」（v5.33.0 · 实战确立）

G3 只比对相邻两条的持物**字符串**。真实分镜里手势每镜都在微变（双手扫 → 单手停帚 → 拄帚），
若把这些写进持物字段，每镜都会被判「变更」，G3 噪声爆炸——实战《梦中人》场 1 一次跑出 6 条 G3。

**正确口径**：持物字段只记「**哪些物件在谁手里**」（物件级），手势与动作细节归姿态行：

| 写法 | 后果 |
|---|---|
| 持物：右手·停帚（手势级） | 镜3「双手·竹笤帚」→ 镜4「右手·停帚」被 G3 判为变更，报 6 条假错 |
| 持物：竹笤帚（物件级，姿态行写「扫到第三帚停住、左手离帚捶腰」） | 字符串跨镜一致，G3 零噪声；真变更（物件易手）才需要变更行 |

配套：**G2 用词一致**——台账里的物件名与包内正文必须同名（台账「竹笤帚」vs 包内「帚柄」= 对不上）。

### 为什么「道具持拿」必须写左右手

模型不区分左右——写「手持剑」它会在三段里分别给出左手、右手、双手。写死「右手·桃木剑」后三段才可能一致。**换手必须有触发节拍**（见第五节）。

## 三、 场景账（七项）

| 账目项 | 记什么 |
|---|---|
| **陈设状态** | 完好 / 已损毁 / 已移位；损毁要记**持续区间**（哪段破、哪段恢复） |
| **时段** | 取 `lighting_anchors` 的标签（夜 / 黄昏 / 晨…）。**只引用，不现场编** |
| **空气介质** | 雾 / 烟 / 尘 / 雨的**来源 + 密度 + 运动 + 衰减区间** |
| **光源** | 实际光源（天光 / 灯火）的方向与**是否点亮**；体积光不算场景固有资产 |
| **方位卡版本** | 引用哪张方位卡（场景名 + 版本号） |
| **尺度参照** | 巨构 / 巨兽场景的熟悉参照物（参照物不许消失） |
| **轴线与屏幕方向** | `建立 / 保持 / 跨越` + **锚物连线** + 谁在左谁在右（按方位卡的屏幕方向映射）。**状态词只在台账**——逐镜正文只写连线与左右（v5.27.0） |

**陈设状态是场景账里最容易漏的一项**，也是打戏之后最高频的穿帮源：墙被撞穿了，下一段回全景时墙又好了——因为提示词里没地方记「墙现在是破的」。

**时段只引用不编造**：`lighting_anchors` 是全项目唯一光源事实源（见 `场景资产与时间线光照.md`）。台账里写「黄昏」，就必须能在锚点表里找到「黄昏」这一行；找不到说明注册表漏建变体，先补注册表。

## 四、 时间轴账（三项）

- **入口时间 / 出口时间**：本段在全片时间轴上的位置。跨集项目写「第 N 集 MM:SS」。
- **推进方式**：连续（紧接上段）/ 跳跃（写明跳多久）/ 平行（与某段同一时刻）。
- **同一时刻全片对齐**：平行蒙太奇的两条线必须标同一个时刻锚，否则剪辑时会发现两条线的天光对不上。

**与 C2 门接驳**：台账的「时段」是本段的**事实声明**，C2 门拿它去核提示词里的时段声明行（见 G5）。台账不替 C2 门查光照词，C2 门也不替台账记状态。

**时长纪律照旧**：单段上限由锁①模型版本决定（2.5 面 30s / 2.0 与 H3 面 15s），见 D 门；镜长按剧情倒推，不机械等分。

## 五、 变更行：没有触发节拍的变化就是穿帮隐患

每处状态变化写一行**变更**，四段缺一不可：

```
变更：<触发节拍> ｜ @<角色或对象> <字段>：<旧值> → <新值>（<落点或方式>）
```

- **触发节拍**：哪一个 beat 引起的（beat 编号或「段 3 第 2 拍」）。**没有触发节拍的变化＝凭空变化**。
- **落点**：道具离手必有落点——放下 / 递给谁 / 被打落 / 收入鞘 / 插回地面，必须写清。**「没了」不是落点。**
- 落点允许发生在画外（切场时收刀），但**必须写明**，不能因为「镜头没拍到」就不写。

例：

```
变更：beat-3 ｜ @长风 持物：右手·桃木剑 → 无（被打落，落在承重柱西侧地面）
变更：beat-4 ｜ @长风 姿态：站立 → 单膝跪（拾剑）
变更：beat-4 ｜ @长风 持物：无 → 右手·桃木剑（自地面拾起）
```

**姿态回退同样要有交代**：前段坐起、后段躺回，若中间没有「伤痛复发，撑不住躺下」这条变更，就是无声回退。

**两种变更行**（v5.15.8 明确——本节上文是第一种，第二种是段末的出口记录，别混）：

| | 触发节拍式（上文四段式） | **出口末态式（每段最多一条）** |
|---|---|---|
| 记什么 | 段内**某一拍**发生的状态变化 | 本段**出口**谁挪到了哪 |
| 格式 | `变更：beat-3 ｜ @长风 持物：右手·桃木剑 → 无（落在承重柱西侧地面）` | `出口末态（见接戏全景）：@甲 <位移链>；@乙 <位移链>` |
| 何时写 | 有变化就写 | **本段有人净位移**才加（没人挪位置就不加这条） |
| 放哪 | 变更块内逐条 | 变更块**末尾**一条 |

出口末态式的三条纪律：

1. **逐字取自提示词包的位移行**（只滤掉判为「无位移」的人），**不另立文字**——台账是核对者，不是第二作者。
2. 出口末态以**验收通过的实际尾帧**为对照（v6.4.0 起无专用接戏全景拍——机制废止留档于空间层 §十三；不再写「（见接戏全景）」标注）。
3. 它与触发节拍式**互不替代**：段内拍了三拍变化，三条节拍式照写；出口谁在哪，末尾再补一条出口末态式。

> 为什么段末要有这条：跨段继承不能只靠计划文字。需要接戏时，以**验收通过的实际尾帧**为事实源，
> 为什么段末要有这条：跨段继承不能只靠计划文字。出口以**验收通过的实际尾帧**为事实源，台账出口末态是它的文字对照；下一段还需硬绑定 `first_frame` 并复核实际首帧。（v6.4.0 起「接戏全景」机制废止：不再有专用全景拍，实际尾帧就是末态实物。）

## 六、 逐段台账格式（G 门的解析格式）

落盘位置按 `asset-registry.json` 的三步顺序（项目资产目录 → 与输入同目录 → 项目根），文件名固定 `continuity-ledger.md`。

**条目编号必须与提示词包的块编号一致**——包里是「段 3」就写「段 3」，包里是「镜 12」就写「镜 12」，包里是「U07」就写「U07」。编号不一致 G 门对不上账（G6 会报出来）。

```markdown
## 段 1｜废弃工地顶层 · 夜 · 拾灵

人物账：
- @长风 站位：承重柱旁 ｜ 朝向：面朝南 ｜ 服装：灰袍·束袖 ｜ 持物：右手·桃木剑 ｜ 姿态：站立 ｜ 声音：低沉青年男声·戒备
- @清羽 站位：窗洞前 ｜ 朝向：面朝北 ｜ 服装：白毛斗篷 ｜ 持物：无 ｜ 姿态：倚墙 ｜ 声音：清亮少女·疲惫

场景账：
- 陈设状态：完好（石膏隔断墙未破）
- 时段：夜
- 空气介质：浮尘·中·随呼吸气流缓升
- 光源：东侧窗洞月光，无人工光
- 轴线：建立 ｜ 承重柱—石膏隔断墙连线 ｜ @长风 左（西）、@清羽 右（东）
- 方位卡版本：废弃工地顶层 v1
- 尺度参照：无

时间轴账：
- 入口：第1集 00:00
- 出口：第1集 00:45
- 推进：连续

变更：
- 段初 ｜ @清羽 姿态：卧 → 倚墙（开场前已发生，本段首镜可见）

## 段 2｜废弃工地顶层 · 夜 · 交手

人物账：
- @长风 站位：承重柱旁 ｜ 朝向：面朝北 ｜ 服装：灰袍·束袖 ｜ 持物：双手·桃木剑 ｜ 姿态：弓步 ｜ 声音：低沉青年男声·发力

场景账：
- 陈设状态：石膏隔断墙出现裂纹（未塌）
- 时段：夜
- 空气介质：浮尘·中 + 撞击扬尘（局部·浓）
- 光源：东侧窗洞月光，无人工光
- 轴线：保持 ｜ 承重柱—石膏隔断墙连线 ｜ @长风 左（西）、@清羽 右（东）
- 方位卡版本：废弃工地顶层 v1
- 尺度参照：无

时间轴账：
- 入口：第1集 00:45
- 出口：第1集 01:30
- 推进：连续

变更：
- beat-2 ｜ @长风 持物：右手·桃木剑 → 双手·桃木剑（举剑过顶劈下）
- beat-2 ｜ @长风 姿态：站立 → 弓步
- beat-3 ｜ @清羽 站位：窗洞前 → 隔断墙西侧（避让，贴墙移动）
- beat-3 ｜ 场景账·陈设状态：完好 → 石膏隔断墙出现裂纹（被气浪掀裂，未塌）
```

### 字段别名

G 门认下列写法，任选其一，不必统一：

| 字段 | 认的写法 |
|---|---|
| 持物 | 持物 / 道具持拿 / 手持 |
| 姿态 | 姿态 / 姿态状态 |
| 声音 | 声音 / 声音身份 |
| 服装 | 服装 / 造型 |

「无 / 空手 / 徒手 / 未持物」都算**空手值**，写哪个都行。

### 可选 JSON 版（不参与 G 门）

跨集项目或要接外部工具时，可另存 `continuity-ledger.json`，逐段一个对象：

```json
{
  "segment": "段 1",
  "entry_state": { "characters": [{"name": "长风", "holding": "右手·桃木剑", "posture": "站立"}],
                   "set_state": "完好", "time_label": "夜" },
  "changes": [{"beat": "beat-2", "target": "@长风", "field": "持物",
               "from": "右手·桃木剑", "to": "双手·桃木剑", "how": "举剑过顶劈下"}],
  "exit_state": {},
  "must_carry_forward": ["长风持桃木剑", "隔断墙裂纹"],
  "unresolved_conflicts": []
}
```

⚠️ **G 门只解析上面的 md 列表形**。JSON 版是给外部工具对接的并行产物，两者要一致时以 md 为准（md 是给人看的，人改得动 json 才会跟着改）。

## 七、 G 门七条机检（`audit_project.py --ledger`）

| 码 | 判据 | 级别 |
|---|---|---|
| **G1 持物矛盾** | 台账记持物 X，包内该角色所在块出现空手词（空手 / 徒手 / 未持物 / 两手空）且无交接词 | ERROR |
| **G2 持物漏写** | 台账记持物 X，包内该角色所在块既无 X 也无空手词、无交接词 | WARN |
| **G3 离手无落点** | 上段持 X、本段持无（或换物），本段变更行里没有该角色的持物变更 | ERROR |
| **G4 角色漏登** | 该角色在别的段登过记、本段包内也点名了，但本段台账没登记 | WARN |
| **G5 时段对账** | 台账时段标签 ≠ 包内时段声明行里的标签 | ERROR |
| **G6 段号对不上** | 台账的条目编号在包里找不到对应块 | WARN |
| **G7 空账元检查** | 台账解析出 0 条 | ERROR |

**G7 是假绿防护，不是凑数**：台账解析不出条目时，G1~G6 全部返回「零命中」，一眼看去是绿的——那是最危险的一种绿。解析不出就明说「对账是空跑，不算通过」，与 Z 门、S22 同一口径。

用法：

```bash
python scripts/audit_project.py <提示词包.md> --ledger continuity-ledger.md
```

不给 `--ledger` 时 G 门报 WARN「未配置台账，跳过——这不是通过」，不报 OK。

### 为什么 G2 是 WARN 不是 ERROR

台账记了持剑、提示词里没写剑，有两种可能：一是漏写（真问题），二是本镜景别是大远景、剑本来就看不清、写了反而污染画面（合法）。**G2 只提示「这里没人说过剑的事」，让人自己确认**，不替人下结论——这是 liqi 一贯的分级口径（该报错的零容忍，该提示的不冒充错误）。

反过来 **G1 是 ERROR**：提示词明写「空手」与台账的「持剑」是直接矛盾，不存在合理解释。

## 八、 三条防误报与倒车防护

1. **G1 只在「明写空手」时报**，不因「没写」而报。没写走 G2 的 WARN。
2. **G3 只比对相邻两条台账**，不跨不相邻的段（跨段本就可能切场）。且变更行只要**写明落点**即可，不要求落点在画内演出。
3. **G5 只比标签，不比光照词**。光照词那层语义由 C2 门用 `lock_out` 判，台账不重复判一遍。

**倒车防护**：本门新增的七条不推翻任何既有结论——

- 此前判为合法的**跳级景别 / 极限景别跳跃 / 开场 ECU**（见 `分镜配额与机检规范.md`）不因台账出现而改变判定；
- 此前 C 门、C2 门的判定不变，G 门只做两个事实源的比对，不改提示词内部的判据；
- 台账没给 → 跳过不报 OK，不把「没台账」变成「通过」。

## 九、 自检清单（交台账前八问）

1. 每个在场的人六项都登了吗？有没有只登了站位、没登姿态的？
2. 站位挂的是锚物还是活人？（写「距某人三步」就是挂活人，改）
3. 道具写了左右手吗？
4. 本段与上段相比，每一处变化都有变更行吗？变更行有触发节拍吗？
5. 道具离手的变更行写了落点吗？（「没了」不算）
6. 陈设状态更新了吗？（尤其打戏、灾害之后）
7. 时段能在 `lighting_anchors` 里找到吗？
8. 时间轴的入口 = 上一段的出口吗？平行线标了同一时刻锚吗？

## 十、 失败模式

| 症状 | 根因 | 处方 |
|---|---|---|
| 道具在几段之间时有时无 | 没登持物，或离手没写落点 | 补持物项 + 补变更行落点 |
| 角色朝向莫名反转 | 朝向没登，或转头没触发 | 补朝向项 + 给转头一个 beat |
| 打戏后墙自己好了 | 陈设状态没更新 | 补陈设状态与**持续区间**（哪段恢复） |
| 两条平行线天光对不上 | 时间轴账没标同一时刻锚 | 补「推进：平行 · 与段 N 同一时刻」 |
| 台账写了但包里没兑现 | 写台账与写提示词是两拨动作，中间漏了 | 跑 G 门（G2/G3 专抓这类） |
| 台账与包各说各话，两边都不红 | 没跑对账 | 跑 `--ledger`，别只看单侧 |

## 十、 开场站位快照（v5.37.0 新增 · 可选段）

> 来源：shuohao `novel-staging` 的 `staging.json`（Apache-2.0）。liqi 吸收其**数据结构**，不搬其 HTML 工具。

**用途**：一场戏第一镜之前的站位底稿。人物账管「状态怎么变」，本节管「开场时谁在哪」——两件事不同层，别混写。

**何时写**：本场 ≥3 人同场，或同侧有 ≥2 人（要用 along 坐标）时。两人一侧一人的简单场不必写。

**格式**（每场一小节，跟在台账末尾或独立 `staging.md`）：

```
### 场 2｜渡船船舱 · 夜
cast：C01 沈知微、C04 胡二爷
places：
  C01 沈知微｜present: false｜—（随后进舱，开场不在）
  C04 胡二爷｜present: true｜item: 第三排坐板｜side: on｜along: 0.50｜posture: sit｜facing: north
extras: 0（剧本未写他人，座位空着）
why：沈知微随后进舱，开场不在；胡二爷带着货担坐第三排。
```

字段口径：

| 字段 | 写法 |
|---|---|
| `present` | 开场是否在场。**剧本没写某人进场，当他开场就在** |
| `item` | 挂在**哪件东西**上（锚物）。只用场景资产里认得出的东西，不发明 |
| `side` | 在该物的哪一侧；坐/躺在其上写 `on` |
| `along` | 沿该侧的归一化位置 0~1。**同侧任意两人差值 ≥ 0.12** |
| `posture` | `sit` / `stand`。站着要有理由（刚进门、在伺候、被罚站、正要发难） |
| `facing` | 面朝哪。坐着的一般面朝桌子；坐主位的面朝全场；站着的面朝他开场在看的人 |
| `extras` | 群演人数。**默认 0**——剧本没写就是没有，空着的位置模型会自己画成有脸的人 |
| `why` | 为什么这么排。人改的时候知道原来的考虑 |

**与逐镜提示词的关系**：本场第一镜的站位行**照抄这份快照**；之后各镜从这份接着往下写。改站位时只改快照，不要每镜各自编。
