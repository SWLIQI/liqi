# 资产结构层（双输出：结构 → prompt）

## 为什么需要结构层

只输出生成 prompt 时，一旦出图崩了，你面对的是一坨几百字的散文——不知道该改哪个词，只能整条重写，而整条重写会引入新的漂移。

**结构层是给人看的，prompt 是给模型看的。** 先出结构层，再压成 prompt。迭代时定位到出问题的那一层，只改那一层，其他层原样保留。

> 结构层才是真正的工作成果。prompt 只是它在某一刻的投影。

## 六层结构

每个资产条目**先输出 (A) 结构层，再输出 (B) 生成 prompt**。顺序不能倒，不能跳过 A 直接给 B。

| # | 层 | 写什么 |
|---|---|---|
| 1 | **环境与气候** | 空间类型、时段、光源与光质、天气、空气感 |
| 2 | **主体与构成** | 谁/什么在画面里、数量、位置关系、视角组织（三视图 / 双视图 / 2×2 网格）、视觉层级 |
| 3 | **外观与造型** | 角色=五官发型体型服饰；道具=形制材质状态；场景=陈设与空间结构 |
| 4 | **状态与版本** | 角色=姿态与版本状态（A版/瘦脱形版）；道具=完好/烧焦等；场景=时段版本（晨/午/昏/夜） |
| 5 | **质感与细节** | 材质、织法、磨损、纹理、光影细节、面板分工 |
| 6 | **氛围终层** | 情绪锚与调性 |

> 🗂 **角色的「视角组织」本 skill 固定为 4 View 资产板**：左区头部近景（身份锚）+ 右区保头无脸三联（正面 / 90° 侧面 / 背面），另附身高比例尺、HEX 三色；**启用音色时最下方另加一条通宽「图底音纹条」（声纹波形 + ≤8 词英文音色速览标签，不计入格数）**。原「细节材质三联」已由 v5.10.0 取消，细节改归并进服饰段 / 配饰与鞋履行 / 面部特写格。
> 见 `资产层_锁定与一致性.md` 第二节。**六层骨架不变，只换第 2 层与第 5 层的面板组成。**

### 第 5 层补：表面处理两档（v5.36.0 新增 · 来源 shuohao novel-art scene-pass 硬规则 6/8）

第 5 层写「磨损」时要先判这个空间/物件的**保养水平**，二选一——**不是两种画风，是两种事实**：

| 档 | 适用 | 写法 |
|---|---|---|
| **A · 日常使用** | 民居、客栈、码头、作坊、久无人修的宅子 | 掉漆、水渍、金属包浆、磨白木纹、角落与光柱里的积尘；布纸道具起皱显旧；没有一处像出厂新品 |
| **B · 持续维护** | 宫殿、官署、显贵府邸前厅、新建或刚整修的空间 | 漆面完好有匀光、石木扫净、金属件擦亮、榫接紧密；**磨损只留在人走出来的地方**——门槛正中、栏杆扶手、台阶踏面 |

**别把 A 当默认。** 一整部戏全上 A，金銮殿会出成漏雨的废殿——shuohao 实测《状元是买的》S06 金銮殿拿到「漆面剥落」「门框下部浅淡水渍」，而那是全国维护最勤的一栋建筑。选了 B 仍要写磨损，只是**磨在该磨的地方**。

**不要把角色的表面处理带进环境**：毛孔、皮下散射是皮肤的事；环境的可信度来自**用旧的材质**。

> 两条边界：① 画风（赛璐璐 / 水墨 / 写实）不在这两档里，它由当次出图的风格指令决定；② 反向提示词里**绝不能禁画风词**（`photorealistic` / `3d render` / `anime`）——出图时选的就可能正是它，禁掉等于自己跟自己打架。

### 第 4 层：状态与版本（三类资产的版本维度不同）

| 资产 | 版本维度 | 典型取值 |
|---|---|---|
| 角色 | 服装阶段 / 体态状态 | 素白中衣版 / 藕荷衣裙版、正常版 / 瘦脱形版 |
| 道具 | 使用状态 | 完好态 / 烧焦态、闭合态 / 微开态 |
| 场景 | **时间线时段** | 拂晓 / 晨 / 正午 / 午后 / 黄昏 / 入夜 / 深夜 |

这一层是 liqi 版本互锁机制的落点——**每出一个版本，就要在这一层写清它排除什么**。

### 第 6 层：氛围终层的检验标准

**这一层必须是新的诠释层，不能是前五层的复述。**

自检方法：把第 6 层删掉，如果前五层描述的画面完全不变——说明它是复述，重写。

它应该命名的是：**前五层已经显示出来、但没有说破的那个东西**。

- ❌ 反例（复述）：`整体氛围昏暗肃杀沉重。` —— 第 1 层已经说了"昏暗"，这是重复。
- ✅ 正例（诠释）：`这是一个被体制遗忘的角落——尸体和卷宗被同等对待，都只是待处理的对象。` —— 前五层没说过这个判断，但它被画面支撑着。

## 输出格式

```
(A) 结构层

1. 环境与气候：
[正文]

2. 主体与构成：
[正文]

3. 外观与造型：
[正文]

4. 状态与版本：
[正文]
　　互锁（本版排除）：[lock_out]

5. 质感与细节：
[正文]

6. 氛围终层：
[正文]

---

(B) 生成 prompt

[按 SKILL.md Step 2.5（资产板 / 道具表 / 场景表）与 Step 3（逐镜）的模板，把 A 压成可直接复制的提示词正文]
```

## 迭代纪律（这是结构层的全部价值所在）

出图崩了之后的流程：

1. **定位层**——对照 `失败模式诊断表.md`（角色/道具）或 `场景资产与时间线光照.md` 第六节（场景），判断是六层里的哪一层出问题。
2. **只改那一层**——改完重压 prompt，其他五层**原样保留**。
3. **禁止整条重写**——重写会让本来没问题的层也跟着漂。

常见故障的层定位：

| 症状 | 出问题的是 |
|---|---|
| 光不对（太亮/太暗/方向乱） | 第 1 层 |
| 面板被吞、构图散、视角雷同 | 第 2 层 |
| 长得不像参考图、形制错、陈设缺 | 第 3 层 |
| 串版（混入另一版本特征）、白天点了灯 | 第 4 层 |
| 布料像色块、材质平、没质感 | 第 5 层 |
| 画面"对但没感觉"、不出戏 | 第 6 层 |

最后一行值得留意：**画面技术上全对但就是不出戏，问题在第 6 层**。这时候加技术参数（8k、超细节）是没用的，要回去重写情绪锚。

## 与资产注册表的关系

- 结构层是**单次产出的中间态**，随 `.md` 落盘，供后续迭代定位用。
- 注册表是**跨会话的唯一事实源**，只存 durable 事实（见 `资产注册表_asset-registry.md`）。
- 第 1 层的光照数值、第 3 层的色值，必须从注册表取，不能在结构层现场编。
