# liqi-move · 运镜专精包

从 `liqi-video-forge v6.19.8` 的**镜头骨架库**抽出来的运镜维度：8 个场型 × 3 条骨架 = 24 条。
不依赖三锁、不依赖主包。

## 运行前提

- Node.js ≥ 16（ESM，脚本为 `.mjs`）；零第三方依赖
- 全部文件名 ASCII，Windows / macOS / Linux 解压一致
- Windows 控制台中文乱码时先执行 `chcp 65001`

## 什么时候用

- 写分镜，需要"这一场该用什么机位和运镜"
- 已经写完镜头描述，想确认里面有没有自造的复合镜头、抽象词
- 想让运镜有节奏（时间轴分段），而不是一句"镜头推进"

## 什么时候不要用

- 只写静态画面（构图、光、风格）：用 `liqi-lens` / `liqi-style`
- 需要角色一致性：用 `liqi-cast`
- 需要剧本、台词、叙事：不属于运镜

## 它到底给了什么

| 场型 | 骨架数 | 这一场管什么 |
|---|---|---|
| 开场定调 | 3 | 先给环境气质，再进人物 |
| 空间交代 | 3 | 横向关系与纵深 |
| 人物亮相 | 3 | 第一次看清主体 |
| 关系建立 | 3 | 人物之间的位置与距离 |
| 情绪爆发 | 3 | 把变化压到一处 |
| 动作接触 | 3 | 接触前后，不拍碰撞 |
| 转场过渡 | 3 | 用遮挡或分镜换场 |
| 收尾留白 | 3 | 末段静止，留余味 |

> 运镜取值以 `move-index.json` 为准；本文不再抄一份「典型运镜」列，避免文档与数据漂移。
> 取法：`node scripts/pick_move.mjs <场型>`。

**词表只有 7 个**（骨架库实际取值）：固定、横移、缓推、后拉、跟拍、缓降、微推。

## 一条必须说清的诚实边界

文档里写着"运镜只有 12 个原语"，**但从未列出这 12 个是什么**——它指向一个外部的
`h3-camera-shots` skill。本包不冒充那份清单：这里给的是**骨架库实际用到的 7 个用词**，
以及文档明确禁止的具名复合镜头。要真正的 12 原语，需要那份外部资料。

## 工作流

1. **选场型**：这一镜在叙事上干什么（开场/交代/亮相/关系/爆发/接触/转场/收尾）。
2. **取骨架**：`pick_move.mjs` 给出该场型的 3 条骨架，挑一条。
3. **填占位**：把 `<环境整体>`、`<遮挡物>` 这类占位符换成你的内容，**别改结构**。
4. **自检**：`check_move.mjs` 查具名复合镜头、抽象词、超纲运镜；**三类都是 ERROR**，命中即 exit 1，并给逐条改法。

## 快速开始

```bash
node scripts/pick_move.mjs 情绪爆发
node scripts/pick_move.mjs 转场
node scripts/check_move.mjs examples/shot-good.md
node scripts/check_move.mjs examples/shot-bad.md   # 预期 exit 1
npm test
```

## CLI 参数表

| 脚本 | 参数 | 说明 |
|---|---|---|
| `pick_move.mjs` | `<场型或意图>` | 按场型/标题/适用/主运镜匹配；可只给「情绪」「转场」这种片段 |
| `check_move.mjs` | `<文件.md>` | 相对路径按包根解析，包外调用请用绝对路径 |
| `build_index.mjs` | `[主包目录] [--dry-run]` | 需同时读到 `镜头骨架库.md` 与 `MiniMaxH3适配.md` |
| `check_sync.mjs` | `[主包目录]` | 缺省读 `LIQI_CORE` 或 `../liqi-video-forge` |
| `selftest.mjs` | 无 | 29 条自测 |

## 骨架长什么样

```
【情绪爆发 5.2 推近至大特写】
  景别机位：中近景起手，推至大特写。
  主运镜：缓推（单一原语群）。
  时间轴：0-3s：中近景，<外部动作>｜3-6s：缓推，<动作减弱，表情显现>｜6-9s：大特写，<只剩局部与微动>
  必锁：推近匀速无停顿；终态景别；外部动作在第一段内完成。
  已知失败：推近中途停顿；终态景别不到位；第三段又出现大动作。
```

## 检查输出长什么样

通过：

```
文件：examples/shot-good.md
库内允许：后拉、固定、微推、横移、缓推、缓降、跟拍
命中运镜词：移
结果：0 ERROR / 0 WARN
```

失败（`examples/shot-bad.md`，节选）：

```
结果：9 ERROR / 0 WARN
  · 出现具名复合镜头「滑轨变焦」：用原语拼装（…），不要直接写
  · 出现抽象词「cinematic」：换成具体的视觉与听觉细节（光位、材质、动作、声音）
  · 运镜词「环绕」不在骨架库 7 词表里：改用 …，或拆成两个原语
```

完整通过/失败输出见 `examples/check-pass.txt` / `examples/check-fail.txt`。

## 字段说明

`move-index.json` 与 `move-vocab.json` 的字段、类型与生成方式见 `references/field-schema.md`。
禁止清单的策展文件是 `references/bans.json`：标注为 `MiniMaxH3适配.md` 的词会在
`build_index` 时逐条回查主包原文；`local` 是本包扩展。

## 边界

- 不做分镜叙事、不做角色、不做风格
- **轴线与反打不在本包**（那是视听层的事），本包只管"镜头怎么动"
- 不承诺"某种运镜更好"——只给骨架、必锁项与已知失败

## 来源与同步

骨架库与 H3 的用词禁令来自 `liqi-video-forge v6.19.8`（MIT）。
`SYNCED.json` 记录两个来源文件的哈希；主包升级后跑
`node scripts/build_index.mjs <主包目录>` 重新生成索引与词表（会逐条回查禁止词），
再跑 `check_sync.mjs` 确认。主包不在时返回 SKIPPED（跳过 ≠ 通过）。
