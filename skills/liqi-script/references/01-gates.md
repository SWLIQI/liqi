# 五阶门控与量化门禁

> 同步来源：`liqi-video-forge v6.19.8` → `references/叙事层_剧本门控与台词.md`（一、六节）
> 触发条件：原料不是合格剧本（只有梗概/小说/一句创意），或用户明确要求审剧本；已是合格剧本时整层跳过。

## 一、五阶门控

| Gate | 管什么 | 产出 | 本包机检 |
|---|---|---|---|
| 1 Premise | 核心前提 | 30 字前提四要素 + 开场钩子 | ✓ |
| 2 Structure | 结构 | 三幕比例 + 结尾卡点 | 比例可算；卡点人工 |
| 3 Beat Sheet | 场景因果 | 每场五段因果 + 情节点 | ✓ 结构 + 密度 |
| 4 Entity Bounds | 世界观/实体 | 角色唯一、关系/战力天花板 | ✓ 角色一致性 |
| 5 Script Page | 脚本页 | 场景头/动作/台词标准排版 | ✓ 结构 + 词表 |

## 二、Gate 1 · Premise

**30 字前提公式**：`[主角] + [核心欲望] + [不可抗力阻碍] + [失败的致命代价]`。
四项缺一，后续节拍会漂。

**开场钩子四选一**：

1. 极端悬念——刀尖对准咽喉，生死悬于一瞬
2. 认知反差——最弱的人展现颠覆常理的能力
3. 情绪爆发——至亲受辱 / 婚约撕毁 / 绝境背叛
4. 视觉奇观——异象、法相、天雷裂空

文艺短片可以慢开场，但第一拍必须在 3 秒内给一个「值得看下去」的信息（动作/反常/视线），不能是空镜。

## 三、Gate 2 · Structure

- 三幕时间比例：**铺垫 30% → 核心冲突 50% → 转折爆发与卡点 20%**。只吸收比例，不吸收固定秒数。
- 结尾卡点：停在决策关头、身份暴露瞬间或攻击命中的**前一帧**。

## 四、Gate 3 · Beat Sheet

**场次存在性法则**：删掉一场戏后不影响后续剧情，则该场必须删。

**每场五段因果链**：

```
场景目标 → 遭遇阻碍 → 升级行动 → 意外转折 → 产生不可逆新局面
```

五段缺一，这场只是「发生了点什么」，不是「推进了什么」。

**情节点**：一次**意图变化 / 关系变化 / 信息翻转**，任一即算一个；「发生了一件事」但没改变任何人的意图/关系/信息量，不算。

- 标注写法：`情节点：桃木剑被认出是师父旧物（信息翻转 · 清羽立场动摇）`，或 `（情节点：…）`。不标 = 机检无法核对，**不是通过**。
- 单集 **≥5 个**；15s 投喂段 **≥1 个**；相邻情节点**不得跨过一场戏**（这一场的后果要在下一场被看见）。

## 五、Gate 4 · Entity Bounds

- 时代背景锁定法律、战力天花板、技术极限；天花板没锁，第三幕就会出现「主角忽然会飞」。
- 人际关系网络明确上下级/仇恨/盟友，杜绝无动机叛变。
- **同一实体不得两个编号**（`@长风` 与 `@长风道长` 会被下游当两个人建两套资产）；编号跨集连续，与 asset-registry slug 对齐。
- **软肋锚点＝物**：每个主要角色的软肋挂在一个物上（裂头盔/旧工牌/绘本），并在资产清单登记；物比台词更能被模型记住。

## 六、Gate 5 · Script Page

```text
[场景序号] [内景/外景] · [具体地点] - [日景/夜景]
出场人物：@角色A、@角色B
环境氛围：[空间构图、天气、主导光源与声音质感]

[动作描述]（只写摄像机能拍到的物理动作与空间位移）

@角色A（微动作：咬紧后槽牙，指节泛白）
"（台词，遵循冰山法则与潜台词）"
```

**反形容词法则**：只写摄像机能记录的东西。「他很愤怒」不写，写「咬紧后槽牙，咬肌隆起」。
**镜头语言不进剧本页**：景别/机位/光位/特写交给 `liqi-lens`；本包出现这些词只报警，不改写。

## 七、量化门禁总表

| 门 | 量化判据 | 核对 |
|---|---|---|
| Gate 1 | 30 字四要素；开场钩子四选一 | 人工打勾 / 本包机检 |
| Gate 2 | 三幕 30/50/20；卡点在前一帧 | 比例可算；卡点人工 |
| Gate 3 | 单集情节点 ≥5；15s 段 ≥1；相邻不跨场 | 机检（N2 近似） |
| Gate 3 | 每场五段因果齐全 | 本包机检 |
| Gate 4 | 实体编号唯一、跨集连续 | 本包机检（单文件） |
| Gate 5 | 对白零擅删、场号连续、角色可追溯 | 本包机检 + 人工 |
| 改编 | 事实权威链五级：FACT / INFERENCE / ASSUMPTION / USER_OVERRIDE / OPEN_ITEM | 机检 N3（主包） |

**N 码参考**：N1 场序号（重复 ERROR、缺号/乱序 WARN）；N2 情节点密度（0 标注 = 未标注，不是通过；单集 <5 WARN；每 15s <1 WARN）；N3 事实权威链（改编类 0 标注 = 未标注）；N5 筹码账；N6 尾钩链。N4b/N5/N6/N3b 是 opt-in 门，不传输入 = 跳过，**跳过不是通过**。

> **本包只实现 N 码中可由单个 JSON 判定的部分**：id 重复（N1 的重复项）、情节点数量（N2 近似）、角色一致性（Gate 4）、尾钩/筹码枚举与空值（N5/N6 的 JSON 子集）。场号缺号/乱序、事实权威链、分集结构表解析不在本包；看到 N 码不要误以为全部已机检。

## 八、三视角审稿（自检，不是硬门）

- 观众视角：哪里没看懂、想划走、记不住人；不许评文笔。
- 类型视角：这个类型的观众期待什么，剧本给没给；不许按别的类型要求。
- 类型反例视角：这个类型最烂的片子会怎么拍这一场，本稿有没有踩；只指病灶，不给方案。
- 每视角至少 2 个真问题；「节奏不错，建议加强人物」不算。
- 反捧杀：作者自评至少一处不满意；三视角全好评 → 可疑，回到类型反例视角重审。

## 九、本包机检边界

能查：前提四要素/开场钩子、三幕比例、五段因果、情节点数量、角色/speaker 一致性、场景头、台词长度/语速/时长/预算、VO/OS、镜头词/不可拍词/slop、尾钩/筹码枚举。
不能查：潜台词质量、类型语感、卡点是否前一帧、三视角审稿、表演容量。**未标注 ≠ 通过。**
