# 版本互锁与跨集复用

> 同步来源：`liqi-video-forge v6.19.8` → `references/版本拆分与互锁清单.md`、`references/资产层_锁定与一致性.md`（四、五节）
> 编号规则与负面词对照表的完整表格以主包为准，本文件给操作口径。

## 一、什么时候拆版本

同一个**持续身份**、不同**可复用状态** → 拆变体，不新建角色。

| 情形 | 处理 |
|---|---|
| 换装（常服 / 战袍 / 礼服） | 同角色拆变体，五官 10 项一字不改 |
| 年龄跨度（青年 / 中年 / 老年） | 拆变体，骨相与标志特征必须继承 |
| 受伤前后（完整 / 带疤 / 缠绷带） | 拆变体，疤的位置与形状写进互锁词 |
| 持续身份不同（双胞胎、易容、替身） | **新资产**，不是变体 |

判断口诀：**去掉临时状态后，还是不是同一个人？** 是 → 变体；不是 → 新资产。

## 二、三条硬纪律

1. **不许同名两版。** 版本名必须带状态后缀（`沈知微-常服` / `沈知微-战损`），否则下游无法引用。
2. **变体之间必须互斥。** 每个版本写一组「互锁负面词」：本版不该出现的特征，全部压掉。
   字段：`interlock`（必填，≥1 项）；需要英文时加 `interlock_en`，生成器优先用英文。
   例：`沈知微-战损` 的负面词里必须包含「干净衣角、完好袖口」；`沈知微-常服` 的负面词里必须包含「血渍、绷带」。
3. **未决不带默认 ID 进 4 View。** 身份没判定清楚就出图，等于把错误固化，返工是全线的。

**机检范围**（`validate.mjs`）：互锁词非空；不得出现在本版 `name` / `diff` 里（自我矛盾）；两版不得完全雷同。
语义上的「这一版有什么、另一版必须压什么」仍需人判断——机器只保证结构不偷懒。

## 三、出现四态（先记录，后判定）

| 态 | 定义 | 资产动作 |
|---|---|---|
| 出镜 | 本场画面可见 | 进身份判定与出图链 |
| 画外音 | 只有声音 | 记人物/声音事实，本场不绑造型 |
| 影像出现 | 照片、屏幕、画像里 | 按剧情处理，**不默认露脸** |
| 只被提及 | 台词提到 | 只做故事追踪，不建图 |

环境里的普通桌椅算布景；只有承担动作、识别或连续性时才升级为道具。

## 四、身份判定：四选一

| 判定 | 含义 | 下游动作 |
|---|---|---|
| `reuse` | 已有条目覆盖 | 沿用编号、身高、色值、互锁词 |
| `new_variant` | 同一身份的新状态 | 基础身份不变，只写差异 |
| `new_asset` | 持续身份不同 | 新建条目 |
| `unresolved` | 证据不足 | 挂起：列候选、缺失证据、影响；**禁止出图** |

落盘时只写英文值（`reuse` / `new_variant` / `new_asset` / `unresolved`），中文含义写在旁边注释里。
「已处理」不是判定结果。

## 五、跨集复用

> 本节是人工台账口径。本包只机检单角色内的版本互锁，**不做跨集编号/色值/材质比对**。

- 同一物件跨集必须同款：编号、色值、材质三项对齐，任一项变了就是新道具。
- 角色跨集复用时，投喂顺序不变：先 `face_hd`，再对应版本的全身格。
- 集与集之间不共用「临时状态」（血迹、雨水、破损）——那是版本，不是身份。
